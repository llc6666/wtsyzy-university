## 二、SPL 对照：主循环长什么样

PC 上程序跑完就退出，MCU 上程序必须一直运行，所以主循环是骨架：

```c
int main(void)
{
    /* 初始化：时钟、GPIO、外设 */
    LED_Init();
    Key_Init();

    while (1) {                 /* 永远循环，靠内部逻辑决定做什么 */
        if (Key_Get() == 1) {   /* 查询式：问一次按键 */
            LED_Turn();         /* 翻转 LED */
        }
    }
}
```

对照 PC 示例第 3 步：那里用 `while (tick < 5)` 跑 5 轮是为了能在命令行里结束；把条件换成 `1` 就是 MCU 的主循环。

## 三、用 switch 组织状态：按键消抖

按键按下时电平会抖动，直接读会读到多次按下。常见做法是记一个状态，用 `switch` 分情况处理：

```c
typedef enum { KEY_IDLE, KEY_PRESS, KEY_RELEASE } key_state_t;

static key_state_t state = KEY_IDLE;

void key_tick(void)          /* 由定时器或主循环周期性调用 */
{
    uint8_t level = GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0);
    switch (state) {
    case KEY_IDLE:
        if (level == 0) state = KEY_PRESS;      /* 检测到按下 */
        break;
    case KEY_PRESS:
        if (level == 0) { /* 确认按下，执行动作 */ state = KEY_RELEASE; }
        else state = KEY_IDLE;                  /* 抖了一下，回到空闲 */
        break;
    case KEY_RELEASE:
        if (level == 1) state = KEY_IDLE;       /* 等松手 */
        break;
    }
}
```

（以上为示意写法，未上板验证；`GPIO_ReadInputDataBit` 是 SPL 的函数名，具体以库头文件为准。）

要点：`switch` 的每个 `case` 都要有 `break`，漏掉会**贯穿**到下一个 case —— 这是 C 的设计，不是 bug，但初学者几乎都会踩一次。

## 四、软件延时与主循环的关系

```c
for (uint32_t i = 0; i < 720000; ++i) { __NOP(); }   /* 粗略延时 */
```

要注意：这种延时把 CPU 占死了，期间什么也做不了。真实项目里用定时器中断来计时，主循环继续跑其他任务。这是 K04 之后 K10（`volatile`）会接上的内容——中断里改标志、主循环看标志。

## 五、把本知识点带回 PC 的做法

在 PC 上把状态机单独跑通（用 `printf` 模拟按键输入），确认状态迁移正确，再搬到 MCU 上。这样出错时只有硬件一层需要排查。
