# 素数筛：标记范围、最小质因子与下标边界

当任务需要一段连续范围内的素数表、素数个数，或重复查询某个数是否为素数时，可以先筛一次，再读取结果。本页整理埃氏筛和常称“欧拉筛”的线性筛，重点是写清标记范围、循环变量和状态边界。

如果只判断一个数，先考虑试除等单点方法；若区间上限远大于内存能够容纳的范围，应另查分段筛，不直接把数组扩到上限。

## 先写输入与输出契约

| 项目 | 开始实现前要回答 |
| --- | --- |
| 范围 | 是 `[2,n]`、`[2,n)`，还是另一个区间？本页默认 `[2,n]` |
| 输出 | 素数列表、数量、查询表，还是每个数的最小质因子？ |
| 上限 | `n` 的最大值是多少？`n+1` 和循环递增是否仍在所选类型范围内？ |
| 多组数据 | 每组独立重建，还是一次筛到最大上限后重复查询？ |
| 空间 | 标记表、素数表及辅助表分别需要多少元素，能否放下？ |

`0` 和 `1` 都不是素数；`n<2` 时结果为空。如果仅分配 `n+1` 个槽位，初始化时也不能无条件访问下标 1。

## 第一步：先选结果形态，再选筛法

| 需要什么 | 可以从哪里开始 | 要付出的代价 |
| --- | --- | --- |
| 只要素数标记或列表 | 埃氏筛 | 一个合数可能被重复标记 |
| 学习“一次生成一个合数”的组织方式 | 线性筛 | 维护有序素数表，严格控制停止位置 |
| 还需要最小质因子，供后续分解使用 | 保存最小质因子的线性筛版本 | 额外的整数表空间 |
| 整段标记表放不下 | 分段筛 | 分块边界及基准素数需要另外设计 |

埃氏筛常见复杂度为 `O(n log log n)`，线性筛为 `O(n)`；复杂度不直接给出某台机器上的耗时。不要写成“到某个固定规模就必须换欧拉筛”，也不要把一次运行的毫秒数当作通用选择阈值。原理与实现形式可分别查 [CP-Algorithms 的埃氏筛说明](https://cp-algorithms.com/algebra/sieve-of-eratosthenes.html)和[线性筛说明](https://cp-algorithms.com/algebra/prime-sieve-linear.html)。

## 第二步：埃氏筛只处理仍未被筛掉的数

先固定标记含义，例如 `composite[x] == true` 表示 `x` 已被标记为合数。随后按升序处理 `i`：

1. `i` 已被标记时，跳过这一轮标记。
2. `i` 未被标记时，将它作为素数。
3. 从 `i×i` 开始，以 `i` 为步长标记倍数，直到超过 `n`。
4. 最后只在 `2..n` 范围收集结果；标记表中“未标记”不能脱离这个范围直接等同“素数”。

从平方开始，是因为 `i×k` 中 `k<i` 的倍数已可由更小的质因子处理。例如处理 5 时，10、15、20 已有更早的标记来源，本轮从 25 开始。这个优化不保证每个合数只被标记一次；例如 12 可由 2 与 3 的轮次重复处理。

### 先处理乘法类型，再写下标

把 `i*i` 的结果赋给较宽变量，不能补救乘法在窄类型里先发生的溢出。需要让操作数在乘法之前进入足够宽的类型，或在 `i>0` 的前提下，用 `i <= n/i` 判断是否还有标记区间。标记位置及其下一次递增也应在类型范围内。

C++ 有符号溢出属于未定义行为，不能描述成“必然变成负数”或“必然跳出循环”。语言依据见 [C++ 工作草案的表达式规则](https://eel.is/c++draft/expr.pre)。数组容量问题可对照[容器前置条件与下标边界](../06-STL/容器前置条件与下标边界：从运行时错误读修复线索.md)。

## 第三步：线性筛分开“当前数”和“素数表下标”

先在纸上固定四个名字：

| 名称 | 含义 | 合法使用范围 |
| --- | --- | --- |
| `i` | 当前处理的数 | 从 2 到 `n` |
| `j` | 素数表下标 | `0 <= j < cnt` |
| `p[j]` | 当前枚举的素数 | 已写入的素数表元素，按升序 |
| `p[j] * i` | 本轮待标记的合数 | 先确认不超过 `n`，再形成下标 |

每个外层数按下面的顺序处理：

1. 若 `i` 尚未被筛掉，先把 `i` 加入素数表。
2. 从 `j=0` 开始，按素数表顺序取 `p[j]`。
3. 先确认 `j<cnt`，再读取 `p[j]`；对正整数 `i`，可用 `p[j] <= n/i` 限制乘积范围。
4. 标记 `p[j]*i`。
5. 若 `i % p[j] == 0`，结束本轮内层循环；否则继续下一个素数。

**先标记，再判断是否停止。** 第一个整除 `i` 的 `p[j]` 是 `i` 的最小质因子；在这里停止，避免用更大的素数重复生成合数。

保留来源中的手算示意，假设上限至少为 18：

| 外层当前数 | 当前素数 | 本轮动作 | 随后的动作 |
| --- | --- | --- | --- |
| 6 | 2 | 标记 12 | 6 能被 2 整除，立即结束内层 |
| 6 | 3 | 不执行这一步 | 18 留到后面的轮次处理 |
| 9 | 2 | 标记 18 | 9 不能被 2 整除，允许继续尝试下一素数 |

这是动作顺序示意，不是本轮运行输出，也不代替完整实现的边界检查。

## 第四步：逐个审核下标属于哪一层

对每个 `p[?]` 和标记下标，写出它的含义，再看变量名。

`i % p[j]` 中需要的是“本轮取出的素数”；若误写成 `i % p[i]`，便把当前数当成了素数表位置。该位置可能未写入，也可能越界。全局零初始化数组读到零值后再参与取余，会触及除零；其他情境下不能断言一定表现为同一个错误。

除数为零的 `/` 或 `%` 在 C++ 中行为未定义，见 [乘除与取余规则](https://eel.is/c++draft/expr.mul)。不要用某个环境的退出码判断所有同类问题，也不要把“编译没有警告”当成下标语义正确。

| 容易混淆的点 | 改写时要留下的说明 |
| --- | --- |
| 先 `break`，后标记 | 当前应生成的合数可能被漏掉，先写动作顺序 |
| 素数表长度与最大下标 | 长度为 `cnt` 时，最大可读下标为 `cnt-1` |
| 先相乘再判是否越界 | 在乘法安全的前提下判断范围，或先用正整数除法限制 |
| 假定素数表开 `n/10` 一定够 | 近似的素数密度不能当容量证明；用可增长容器或有依据的上界 |
| 每组复用旧 `cnt`、标记表或结果表 | 明确重置全部相关状态，或约定只预处理一次 |
| 已筛到最大值却又把每次查询重筛 | 分开预处理上限与查询上限；计数查询可另设前缀计数 |

内存估算应按当前元素类型和存储形式记录。普通数组、`vector<bool>` 的压缩存储和整数最小质因子表不能混算；也不预设所有平台的 `int` 都占相同字节数。
