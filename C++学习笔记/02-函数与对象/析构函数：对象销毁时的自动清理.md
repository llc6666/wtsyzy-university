# 析构函数：对象销毁时的自动清理

## 一句话结论

析构函数是对象生命周期结束时自动执行的清理函数，用于归还对象持有的资源（例如 `new` 出来的链表节点）。名字固定为 `~类名`，没有返回类型，没有参数。

## 它解决什么问题

`new` 和 `delete` 必须成对出现，但人很容易忘记 `delete`，忘一次就是一次内存泄漏。析构函数把“释放资源”变成对象的自动义务：对象销毁时会自动执行。若类直接拥有由 `new` 分配的原始资源，析构函数应负责释放它们；若资源由 `std::unique_ptr` 等 RAII 成员管理，编译器生成的析构过程通常已经足够。

对比手动释放与析构释放：

```cpp
// 手动：每个分支都要记得 delete，容易漏
// 析构：销毁自动执行，永远不遗漏
```

## 工作机制

析构函数何时触发：

| 对象类型 | 销毁时机 |
| --- | --- |
| 栈对象 | 离开作用域（函数返回、块结束）时 |
| 堆对象 | 执行 `delete` 时 |
| 静态/全局对象 | 程序结束时 |

编译器在对象销毁点自动调用析构函数，无需手写调用语句。

链表类的析构标准模式：遍历释放全部节点。普通单链表直接走 `while (p != nullptr)`；循环链表没有 `nullptr` 结尾，必须先找到尾节点并令 `tail->next = nullptr` 断开环，然后再按普通单链表释放。直接写 `head->next = nullptr` 会断开并丢失其余节点，可能造成内存泄漏。

```cpp
class List {
public:
    Node* head;
    List() : head(nullptr) {}
    ~List();                    // 声明：~ + 类名
    void push(int d);
};

List::~List() {                 // 实现：函数头 = 类名 + :: + ~类名
    Node* p = head;
    while (p != nullptr) {
        Node* t = p->next;      // 先存下一站
        delete p;               // 再退当前房
        p = t;
    }
}
```

## 最小示例

```cpp
struct Node {
    int data;
    Node* next;
    Node(int d) : data(d), next(nullptr) {}
};

int main() {
    List l;                     // 构造函数：head = nullptr
    l.push(10);
    l.push(20);
    l.push(30);
    // return 0 这一刻，l 销毁，~List() 自动释放全部节点
}
```

## 常见错误与边界

1. **忘记释放自己拥有的原始资源**：链表类若用原始 `new` 创建节点却没有相应析构逻辑，对象销毁后节点会泄漏。若使用 `std::unique_ptr` 管理节点，通常无需手写析构。
2. **析构里双重释放**：析构中再对已释放的节点 `delete`，行为未定义。释放循环的"先存 next 再 delete"顺序不能反。
3. **循环链表直接 `while (p != nullptr)`**：环里没有空指针结尾，会死循环。应先找到尾节点，将 `tail->next` 置为 `nullptr`，再遍历释放。
4. **栈对象不能 delete**：析构由编译器自动调用，不要手动 `delete` 栈对象。
5. **析构函数没有参数和返回类型**：`~List()` 括号内必须是空的，`void` 都不写。

## 使用规则

- 类直接拥有动态资源（尤其是原始 `new` 得到的内存）时，必须有明确的释放责任；可手写析构，也可交给 `std::unique_ptr` 等 RAII 成员。
- 释放顺序："先保存下一站指针，再 delete 当前节点"。
- 循环链表释放：先找到尾节点，再令 `tail->next = nullptr` 断开环。
- 资源管理优先考虑现代 C++ 方案（`std::unique_ptr`），手写析构只用于所有权清晰的自定义容器。
