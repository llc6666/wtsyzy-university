# K09 动态内存与所有权

## 一句话结论

**每一次 `malloc` 都要回答三个问题：谁申请、谁使用、谁释放。** C 没有垃圾回收，也没有析构函数，所有权全靠约定与记性。

## 四条规则

1. **申请后立刻判空**：`malloc` 可能返回 NULL
2. **释放后立刻置 NULL**：避免悬空指针被再次使用
3. **谁申请谁释放**，跨函数时写进注释
4. **不重复释放**：同一块内存只能 `free` 一次

实测（见 [嵌入式实例.md](嵌入式实例.md)）：

```text
3) 链表内容：4 1 3
   销毁后 head = NULL
```

销毁函数把调用方的指针也置空了——这是所有权交接的完整写法。

## `malloc` 与 `calloc`

| 函数 | 行为 |
| --- | --- |
| `malloc(n)` | 分配 n 字节，**内容不确定** |
| `calloc(count, size)` | 分配并**清零** |
| `realloc(p, n)` | 改变已分配块的大小，可能搬移 |
| `free(p)` | 归还；`p` 本身的值不变（所以要手动置 NULL） |

写 `malloc(sizeof(*p))` 而不是 `malloc(sizeof(struct node))`：改类型时不会漏改。

## 为什么嵌入式里要慎用堆

- **碎片**：反复申请释放不同大小的内存，会让连续空间变碎，某次申请突然失败
- **时间不确定**：`malloc` 的耗时不固定，实时任务里不可接受
- **失败难处理**：裸机上失败往往只能重启

常见替代：**编译期定死的静态数组**、**内存池（固定大小块）**、**环形缓冲**。实测第 4 步演示的就是静态分配的写法。

## 易错清单（本节）

1. `malloc` 后不判空
2. `free` 后继续使用（悬空指针）
3. 重复释放
4. 只释放了头节点，子节点泄漏
5. 在中断服务函数里 `malloc`（不可重入，且耗时不定）
