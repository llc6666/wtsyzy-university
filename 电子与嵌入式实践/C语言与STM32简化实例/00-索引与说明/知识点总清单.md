# 知识点总清单

顺序即学习顺序（`K01 → K12`）。「对应资源」列给出原始资料的具体位置，不复制原文，只作定位与对照。

编写顺序上没有从「C 语言概论」慢慢铺，而是**嵌入式越早要用到的越靠前**：位运算（K03）提前到指针（K07）之前，因为 SPL 里配置 GPIO 先碰到的是掩码，不是指针算术。

## 三个阶段

按「能跑 → 能用 → 能组织」分三段，跟上面 12 个知识点是同一条线的不同切面：

- **第一段（K01–K03）能跑**：写得出最小 C 程序，说清编译四步在做什么，位运算能在纸上手算。这一段做完就能看懂 SPL 里 `GPIOA->ODR |= (1<<5)` 这类语句在干什么。
- **第二段（K04–K07）能用**：控制流、数组与字符串、函数传参、指针与地址。这一段做完能把串口收到的一串字符解析成命令，也能理解库为什么把寄存器包成结构体指针。
- **第三段（K08–K12）能组织**：结构体与内存布局、动态内存的取舍、`volatile`、多文件与头文件、基础数据结构。这一段做完能自己拆模块、能看懂库的头文件组织方式，也知道裸机上哪些 C 特性要慎用。

## 样板的验收口径

K01–K12 全部十二个知识点已建成，每个各含四件：`README.md`、`读-示例分析.md`、`写-练习记录.md`、`嵌入式实例.md`，并附已实际编译运行的 `.c`（K10 另有汇编探针，K11 另有三文件示例工程）。

验收时看三点：

1. 实例是否真的能在 PC 上编译运行（命令与输出都写在 `嵌入式实例.md` 里，可复现）。
2. 练习题是否标出「题面要点 + 我做在哪一步 + 复盘结论」三栏，而不是只列题名。
3. 易错清单是否写到了具体现象与后果，而不是只写「注意越界」这类空话。
4. 每题是否配齐「素材（指向 `99-素材库/` 的题面与参考解）+ 验收标准（用例表与五类边界）」，使搬走原始资料后仍能独立做题。

## 与正式知识库的分工

本库只做练习与对照。一个知识点在**本库**里反复写对、能讲清原理、且经编译或上板验证后，结论才回填到 `codeing/编程/c` 的正式目录；在那之前它在本库里只是「练习稿」。
