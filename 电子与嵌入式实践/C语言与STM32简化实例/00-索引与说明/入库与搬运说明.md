# 入库与搬运说明

本库已按「可整体搬运」的要求建成。这一页记录搬走时要带什么、在哪里补链接、以及公开时要划的边界。

## 一、搬运清单

**必须带**（这五项构成完整的库）：

```text
README.md                 顶层入口
00-索引与说明/            索引、来源登记、易错清单、本页
01-知识点/                K01–K12
02-嵌入式专题/            S01–S06
99-素材库/                题面、参考解、教程章节、MIT 许可全文
```

**不带**（原材料，本库不依赖）：

```text
exercism-c/  hairrrrr-C-CrashCourse/  cpq-bare-metal-programming-guide/
Amuvin-STM32F103-Notes/  dekuNukem-STM32_tutorials-阅读精选/
STMicroelectronics-STM32CubeF1-阅读精选/  *.zip  下载说明.md
```

`下载说明.md` 记录了原始 ZIP 的字节数与 SHA-256，属于下载环节的凭证，不随练习库搬运（若需要核对完整性，单独带它）。

**许可文件随行**：`99-素材库/exercism-c/LICENSE.md` 是 MIT 许可全文，对外分发时必须一起带。

**关于 `本地 STM32 资料/works` 的引用**：S04–S06 的「SPL 对照」段抄真实练习工程的代码（本地 OLED 工程原型、本地传感器工程原型），并在文里标了路径，这是**溯源标注，不是素材依赖**。搬运后这些绝对路径失效，但每个专题的结论、`嵌入式实例.md` 里的要点、以及 PC 模拟程序与实测输出都完整保留，**不影响独立使用**——搬走时不需要带 `本地 STM32 资料`。

## 二、整体移动不影响内部链接

库内所有链接都是**相对链接**，因此把上述五项作为一个整体移动到任何位置，内部链接依然有效。只有「外部指向本库」的链接需要按新位置重算。

## 三、入库位置（两个方案，需本人定）

### 方案 A：原地入库

留在 `学习资料下载/C与嵌入式编程-2026-09-30/`，在父级索引里补一条链接即可。

- 优点：不动文件，零风险
- 缺点：`学习资料下载` 这个名字暗示「临时下载物」，正式库的入口放在这里不直观

### 方案 B：移到正式位置

整体移动到正式知识库下，例如 `codeing/编程/C与嵌入式练习库/`，再补父级链接。

- 优点：位置与性质匹配，长期好找
- 缺点：需要移动目录并重算外部链接

移动后要改的外部链接：只有「从别的库指向本库」的那些，本库内部的不用动。

## 四、需要补链的父级文件

无论选哪个方案，都应在下面这些位置补一条入口（链接路径按最终位置调整）：

| 父级文件 | 建议补的位置 | 建议文本 |
| --- | --- | --- |
| `codeing/编程/README.md` | 「## 分区」列表末尾 | `[[<本库相对路径>/README\|C 与嵌入式编程练习库]]：练习题、参考解与 PC 可运行实例的练习场。` |
| `codeing/编程/c/README.md` | 「## 学习入口」附近 | 加一行说明：正式笔记在 `c/`，练习与素材在练习库 |
| `嵌入式/02-STM32/README.md` | 相关资料区 | 加一行：单片机场景的 PC 模拟见练习库 `02-嵌入式专题/` |

（Wiki 链接若不支持跨目录，改用普通 Markdown 相对链接即可。）

## 五、公开库的边界

若要进公开库 `wtsyzy-university-md`：

**可以公开**：本人撰写的部分——`README.md`、`00-索引与说明/`、`01-知识点/`、`02-嵌入式专题/` 里的全部 Markdown 与自写 `.c`。

**本批特批公开**：`99-素材库/` 里的已整理题面、参考解、教程章节和 CrashCourse 示例；来源、许可证和特批记录必须一起保留。今后的新增素材仍需单独核对，不因本批特批自动获得公开资格。

**折中做法**：公开库里只放一篇「练习方法与资源索引」，说明用了哪些开源资料、许可状态、以及为什么值得练，正文不复制原文。

公开时要同步的文件（按该库的既有规范）：

- `README.md` 的阅读入口
- `知识地图.md`
- `更新日志.md`（按固定字段：日期、提交号、更新内容、公开边界、验证、远端状态）

## 六、搬运前自检清单

搬走之前按这个顺序核一遍：

1. **四件齐全**：12 个知识点各有 `README`、`读-示例分析`、`写-练习记录`、`嵌入式实例`，且都有 `.c`
2. **专题三件齐全**：6 个专题各有 `README`、`嵌入式实例`、`xxx-demo.c`，且都能实际编译运行
3. **链接有效**：库内相对链接都能打开（可用脚本扫一遍 `[](...)`）
4. **frontmatter 完整**：每个 md 有 `title / tags / created / status`，素材类另有 `source`
5. **素材齐全**：每个知识点 README 里列的素材文件在 `99-素材库/` 里确实存在
6. **许可文件在**：`99-素材库/exercism-c/LICENSE.md` 未被删
7. **命令可复现**：`嵌入式实例.md` 里的编译命令与输出是实测过的，没有占位内容
8. **不留死链**：确认没有指向原始解压目录的链接（本库所有素材引用都指向 `99-素材库/`）

第 8 条最容易被忽略：如果哪篇笔记里写了「见 `exercism-c/c-main/...`」，搬走之后就是死链。本库建立时已避免，但**新增内容时要继续遵守**。（指向 `本地 STM32 资料/works` 的路径属溯源标注，不在本条范围内，见第一节说明。）

## 七、后续维护规则

1. 新增知识点：建目录 → 四件 + `.c` → 在 [知识点总清单](知识点总清单.md) 补行 → 在 [00-索引与说明/README.md](README.md) 的知识库入口表补行
2. 新增专题：建目录 → `README` + `嵌入式实例` + `xxx-demo.c` 三件（**必须实际编译并把输出抄进 README**）→ 在 [02-嵌入式专题/README.md](../嵌入式专题/README.md) 的专题表与映射表补行 → 在本页 [00-索引与说明/README.md](README.md) 的专题表补行
3. 新增素材：复制进 `99-素材库/` 对应来源与知识点目录 → 在 [99-素材库/README.md](../99-素材库/README.md) 的对应表补行 → 在知识点 README 的素材表补链接
4. 英文素材：译为中文后再入库，**英文原件不留**；代码标识符保留原文
5. 做完一题：更新 `写-练习记录.md` 的状态与复盘三问，新坑补进 [易错清单](易错清单.md)
6. 发现事实性错误：当场改，并在该页的 `status` 里注明改动
7. 新增 Makefile/构建文件：本库不做（保持「每个 .c 单条 gcc 命令可编」的做法），命令一律写进 `嵌入式实例.md`
