# K10 volatile 与编译器优化

## 一句话结论

`volatile` 用于约束编译器对易变对象的访问，常见于内存映射寄存器。它不提供原子性和线程同步，也不能当作普通内存的发布屏障；具体访问语义受编译器与平台约束。

## 确定证据：两份汇编

这是本知识点最硬的证据，不依赖运行时现象。源文件 [volatile-asm-probe.c](volatile-asm-probe.c)，命令：

```bash
gcc -std=c17 -O2 -S volatile-asm-probe.c -o volatile-asm-probe.s
```

**没有 `volatile`** 的等待循环，被编译成：

```asm
wait_plain:
	movl	flag_plain(%rip), %eax   ; 只读一次
	testl	%eax, %eax
	je	.L3
	ret
.L3:
	jmp	.L3                          ; 死循环，再也不去读 flag
```

**加了 `volatile`** 的等待循环：

```asm
wait_volatile:
.L6:
	movl	flag_volatile(%rip), %eax    ; 每一轮都重新读内存
	testl	%eax, %eax
	je	.L6
	ret
```

差别就在那一行 `movl` 是在循环里还是循环外。前者一旦进了死循环就永远出不来——这就是「中断里改了标志，主循环永远看不到」的真实机理。

## 一个重要的实验观察

用线程模拟中断的可运行版本 [volatile-demo.c](volatile-demo.c) 实测输出：

```text
1) 原子版本：循环次数约为 50，flag=1
2) 说明：跨线程通知不能用普通变量或单靠 volatile
```

当前可运行程序只有原子版本。旧版普通变量与 `volatile` 变量的跨线程读写存在数据竞争，已经移除，旧版正常退出的现象不再作为正确性证据。

外部函数调用有时会影响优化，但不是同步保证；链接时优化、可见的函数实现和别名分析都可能改变生成结果。循环次数受线程调度影响，不是固定验收值。

## 三条使用规则

1. 内存映射寄存器按芯片与编译器规则使用 `volatile`，通常直接使用厂商提供的寄存器定义。
2. 裸机中断与主循环共享的标志通常需要易变访问，并另查访问宽度、读改写和临界区；标志加 `volatile` 不代表共享数据已安全发布。
3. PC 线程或 RTOS 任务之间使用原子操作、锁或平台同步 API；复合操作和多个字段的一致快照需要额外同步。

官方语义边界见 [GCC Volatiles](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html)。

## 易错清单（本节）

1. 以为「试过没问题」就等于「没问题」——优化等级一变就露馅
2. 寄存器结构体成员漏写 `volatile`
3. 用 `volatile` 当同步手段（它不保证原子）
4. 以为 `volatile` 能保证执行顺序
5. 调试时关掉优化就正常，一开 -O2 就失灵（典型症状）
