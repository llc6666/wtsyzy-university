# K11 读：一个最小模块的三份文件

## 一、`sensor.h`：模块的对外界面

来源：本库自建示例 [multifile-demo/sensor.h](multifile-demo/sensor.h)

（原示例代码未随公开版复制；此处保留分析结论。）

逐项看这份头文件**放了什么**：

| 内容 | 为什么放这里 |
| --- | --- |
| include guard | 防重复包含 |
| `#include <stdint.h>` | 让用到 `uint16_t` 的地方都能编译（头文件要自足） |
| 宏常量 `SENSOR_OK/ERR` | 调用方需要知道成功失败的含义 |
| 函数声明 | 告诉调用方函数长什么样 |
| `extern` 变量声明 | 告诉调用方「有这么个变量，定义在别处」 |

以及**没放什么**：没有函数体、没有变量的初始化值、没有 `static` 的东西。

## 二、`sensor.c`：实现与隐藏

（原示例代码未随公开版复制；此处保留分析结论。）

值得学的三点：

1. **命名习惯**：内部标识符加 `s_` 前缀、全局变量加 `g_` 前缀。C 没有命名空间，靠前缀区分归属是最实用的办法
2. **判空**：输出型指针参数在使用前判空，返回错误码
3. **谁都能改的和谁都不能碰的，分得很清楚**：`g_sensor_read_count` 对外可见（所以调用方能统计次数），`s_last_raw` 只归本模块

读的时候带着一个问题：**每一条声明到底是在「定义」还是在「引用」**。分不清这两者，多文件工程里所有错误都会来。

## 读码小结

1. 看头文件，先确认它自足（用到的类型都有 include）
2. 看 `.c` 文件，先分出哪些是 `static`（内部）、哪些是全局可见
3. 看到 `extern` 就去找它的定义在哪
