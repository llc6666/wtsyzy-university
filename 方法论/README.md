# 方法论

这里的每一篇都以“完成一个可检查的产物”为终点。阅读后应能得到文件夹、表格、来源卡片、决策记录、项目说明或维护报告中的至少一种。只读完而没有产物，等于还没使用。

## 使用顺序

1. 新建知识库：从 [从零搭建可维护知识库](知识库构建/从零搭建可维护知识库.md) 开始。
2. 收到资料：按 [资料入库与来源卡片](知识库构建/资料入库与来源卡片.md) 保存原始证据。
3. 想把资料变成方法：按 [从来源到可复用笔记的编译流程](知识库构建/从来源到可复用笔记的编译流程.md) 写出有边界的结论。
4. 找不到内容：补 [知识地图与导航设计](知识库构建/知识地图与导航设计.md)。
5. 库开始变乱：执行 [每周维护与健康检查](知识库构建/每周维护与健康检查.md)。
6. 面临选择或启动项目：使用 [可复查的决策记录](决策与项目/可复查的决策记录.md) 与 [项目定义与验收](决策与项目/项目定义与验收.md)。
7. 完成任务后：按 [阶段复盘与成果回流](决策与项目/阶段复盘与成果回流.md) 把结果回写到知识库。
8. 准备公开：完成 [公开知识库的脱敏与发布检查](公开发布/公开知识库的脱敏与发布检查.md)。
9. 想让 Agent 参与重复性工作：从 [Agent 使用方法论](Agent使用/README.md) 建立任务契约、权限和验收。

## 输入

- 一个真实问题，例如“课程资料太乱，找不到最新规则”。
- 一个 Markdown 文件夹和每周 30 分钟维护时间。
- 至少一份可定位的原始资料。

## 步骤

按上面的使用顺序，只完成与当前问题对应的一步。不要在没有来源卡时设计复杂标签，也不要在没有项目交付物时写长复盘。

## 交付物

第一次完整执行后，应至少留下七层目录、一个来源卡、一篇可复用笔记、一个地图入口、一张决策或项目卡，以及一份维护报告。

## 统一质量门槛

一篇可复用笔记至少要能回答六个问题：何时用、输入是什么、具体怎么做、最后留下什么、如何验收、何时会失效。缺其中任一项时，先把它放在“资料”或“待验证”区，不要包装成结论。

## 最小闭环

```text
原始资料 → 来源卡片 → 可复用笔记 → 知识地图 → 决策或项目 → 复盘 → 更新前四项
```

这个流程只需要一个 Markdown 编辑器和文件夹即可实施。Obsidian 的内部链接和模板功能能减少维护成本，但不决定方法是否成立；其官方文档说明了 [Markdown/Wikilink 内部链接](https://help.obsidian.md/Linking%2Bnotes%2Band%2Bfiles/Internal%2Blinks)、[模板文件夹与日期变量](https://help.obsidian.md/Plugins/Templates) 的用法。

## 第一次执行清单

- [ ] 建好七层目录和根索引。
- [ ] 用一份官方资料建立来源卡片。
- [ ] 从该卡片写一篇只包含一个结论的可复用笔记。
- [ ] 在地图页建立入口链接。
- [ ] 用一个真实选择写决策记录。
- [ ] 一周后做一次维护报告。
