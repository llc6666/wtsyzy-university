# 第六册：读懂无线接口、邻居与 Mesh 路径

**目标：**用一张卡记清网卡声明的能力、当前接口、对端、二层路径和 IP 状态。准备一台已有无线配置且自己有权限管理的 Linux/OpenWrt 设备，或直接阅读本页示意字段。这里练观察，不要求更改模式、安装无线软件包、抓取空口流量或改动现有网络。

## 1. 分三层问问题

| 层次 | 问什么 | 入口 |
| --- | --- | --- |
| 无线电能力 | 驱动列出哪些接口类型？允许哪些并行组合？ | `iw list`；看 `Supported interface modes` 和已有的组合限制 |
| 当前无线接口 | 现在有哪些接口，各是什么类型？ | `iw dev`；根据实际输出选择接口名 |
| 对端或路径 | 客户端连着谁？已有 mesh 有无邻居和转发路径？ | 根据接口角色使用下表 |

`managed` 通常是连入 AP 的客户端，`AP` 提供接入，`mesh point` 属于 802.11s 的 mesh 接口。设备列出某模式，说明驱动报告了这种能力；不保证任意两种模式能并用，也不保证当前镜像、工具或配置已启用它。能否并用还受接口组合、信道及实现条件限制，别仅凭网卡数量断定。

## 2. 按现有角色选择只读命令

在命令中把 `接口名` 换成 `iw dev` 实际列出来的名称。先确认工具存在、权限足够。

| 当前角色 | 观察命令 | 结果说明 |
| --- | --- | --- |
| 客户端 | `iw dev 接口名 link` | 查关联状态、信号和报告的发射链路速率；链路速率不等于应用吞吐 |
| AP 或已运行的 mesh | `iw dev 接口名 station dump` | 看驱动报告的对端及计数；不把 MAC 地址或真实网络名贴进公开日志 |
| 已运行的 mesh | `iw dev 接口名 mpath dump` | 查看当前已知的二层目标和下一跳；无对应条目时不能猜测实际跳数 |
| 需要看 IP 是否走对 | `ip addr show`、`ip route show` | 地址和 IP 选路要另行查；Wi-Fi 对端已关联不能证明应用可用 |

**示意记录：**`mesh 接口存在 | 对端 B 的 peering 状态为 ESTAB | 目的 C 的 mpath 下一跳为 B | IP 与应用结果未取`。它支持“观察时看到了 B 的对端状态，记录中 C 的表项经 B”两句，不能支持“应用已连通”或“每次都经过 B”。二层 mesh 转发不会表现成逐个 IP 路由跳点；别用 `traceroute` 的跳数证明 802.11s 转发跳数。

## 3. 有性能记录时这样读

先核对来源：发送端还是接收端、方向、协议、时长、单次还是汇总、当时的路径和频宽。随后区分链路报告速率、应用吞吐、时延和丢包；链路速率高同样可能遇到重传或竞争。共享信道上的多跳会消耗更多空口时间，但没有固定的“每跳必然减半”，不能把缺测或失败的样本填成零来算平均值。

**产物：**`驱动报告的能力 | 当前角色 | 对端状态 | 二层路径 | IP/应用证据 | 记录条件 | 未知项`。最少写出一个已知和一个未知，例如“支持 mesh，当前只开了客户端接口”。若工具缺失、没有合法的设备权限或输出不支持该字段，保留未知项，不切到别的模式补结果。涉及频道、功率或无线配置时，按设备所在地规则和对应版本文档另行核对。
