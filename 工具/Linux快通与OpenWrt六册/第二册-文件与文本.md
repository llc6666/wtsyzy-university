# 第二册：改配置先改副本，读懂差异再替换

**目标：**在普通用户的本地临时目录里，把一份样稿的级别由 `info` 改为 `warn`，留下原版、改稿和修改证据。下面的文件只是练习样稿，不对应系统或路由器上的真实配置。

## 1. 养成先定位、后动手的习惯

```sh
lab=$(mktemp -d) && cd "$lab" && pwd
```

先确认新目录打印成功。后面的命令都在同一会话和这个目录中执行；如果失败，停止，不继续创建或覆盖文件。

```sh
printf '%s\n' 'name=demo' 'level=info' > app.conf
cp -p app.conf app.conf.before
find . -type f -name '*.conf*'
grep -n '^level=' app.conf
sed 's/^level=info$/level=warn/' app.conf > app.conf.proposed
diff -u app.conf.before app.conf.proposed
```

预期 `diff` 只显示一行删除、一行增加，`name=demo` 保持不变。`diff` 的状态 `1` 表示内容不同，在这一步属于正常结果；大于 `1` 表示出错。若没有差异、改了多行或出现错误，先查输入和匹配表达式。

`find` 的通配符加引号，让 `find` 匹配文件名，别让 Shell 提前展开。`sed` 先写入新文件；切勿把输入文件和 `>` 后的输出设为同一个路径。

## 2. 用 vi 练一次退出与保存

若装有 `vi`，打开 `app.conf.proposed`。普通模式按 `i` 进入插入，修改一行后用 `Esc` 返回普通模式：

- 用 `:q!` 加回车退出并放弃未保存改动，再用 `diff -u` 对比，差异应仍然只有级别一项。
- 重新打开后，把级别临时改成 `debug`，用 `:wq` 加回车保存并退出；确认差异出现 `level=debug`，再用同样的方式改回 `warn`。如果报只读，先查当前目录和文件权限，不强制写入。

只在确认是练习副本、变更符合预期后，才用 `cp app.conf.proposed app.conf` 更新练习目标。要恢复，使用 `cp app.conf.before app.conf`，再检查 `diff -u app.conf.before app.conf` 是否无输出且状态为 `0`。真实设备还要确认文件归属、权限、持久化、服务如何读取修改，以及从哪里回滚，见[第三册](第三册-进程权限与服务.md)。

## 3. 区分输出、错误与管道

```sh
grep '^level=' app.conf missing.conf > result.txt 2> errors.txt
cat result.txt
cat errors.txt
```

预期一份文件有匹配行，另一份有缺失文件的错误；即使有正常行，整条 `grep` 仍可能报错。`|` 默认只把左侧标准输出交给右侧；`>>` 追加，`>` 截断覆盖，`2>` 捕获标准错误。需要合在一起时，写 `命令 > combined.txt 2>&1`，顺序表示先定标准输出位置，再让标准错误去同一处。

文本处理按需要选工具：用 `grep` 挑行，`sed` 预览替换，`awk -F= '{print $1}'` 读按等号分开的第一列。`sort | uniq -c` 先把同样的行排到一起再计数；`uniq` 单独使用只处理相邻重复行。精简设备上先核对选项是否存在。

**自查：**手里有可读的原件、改稿、正常输出和错误记录；能解释为什么备份不等于应用，为什么改前要先看差异，以及为什么先输出再重定向标准错误的顺序不能随意换。
