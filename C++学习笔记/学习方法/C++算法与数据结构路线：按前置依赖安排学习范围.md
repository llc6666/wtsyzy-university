# C++ 算法与数据结构路线：按前置依赖安排学习范围

## 先确定这份路线要解决什么问题

适用于已经接触 C++，同时学习基础算法或嵌入式编程，却经常在“补语法、刷题、学新数据结构、做工程”之间切换的读者。

这页用于决定下一步学什么、需要哪些前置知识、学到哪一步可以暂时收口。具体一道题怎样推导、实现和复盘，另见 [C++ 学习闭环](C++学习闭环：从知识点到独立解题.md)；已有笔记怎样安排复习，见 [C++ 复习方法](C++复习方法：从代码画像到重点清单.md)。

先填下面五行，再选专题。空白处必须落到实际任务，不能只写“打好基础”。

```text
近期用途：课程编程 / 基础算法 / 嵌入式，选一个作为主线
下一个交付：例如解释并独立写出固定容量队列的入队、出队和满空处理
当前阻塞：具体到数组边界、函数参数、状态定义等一个问题
允许借助的资料：接口文档 / 自己的旧笔记 / 完整解答，预先约定
本阶段暂缓：列出会分散精力、又不影响当前交付的专题
```

若三个用途都要兼顾，保留一个主线任务，再选一个能复用同一概念的小任务。不要把三套完整课程同时排进近期清单。

## 一、按前置依赖交替推进

语言知识与算法可以交替学。例如，基础动态规划可以用数组和循环表达，不需要先手写平衡树；用裸指针实现链表，则需要先理解节点、指针、空值和生命周期。

下面是一套可调整的顺序。课程要求、目标问题和已有能力不同，可以跳过已有记录充分的部分，也可以回退补缺口。

| 阶段 | 先补的语言与表示知识 | 接入的算法或数据结构 | 本阶段留下什么 |
| --- | --- | --- | --- |
| 1. 表达数据与步骤 | 类型、数值范围、分支、循环、函数参数与返回值 | 扫描、模拟、直接枚举 | 输入输出说明、变量职责、最坏操作量与中间数值范围 |
| 2. 管理一组数据 | 数组、字符串、`vector`、有效长度、下标范围 | 排序、前缀和、差分 | 下标约定、区间含义、公式与边界说明 |
| 3. 利用顺序与单调性 | 比较条件、循环区间、返回位置的含义 | 二分、双指针、滑动窗口 | 不变量或判定条件，以及为什么能移动端点 |
| 4. 按操作选择结构 | 标准容器接口、比较规则、修改后位置的有效性 | 栈、队列、双端队列、堆、集合、映射、哈希 | “需要什么操作，为什么选这个结构”的选择卡 |
| 5. 表达分支与连接 | 函数调用、局部与共享状态、网格或邻接表表示 | 递归、回溯、DFS/BFS、基础树遍历 | 状态定义、出口、访问标记时机和状态恢复说明 |
| 6. 处理依赖与最优性 | 状态存储、遍历顺序、基本复杂度分析 | 基础贪心、动态规划、拓扑排序、并查集 | 贪心的反例与依据，或 DP 五项定义，或图中依赖/连通关系 |

这些是几组学习任务，不要求把一整行学完才碰下一行。遇到具体阻塞时，只补当前任务直接依赖的部分。概率、证明、图等数学前置也要按所选课程补齐。

作为课程范围的参考，MIT 6.006 的入门算法课程同时涉及数据结构、排序、图搜索和动态规划，并列出了编程与离散数学前置。本文的 C++ 顺序是从学习记录提炼的安排，不是该课程的官方路线：[MIT 6.006 课程大纲](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/pages/syllabus/)。

## 二、指针和内存单独补，但不阻断全部算法

当问题涉及数组传参、链表、缓冲区或对象失效时，把语言线拆成下面四步：

1. 先画对象关系：哪个是对象，哪个变量保存地址，访问的元素范围是什么。
2. 再看调用关系：参数得到的是副本、引用还是指针；函数能修改什么，返回后哪些对象仍然存在。
3. 再标生命周期：谁创建对象，何时结束，谁负责资源释放；读写发生在对象存在的哪个阶段。
4. 最后进入结构操作：以单链表为例，分别记录空表、头节点、尾节点、目标不存在和删除节点后的连接关系。

对象占用的存储与对象的生命周期需要分开理解；生命周期开始前和结束后的使用受限制。不能仅凭“地址还在”判断对象可以访问。正式规则与例外见 [C++ 工作草案 basic.life](https://eel.is/c++draft/basic.life)，入门时先围绕当前代码画关系，不把整节标准条文当作背诵任务。

| 语言主题 | 近期做到什么程度 | 可以先放后的内容 |
| --- | --- | --- |
| 数组与 `vector` | 说明长度、合法下标、传参方式，以及哪些修改可能使原有位置失效 | 自己实现完整的扩容容器 |
| 指针与引用 | 区分对象、地址与访问路径，解释参数和返回值对应的对象 | 复杂函数指针声明与模板技巧 |
| 生命周期与资源 | 指出局部对象失效、悬空访问、重复释放和遗漏释放各自发生在哪一步 | 自定义分配器、placement new、ABI |
| 单链表 | 追踪建立、遍历、插入、删除、释放时的节点关系 | 侵入式链表或通用容器库设计 |
| 标准容器与资源管理 | 能解释由谁管理存储、哪些引用仍有效，并按接口使用 | 为普通练习重写标准库内部实现 |

手写链表用于暴露指针与生命周期问题。日常算法练习若没有特定要求，直接选用合适的标准容器。嵌入式是否允许动态分配，要根据工程约束另行决定，不能照搬桌面程序的选择。

## 三、给每个专题写停止线

“基础算法”仍然可能无限扩展。先写当前需要的题型和产物，再写什么条件出现时才扩展。

| 专题 | 当前收口产物 | 重新扩展的触发条件 |
| --- | --- | --- |
| 二分与双指针 | 说明搜索目标、区间含义、端点移动依据及无解表示 | 新问题的判定方向、边界或窗口条件改变 |
| 栈、队列、堆与映射 | 列出操作需求、结构选择、容量和复杂度；能解释一个备选结构为何不合适 | 遇到新的顺序查询、更新或容量要求 |
| 递归与搜索 | 写清一层做什么、何时结束、访问标记和共享状态如何处理 | 状态规模增大，或出现重复状态、复杂剪枝需求 |
| 贪心 | 写候选规则、尝试构造反例，并给交换论证或其他适用的正确性依据 | 规则无法解释新约束，或已经发现反例 |
| 基础 DP | 写状态、转移、初值、遍历顺序、时间与空间复杂度 | 当前状态不能表达约束，或复杂度不满足要求 |
| 基础图 | 用邻接表示、遍历、拓扑或并查集解决明确的连接/依赖问题 | 问题出现带权路径、流量、匹配等新要求 |

DP 可从一维状态、网格状态、0/1 背包、完全背包和 LIS 中选当前需要的部分，逐项记录差异。图基础可先围绕连通与依赖展开。这里没有“学完这些就足够所有课程或竞赛”的保证。

线段树、网络流、复杂字符串、数位 DP、状态压缩 DP、FFT 等可先进入待学清单。目标题型或课程明确要求时，再补对应前置；单纯看见别人学习，不构成本阶段扩展理由。

停止线也不能只写“看过了”。把独立解释、实现记录、变式和读者实际取得的运行结果分开登记。已有记录不足时保留欠账，具体记录方式沿用 [C++ 学习闭环](C++学习闭环：从知识点到独立解题.md)，不用另建一套重复台账。

## 四、只选一个语言缺口和一个算法任务

安排下一轮学习时，按下面顺序选任务：

1. 从最近一次卡点里找一个反复阻塞后续学习的问题，例如函数参数无法对应到实际对象。
2. 找一个直接使用它的任务，例如解释队列状态通过参数传递后由谁修改。
3. 把目标压到可交付的范围，例如队列的满空规则与状态变化；先不扩展成串口协议、显示和菜单的综合工程。
4. 预先写停止条件：完成哪些说明和独立工作后收口；哪些新问题只登记、不在本轮展开。
5. 结束时从三种处理方式中选一种：继续当前任务、回退补前置、进入下一个任务，并写一句依据。

可直接复制的记录卡：

```text
本轮语言缺口：
直接使用它的算法/数据结构任务：
前置资料与允许参考的范围：
最小交付：
本轮暂缓：
实际留下的说明、实现或结果：
仍缺的证据：
下一步与理由：
```

例如，BFS 卡在队列状态和访问标记时，下一步可以退回一个小网格，画出入队、出队与标记顺序。此时继续加图论题量，无法直接解决这个缺口。这个例子是选任务的方法示例，不代表本轮执行过练习。

## 五、同一个概念连接 PC 与 STM32

已有桌面练习和嵌入式学习任务时，可以共用一个概念问题，再分别记录各自的证据。下表供读者选择练习，不要求整理者代为运行或上板。

| 共用概念 | PC 侧可以留下的材料 | STM32 侧需要单独回答的问题 |
| --- | --- | --- |
| 函数、条件与位运算 | 参数含义、位位置和分支条件的逐步说明 | 当前芯片上配置位、输入/输出寄存器和有效电平各是什么 |
| 状态与事件 | 状态转移表，当前值、历史值与事件次数的分工 | 输入变化怎样变成一次事件，采样、消抖与响应怎样安排 |
| 结构体与指针参数 | 状态对象由谁持有，函数能修改哪些字段 | 主循环与回调各负责什么，共享对象何时被访问 |
| 数组与队列 | 有效长度、头尾含义、满空约定与越界边界 | 接收端与消费端如何交接，缓冲满时采取什么策略 |
| 时间与差值 | 时间戳含义、时间差和回绕前提的说明 | 时基来源、计数范围、任务执行时长与实际观测如何记录 |
| 显示缓冲 | 一维索引与二维位置的映射关系 | 页列布局、刷新方式是否影响输入与任务调度 |

PC 上的解释或运行记录不能替代实际硬件行为。中断共享状态也不能只用一个 `volatile` 标签就写成“并发问题已解决”；原子性、访问顺序和缓冲区交接需要按目标平台另查。

每次嵌入式练习只接入当前能观察的概念。输入、时基和状态逻辑尚未清楚时，先暂缓显示、菜单和复杂协议。动态规划、树与复杂图论可以继续在 PC 侧学习，不必为联动而强行移植。

需要规划独立重建时，继续使用 [基础到 STM32：阶段任务与验收](../../电子与嵌入式实践/基础到STM32：阶段任务与验收.md) 的参考权限、首次作答、卡点和分层证据表；串口场景可衔接 [中断搬运、环形缓冲与命令解析](../../电子与嵌入式实践/STM32串口接收：中断搬运、环形缓冲与命令解析.md)。
