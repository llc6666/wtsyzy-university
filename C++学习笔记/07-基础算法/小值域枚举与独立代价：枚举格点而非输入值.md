# 小值域枚举与独立代价：枚举格点而非输入值

## 一句话结论

当答案属于一个很小的连续整数域，并且候选值确定后每个元素的代价可以独立计算，就把每个候选值都试一遍，再取总价最小者。枚举的是允许的整数格点，不一定是输入中出现过的数。

## 1. 什么时候使用这套骨架

同时满足下面三个条件时，直接枚举通常比强行推公式更稳：

1. 最终方案可以用一个整数边界或一个小数量的参数表示。
2. 参数的候选范围很小，例如 `0..83`。
3. 参数固定后，每个元素的费用只取决于自己，可以逐个相加。

示例模型：有若干整数高度，最终所有高度必须落在宽度为 `17` 的区间 `[low, low + 17]` 内。区间外的高度移动到最近边界，移动 `d` 格的费用为 `d²`。求最小总费用。

这类题的关键在建模：最终状态由区间下界 `low` 决定；区间确定后，每座山的账单互不影响。

## 2. 为什么枚举下界就够了

给定 `low` 后，高界就是 `low + 17`。单个高度 `h` 的费用为：

```text
h < low          时，费用为 (low - h)²
low <= h <= high 时，费用为 0
h > high         时，费用为 (h - high)²
```

只需枚举所有可能的 `low`，把每座山的费用加起来。

候选下界可以从输入最小值枚举到 `最大值 - 17`：

- 下界低于输入最小值时，没有山需要向下移动；把下界向上移动不会增加低侧费用，并会让高侧边界上移，因此无需保留更低候选。
- 下界高于 `最大值 - 17` 时，高界已经覆盖最大高度；继续上移只会让更多低山上移，费用不会更小。
- 如果最大高度与最小高度之差不超过 `17`，原数据已经满足限制，答案直接是 `0`。

注意：最优下界不必等于某座山的原高度。高度为 `10` 和 `30`、宽度为 `17` 时，区间 `[12, 29]` 的费用是 `2² + 1² = 5`；区间 `[10, 27]` 和 `[13, 30]` 的费用都是 `9`。只枚举输入值会漏掉最优解。

## 3. 可执行步骤

### 输入

- `n` 个整数高度；
- 高度值域已知且较小，或能通过最小值和最大值把候选区间压缩到可接受规模；
- 区间宽度 `width` 与费用函数已明确。

### 处理

1. 读入数据并求最小值、最大值。
2. 若 `max - min <= width`，返回 `0`。
3. 枚举 `low = min` 到 `max - width` 的每个整数。
4. 对每个高度计算它到区间的距离。
5. 用 `long long` 累加距离平方。
6. 保留所有候选中的最小总费用。

### 输出与验收

- 输出最小总费用。
- 用一个官方样例或手算样例核对总价。
- 至少覆盖：单元素、全相等、刚好满足宽度、逆序输入、极端高度。
- 用一个独立暴力版本枚举更宽的候选区间，对随机小数据做对拍。

## 4. 最小可编译实现

```cpp
#include <algorithm>
#include <iostream>
#include <limits>
#include <vector>

long long minimum_cost(const std::vector<int>& heights, int width) {
    const auto [min_it, max_it] = std::minmax_element(heights.begin(), heights.end());
    const int min_height = *min_it;
    const int max_height = *max_it;

    if (max_height - min_height <= width) {
        return 0;
    }

    long long answer = std::numeric_limits<long long>::max();
    for (int low = min_height; low <= max_height - width; ++low) {
        const int high = low + width;
        long long cost = 0;
        for (const int height : heights) {
            long long distance = 0;
            if (height < low) {
                distance = low - height;
            } else if (height > high) {
                distance = height - high;
            }
            cost += distance * distance;
        }
        answer = std::min(answer, cost);
    }
    return answer;
}

int main() {
    int n = 0;
    std::cin >> n;
    std::vector<int> heights(n);
    for (int& height : heights) {
        std::cin >> height;
    }
    std::cout << minimum_cost(heights, 17) << '\n';
}
```

编译命令：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -g range_enum_demo.cpp -o range_enum_demo
```

示例输入：

```text
5
1 4 20 21 24
```

预期输出：

```text
18
```

这个结果来自区间 `[4, 21]`：高度 `1` 移动 `3` 格，费用 `9`；高度 `24` 移动 `3` 格，费用 `9`；总费用 `18`。

## 5. 复杂度和边界

如果候选下界有 `K` 个、高度数量为 `N`，时间复杂度是 `O(KN)`，额外空间是 `O(N)`。当高度域为 `0..100`、宽度为 `17` 时，候选最多 `84` 个；`N <= 1000` 时最多约 `84000` 次逐元素计算。

需要重新评估的情况：

- 值域扩大到 `10^9`，逐个枚举会超时，应研究候选断点、排序、前缀和或二分等方法。
- 费用不再独立，例如移动一座山会改变另一座山的限制，此模型不能直接套用。
- 费用溢出 `int`，总价和平方计算都应使用 `long long` 或更宽类型。
- `heights` 为空时，`minmax_element` 没有有效结果；若题目允许空输入，应先定义返回值或拒绝输入。

## 6. 三个可迁移的判断

1. 先问“答案参数的候选量有多大”，再选枚举、排序、二分或动态规划。
2. 先问“参数固定后各元素是否独立计价”，能独立相加就优先写出 `cost` 函数。
3. 先问“候选是输入值还是允许域中的格点”，连续整数限制通常要求枚举每个格点。
