# STM32 串口调试：UART 回显、`printf` 重定向与日志边界

## 这页解决什么问题

串口是嵌入式系统最便宜的观察窗口，但“串口有输出”只能证明某条软件路径执行过，不能证明供电、时钟、接线、协议和其他外设都正确。先建立单字节或短字符串回显，再把日志接入更复杂的应用。

## 1. 先核对电气和协议

| 项目 | 要确认的内容 |
| --- | --- |
| 接线 | MCU TX → 模块 RX，MCU RX → 模块 TX，GND 共地 |
| 电平 | USB 转 TTL 模块的 I/O 电平在 MCU 允许范围内 |
| 接口 | 当前芯片、封装和板卡真正引出的 USART/UART 及复用引脚 |
| 帧格式 | 波特率、数据位、校验位和停止位两端完全一致 |
| 工程 | 外设时钟、GPIO 复用、初始化顺序和中断/DMA 配置 |

常见的 `115200 8N1` 表示 115200 波特率、8 个数据位、无校验、1 个停止位。它只是常用组合，不能替代设备手册中的配置要求。TTL/CMOS UART 与 RS-232 使用的电压范围和逻辑约定不同，接入 RS-232 接口时需要专用电平转换器。

## 2. 先做阻塞发送

第一轮只发送固定短字符串，避免同时引入接收缓存、DMA 和格式化输出：

```c
uint8_t message[] = "boot ok\r\n";
HAL_UART_Transmit(&huart1, message, sizeof(message) - 1U, 100U);
```

`sizeof(message)` 包含字符串末尾的 `\0`，串口文本通常不需要把它发送出去，所以长度减一。`huart1`、接口编号和引脚都是当前工程生成的对象，不应从别的板卡直接照搬。

阻塞发送期间 CPU 会等待发送完成，适合建立基线和发送很短的诊断信息。发送量增加或实时性变高后，再评估中断或 DMA；迁移时要重新记录缓存所有权、完成条件和错误处理。

## 3. `printf` 重定向要看工具链

`printf` 只是格式化层，最终仍需一个字符输出通道。不同 C 库和编译器的入口可能不同，不能只复制函数名：

```c
/* 仅示意：使用当前工程的 huart1 和 HAL 头文件 */
int __io_putchar(int ch)
{
    uint8_t byte = (uint8_t)ch;
    HAL_UART_Transmit(&huart1, &byte, 1U, 100U);
    return ch;
}
```

另一些 ARM 编译器/库使用 `fputc` 或 `_write` 作为重定向入口。配置前先查当前工具链的 C 库文档和工程模板，再用一条固定字符串验证；浮点格式化还可能需要额外链接选项，并会增加固件体积。

## 4. 接收回显的最小闭环

接收路径至少要明确四件事：

1. 缓冲区由谁写、由谁读；
2. 一帧以固定长度、换行符、空闲检测还是协议字段结束；
3. 缓冲区满时丢弃、覆盖还是报错；
4. 接收错误、超时和重新启动接收的动作。

可先用轮询做一个单字节回显，确认链路后再切换到中断或 DMA。DMA 只负责搬运数据，不能自动替你定义帧边界、处理缓存溢出或解析协议。

## 5. 日志不要放进高频中断

`printf` 和阻塞式 `HAL_UART_Transmit` 可能占用较长时间。中断服务函数应尽快保存事件和必要数据，随后交给主循环或低优先级任务输出：

```text
中断：记录 event_id、时间戳、少量参数 → 置位标志
主循环：读取标志 → 格式化 → 串口发送 → 记录发送结果
```

这样可以减少高优先级中断被日志阻塞的风险，也便于区分“事件发生”和“日志成功发送”。

## 6. 从乱码到无输出的排查顺序

1. 测电源、GND 和 UART 空闲电平。
2. 检查 TX/RX 是否交叉，模块是否接到了当前工程配置的引脚。
3. 检查两端波特率、数据位、校验和停止位。
4. 检查时钟树与实际外部晶振，确认 UART 初始化返回值。
5. 用阻塞固定字符串替代 `printf`，隔离格式化层。
6. 再检查接收中断、DMA、缓存和协议解析。

## 验收标准

- 复位后能看到带版本标识的固定启动行。
- 连续发送至少 20 个短帧，回显无乱码、无丢失，结果有原始日志留存。
- 断电再上电至少三次，现象一致。
- 日志记录了接口、接线、串口参数、工程提交号和异常处理方式。
- 没有把一次串口输出误判成全部硬件链路已验证。
