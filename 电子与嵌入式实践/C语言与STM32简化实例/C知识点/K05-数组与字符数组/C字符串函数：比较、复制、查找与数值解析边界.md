# C 字符串函数：比较、复制、查找与数值解析边界

## 这篇笔记解决什么问题

串口命令、配置文本和用户输入经常同时涉及比较、复制、拼接、查找与数字解析。函数名很像，前置条件却不同。使用前先写清楚四件事：

1. 输入是否是以 `\0` 结尾的 C 字符串。
2. 目标缓冲区的容量是多少，容量是否包含结尾的 `\0`。
3. 操作结果是字符串、字节序列、指针，还是一个解析状态。
4. 失败、截断、找不到或输入未消费完时，调用方怎样处理。

如果输入来自串口或文件，先把“收到多少字节”和“是否已经形成字符串”分开记录。一个字节数组只有在有效范围内存在 `\0` 时，才能直接交给 `strlen`、`strcmp` 等字符串函数。

## 先固定字符串契约

```c
char text[] = "abc";       /* 4 个字节：a、b、c、\0 */
char bytes[3] = {'a', 'b', 'c'}; /* 只是字节数组，不是 C 字符串 */
```

`strlen` 只统计 `\0` 之前的字符，不把 `\0` 计入长度。写入一个长度为 `n` 的字符串时，至少要为 `n + 1` 个字节留出空间。若数据本来是带长度的二进制或串口帧，应继续按“指针 + 长度”处理，不要为了调用字符串函数而强行添加终止字节。

## 按任务选择函数

| 任务 | 函数 | 结果与前置条件 | 主要风险 |
| --- | --- | --- | --- |
| 比较完整字符串 | `strcmp` | 小于、等于或大于零；输入都必须是字符串 | 不要假定不等时一定返回 `-1` 或 `1` |
| 比较前缀 | `strncmp` | 最多比较 `n` 个字符 | `n` 太小会把不同的完整字符串误判为相同前缀 |
| 获取字符串长度 | `strlen` | 返回 `size_t`，不含 `\0` | 输入无终止字节会越界读取；循环内反复调用可能造成额外遍历 |
| 复制字符串 | `strcpy` | 复制到目标并包含 `\0` | 不检查目标容量 |
| 有上限地复制 | `strncpy` | 最多写 `n` 个字节；源足够长时可能不写 `\0` | 不能把它当作总能生成字符串的安全复制函数 |
| 追加字符串 | `strcat`、`strncat` | 在目标字符串末尾追加 | 目标必须先是字符串，并且要有完整剩余容量 |
| 按字节复制 | `memcpy` | 复制指定字节数 | 区域重叠时行为未定义 |
| 重叠区域移动 | `memmove` | 复制指定字节数 | 仍需自行确认源、目标范围有效 |
| 按字节填充 | `memset` | 每个字节写入同一个无符号字节值 | 不能用 `memset(int_array, 1, ...)` 表示每个整数都等于 1 |
| 查找字符或子串 | `strchr`、`strstr` | 返回指向命中位置的指针，找不到返回 `NULL` | 指针差值只适用于同一数组中的位置 |
| 解析整数 | `strtol` | 可区分数值、未消费文本和范围错误 | 只看返回值无法区分输入 `"0"` 与非法输入 |
| 按格式读取 | `sscanf` | 通过返回的成功赋值数判断读到了什么 | 格式可能只消费前缀，剩余非法文本仍需处理 |

## 比较时只检查关系，不猜返回值

判断两个命令是否相等，应检查 `strcmp` 是否为零：

```c
if (strcmp(command, "start") == 0) {
    /* 命令内容相同 */
}
```

不等时只使用 `< 0` 或 `> 0` 表达字典序关系。`strcmp(a, b) == 1` 不是可移植的“不等且 a 更大”判断。

`command == "start"` 比较的是两个地址，不能用于比较字符串内容。若需要比较固定长度的协议字段，先确认字段的有效长度，再决定是否使用 `strncmp`；比较长度不足时，结果只能说明前缀相同。

## 复制时把容量写进操作步骤

对外部输入复制到固定缓冲区时，先处理零容量，再预留终止字节：

```c
if (capacity == 0) {
    return;
}

strncpy(destination, source, capacity - 1);
destination[capacity - 1] = '\0';
```

这段流程解决的是“目标最多容纳多少字符”的问题。它没有解决 `source` 是否可读、`destination` 是否指向有效存储区、源和目标是否重叠等问题；这些仍要在接口契约中单独写明。对于需要知道实际长度、截断状态或更严格错误处理的接口，应把长度和状态作为返回信息保留下来。

拼接前要先计算：

`目标已有字符数 + 要追加的字符数 + 1 <= 目标容量`

如果数据是带长度的字节帧，优先使用长度驱动的 `memcpy` 或 `memmove`，不要先把二进制数据当字符串。

## `memcpy`、`memmove` 与 `memset` 的分工

- 两段有效范围不重叠时，可以考虑 `memcpy`。
- 源和目标可能重叠时，使用 `memmove`，并仍然确认两段范围都在对象内。
- 初始化字节区域时使用 `memset`。它逐字节写入，写入 `1` 得到的是重复的 `0x01` 字节，不是任意整数对象的数值 1。

在代码审查中，看到 `memcpy` 时先标出源区间、目标区间和字节数；看到 `memset` 时再标出“按字节填充值”的含义。这两个标注比函数名本身更能暴露边界错误。

## 解析数字时保留三类结果

命令解析不能只问“返回值是不是 0”。至少保留：

1. 是否读到了一个数字。
2. 数字后面是否还有未允许的字符。
3. 数值是否超出目标类型范围。

`strtol` 的使用卡片可以写成：

```text
输入：指针、进制、允许的结束字符
输出：数值、结束位置、范围错误状态
接受：结束位置符合协议，且数值在目标范围
拒绝：没有消费数字、尾部有非法字符或发生范围错误
```

若使用 `sscanf`，检查返回的成功赋值数量，并明确是否允许空白、分隔符和尾部内容。`atoi` 无法通过返回值报告这些区别，适合性应先经过接口评估。
