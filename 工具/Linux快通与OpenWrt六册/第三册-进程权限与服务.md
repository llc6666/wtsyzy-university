# 第三册：从进程、权限和日志判断服务状态

**目标：**分清“配置里写了什么”“服务现在做了什么”“还能不能恢复”。普通 Linux 的练习只操作自己启动的任务；在已获授权的 OpenWrt 设备上先做只读观察。

## 1. 先确认进程，再决定是否操作

`ps` 记录 PID、命令和用户（具体列以本机为准）。进程存在只说明程序实例在运行；它可能仍未打开监听端口。被管理的服务还可能由管理器拉起，观察时要记录服务和 PID 两项。

本地终端里可以启动自己的 `sleep 120 &`，紧接着用 `pid=$!` 记下后台任务的 PID，再看 `jobs` 与 `ps`。只在确认它仍是刚才自己的 `sleep` 时，用 `kill "$pid"` 请求结束，再看 `jobs`。服务故障先用服务文档规定的动作，请求退出后也别立刻对未知 PID 强制终止。

## 2. 权限拒绝先问“谁、在哪一层”

| 要区分什么 | 先看 | 结论的边界 |
| --- | --- | --- |
| 当前身份和组 | `id` | 文件所有者与当前用户可能不同 |
| 文件读、写、执行 | `ls -l 文件` | `-rw-r-----` 表示所有者读写，所属组只读，其他用户无普通权限 |
| 上级目录是否可穿过 | `ls -ld 上级目录`，必要时逐级向上 | 目录需要 `x` 才能按名称访问内部条目；创建、删除还取决于目录权限 |
| 存储是否允许写 | 看挂载选项与剩余空间 | 只读挂载和磁盘空间不足不能靠扩大文件权限解决 |

在第二册的样稿上可用 `chmod u=rw,go= app.conf.proposed` 练习，预期普通权限位为 `-rw-------`。不对真实服务目录递归放开权限。

## 3. OpenWrt：依次看配置、进程、监听、日志

1. 先读 `cat /etc/os-release`，再用 `command -v uci; command -v opkg; command -v apk` 记录实机有哪些命令。官方 25.12 系列迁移到 apk；较早的 OpenWrt 教程常用 opkg。定制镜像以实机和对应文档为准，不混用包仓库。
2. 记录目标服务对应的配置区段。如果设备使用 UCI，`uci show system` 可用于查看该配置项，`uci changes system` 用于查看尚未提交的变动；记录前过滤身份相关字段。`uci commit` 用于把 UCI 暂存的修改写入配置，服务应用则是另一动作。读到某个值无法证明服务已采用它。
3. 查看对应服务及监听。根据目标镜像实际支持，查 `ps` 与 `ss -lnt` 或 `netstat -lnt`。记录监听地址和端口；只绑定回环地址的服务不应预期可从另一台机器直接连入。
4. 看最近的 `logread` 与 `dmesg`（权限和工具存在时），分别找服务错误和内核、驱动事件。保留时间、关键原始行及上下文。日志常位于有限的缓冲区；有需要先导出并脱敏，不以重启代替记录。

| 变更阶段 | 检查点 |
| --- | --- |
| 改前 | 有可重启后取回的备份，并记录现有配置、监听和日志 |
| 暂存与持久化 | 只核对目标节和字段，确认没有混入其它改动；配置语法成立仍不代表含义正确 |
| 应用 | `reload` 行为由具体服务实现，可能重启进程或中断连接；只有一条远程入口时先不要动它依赖的服务 |
| 回滚 | 恢复原配置并按服务要求重新应用，核对基线中的监听和日志；撤销暂存不等于恢复已经提交的配置 |

**产物：**填写 `软件版本 | 配置区段 | 进程 | 监听 | 近期日志 | 恢复入口`。遇到“服务不可用”时能指出你在哪一栏发现第一个异常，也能说清哪些栏还没有证据。
