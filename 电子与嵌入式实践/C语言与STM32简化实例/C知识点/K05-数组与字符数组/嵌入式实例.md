# K05 嵌入式实例

形式：**PC 可编译最小例**（已跑通，输出实测）+ **SPL 对照片段**（未上板，未验证）。

## 一、PC 侧：已验证

文件：[char-array-demo.c](char-array-demo.c)

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic char-array-demo.c -o char-array-demo.exe
```

实测输出（gcc 16.2.0，2026-10-01）：

```text
1) "hello" 占 6 字节（5 个字母 + 1 个 \0）
2) stressed 反转后 = desserts
3) "Liquid-crystal display" -> LCD
   "Thank George It's Friday!" -> TGIF
4) 复制了 5 个字节却没放 \0，直接打印会读到后面的内存
   正确做法：复制 n-1 个字节，再手动补 \0
   修正后：ABCD（长度 4，安全）
5) 在本函数里 sizeof(ok) = 5；传给函数后它退化成指针
```

这里用 `memcpy` 做固定长度复制，故意不留 `\0`，让错误保持可控且在 `-Wall -Wextra -Wpedantic` 下无额外警告。真实工程里，`strncpy` 在复制长度刚好等于目标容量时也有同样的风险：它不会自动补 `\0`，不同工具链的警告策略也不一致，不能把“编译器没警告”当成安全证明。

## 二、SPL 对照：把串口收到的字节攒成字符串

串口一个字节一个字节地收，攒到换行符就当成一条命令：

```c
#define CMD_MAX 64

static char cmd_buf[CMD_MAX];
static size_t cmd_len = 0;

void uart_on_byte(uint8_t byte)      /* 在接收中断或轮询里调用 */
{
    if (byte == '\n' || byte == '\r') {   /* 收到行尾 */
        cmd_buf[cmd_len] = '\0';          /* 关键一步：补结尾 */
        handle_command(cmd_buf);
        cmd_len = 0;
        return;
    }
    if (cmd_len + 1 < CMD_MAX) {          /* 留一个字节给 \0 */
        cmd_buf[cmd_len++] = (char)byte;
    }
    /* 否则丢弃：缓冲区满了，宁可丢也不能越界 */
}
```

（示意写法，未上板验证。）

三个关键点：

1. `cmd_len + 1 < CMD_MAX` 保证永远留得下 `\0`
2. 攒满就丢，而不是继续写——嵌入式里「丢一帧」比「越界改坏别的变量」后果轻得多
3. 补 `\0` 是在**当成字符串用之前**做的，不是每次收字节都补

## 三、解析命令：靠分隔符而不是切字符串

```c
if (strcmp(cmd_buf, "LED ON") == 0)  { LED_On(); }
else if (strcmp(cmd_buf, "LED OFF") == 0) { LED_Off(); }
```

注意 `strcmp` 而不是 `==`：

```c
if (cmd_buf == "LED ON")   /* 错！比较的是两个地址，永远不相等 */
```

这一条几乎每个学 C 的人都会踩一次。

## 四、与 K12 的关系

上面这个「攒字节」的做法只适合低频命令。串口连续收数据时，更常用的是**环形缓冲**（K12）：中断里往缓冲写，主循环里读，读写互不阻塞。K05 的字符数组是它的基础——先搞清 `\0` 与容量，再去看环形缓冲的绕回逻辑。
