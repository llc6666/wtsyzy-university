# STM32 最小系统：上电、复位、时钟与下载核对

## 这页解决什么问题

开发板“没有反应”时，先判断 MCU 是否具备运行条件，再判断代码和外设。最小系统的核对对象包括供电、复位、时钟、启动配置和下载接口。教程中的常见引脚、晶振和 LED 接法只能作为线索，不能替代当前板卡原理图。

## 1. 上电前做无电检查

断开 USB、调试器和外部电源后，完成下面的记录：

| 项目 | 要确认的内容 | 证据 |
| --- | --- | --- |
| MCU 身份 | 芯片丝印、完整型号、封装 | 清晰照片或板卡资料 |
| 电源 | 供电入口、电压范围、稳压路径和极性 | 原理图、万用表和板卡标注 |
| 电源回路 | VDD/VSS、模拟电源/地、去耦电容是否按资料连接 | 原理图页码与目视检查 |
| 复位 | NRST 的默认状态、复位按键和上拉/下拉路径 | 原理图与电平测量 |
| 时钟 | 是否有外部晶振、频率、负载电容和对应配置 | 晶振丝印、原理图、数据手册 |
| 下载 | SWDIO、SWCLK、GND、目标板电源和复位连接 | 接线表与下载器标识 |
| 启动 | BOOT 配置在 Flash、系统存储器还是 SRAM | 芯片手册和跳线位置 |

先确认没有明显短路、反接或把不同电压域直接相连，再上电。不要在不清楚电源路径时同时连接 USB、外部 5 V 和调试器供电。

## 2. 依次排查五条链路

### 供电链路

确认电源电压在芯片和板卡允许范围内，并检查 MCU 供电脚、地脚和模拟电源是否真正接入。电源指示灯亮只说明某段电路有电，不能证明 MCU 供电、地回路和去耦都正确。必要时记录空载和运行时电压，观察是否有明显跌落。

### 复位链路

`NRST` 被拉低时，MCU 处于复位状态。检查复位按键是否卡住、下载器是否持续控制复位，以及释放复位后电平是否回到允许运行的状态。复位后的第一条可见现象应能区分“程序没运行”和“程序运行但外设配置错误”。

### 时钟链路

第一次点灯可以先使用芯片和 HAL 支持的最小时钟配置，减少外部晶振和 PLL 变量。若启用 HSE/PLL，必须同时核对晶振实际存在、频率、启动状态和时钟树。串口波特率、定时器周期和 ADC 采样率都依赖时钟，时钟错了，后面的数值也会错。

### 启动链路

明确复位后从哪里取指令：用户 Flash、系统存储器或 SRAM。下载方式和 BOOT 配置要配套。烧录器把程序写入 Flash，不代表下一次复位一定从 Flash 启动；启动脚位置和电平必须以当前型号的参考手册为准。

### 下载链路

SWD 最小连接通常包含 SWDIO、SWCLK、GND 和目标板电源/参考电压，具体接口以调试器和板卡资料为准。下载失败时按顺序检查供电、共地、复位、芯片识别、SWD 线序和启动状态，不要先反复更换工程代码。

## 3. 串口模块的额外边界

USB 转 TTL 模块与 MCU 连接时，TX 接对方 RX，RX 接对方 TX，GND 共地。确认模块的 I/O 电平与 MCU 允许范围匹配；TTL/CMOS UART 与 RS-232 不是同一种电气接口，不能直接互接。串口不通时先测电平和接线，再查波特率与程序。

## 验收标准

- 能说清当前芯片、封装、供电和启动来源。
- 能在无电状态下复核主要电源、复位、时钟和下载连接。
- 能记录一次下载器识别、程序写入和复位后的实际现象。
- 任何具体 LED、串口或晶振引脚都有原理图、数据手册或测量证据。
