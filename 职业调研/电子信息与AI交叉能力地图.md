# 电子信息与 AI 交叉能力地图

这类岗位考察的是一条能交付的工程链，而不是工具名的数量：

> 设备或信号输入 → 数学/物理建模 → 基线算法或模型 → 指标评价 → C/C++/Python 实现 → 受约束平台部署 → 调试、优化与文档。

## 三条路线

### 信号与算法

信号与系统、DSP、通信和概率统计，连接 FFT、滤波、时频分析、阵列处理与 Python/Matlab 仿真，最终落在雷达、音频、ISP 或传感器任务的实时实现。

### 嵌入式与端侧 AI

C/C++、Linux、ARM 或 RTOS，连接小模型训练、ONNX 导出、量化、剪枝与推理引擎，再处理设备上的时延、内存、功耗和稳定性。

### 芯片软件与工具链

C/C++、Python、数字电路和计算机体系结构，连接 LLVM、MLIR、TVM 或 IREE，处理算子、编译、运行时、验证、调度和性能优化。

## 共同底座

- C/C++：内存、并发、性能与设备侧交付。
- Python：数据处理、仿真、训练、测试脚本和实验记录。
- Linux、Git、测试和文档：让结果可复查、可协作、可交付。
- 数学：微积分、线性代数、概率统计、优化与建模。
- 硬件认知：ARM/MCU、接口、DSP、FPGA 或 NPU 至少形成一项实际经验。

## 判断项目是否有价值

一个项目至少应说明输入是什么、基线如何建立、指标如何定义、失败发生在哪里、资源或时延受什么约束，以及代码如何复现。只展示“调用了模型”，不能证明这条工程链已经形成。
