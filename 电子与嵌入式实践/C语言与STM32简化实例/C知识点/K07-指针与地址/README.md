# K07 指针与地址

## 一句话结论

**指针保存地址，指针类型决定访问时的解释方式和指针运算步长。** 学习指针时要同时回答四个问题：地址指向哪个对象、一次访问多少字节、对象还能活多久、当前访问是否被限定符允许。

## 三件事必须分开

| 写法 | 含义 |
| --- | --- |
| `int *p` | `p` 是一个指针变量，它自己占一块内存，保存某个 `int` 对象的地址 |
| `&x` | 取对象 `x` 的地址 |
| `*p` | 按 `p` 保存的地址访问目标对象，称为解引用 |

声明里的 `*` 表示“这是一个指针类型”，表达式里的 `*` 表示“按地址访问对象”。读代码时先判断它处于声明还是表达式，再判断地址是否有效。

## 指针算术的步长

对指向数组元素的指针，`p + 1` 前进的元素数量是 1，前进的字节数由所指向类型的大小决定：

```text
int *       p + 1  -> 前进 sizeof(int) 个字节
uint8_t *   p + 1  -> 前进 sizeof(uint8_t) 个字节
```

指针加减应当围绕同一个数组对象或数组尾后位置进行。把一段内存改用另一种指针类型查看时，必须同时确认对齐、访问宽度、对象边界和目标平台规则。不能把“某个平台上 `sizeof(int) == 4`”写成所有环境都成立的结论。

## 数组、函数参数与地址

`arr[i]` 与 `*(arr + i)` 表达的是同一类访问关系。函数参数仍然按值传递；当参数是指针时，传入的是地址的副本，函数可以通过这个副本修改调用者仍然拥有的对象：

```c
void swap_int(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}
```

使用前要写清楚三件事：指针能否为空、它指向几个元素、函数是否会修改目标对象。数组参数通常还需要单独传入有效元素数量，不能在函数内部用 `sizeof` 反推出调用者数组容量。

## `const`、`volatile`、`void *` 与空指针

| 写法 | 主要限制或含义 | 调用前检查 |
| --- | --- | --- |
| `const int *p` | 不能通过 `p` 修改目标 `int`，`p` 本身可以改指向 | 目标是否允许只读访问 |
| `int *const p` | `p` 初始化后不能改指向，目标 `int` 可以通过 `p` 修改 | 指针是否必须固定 |
| `const int *const p` | 目标只读，指针也固定 | 两层限制是否符合接口 |
| `volatile uint32_t *p` | 每次通过该表达式访问都必须按 `volatile` 语义处理，适合描述可能被硬件或中断改变的对象 | 这不等于原子性、锁或线程同步 |
| `void *p` | 可保存对象地址，但解引用或指针运算前要转换为合适的对象指针 | 转换后的类型、对齐和对象边界 |
| `NULL` 或空指针值 | 表示“不指向对象”的指针状态 | 解引用前先检查；不要把它直接当成所有平台都相同的物理地址 |

`volatile` 只处理编译器对访问的可观察性，不能单独解决并发竞态、复合读改写或硬件寄存器的访问宽度要求。寄存器读写还要按芯片参考手册确认访问方式。

## 指针的生命周期

指针变量本身和它指向的对象是两个生命周期对象。常见情况如下：

| 对象来源 | 生命周期 | 典型风险 |
| --- | --- | --- |
| 函数内普通局部变量 | 进入代码块后创建，离开代码块后结束 | 把局部变量地址返回给调用者 |
| `static` 或全局对象 | 程序运行期间持续存在 | 暴露可变全局状态，接口责任不清 |
| `malloc` 等动态分配对象 | 分配成功后持续到 `free` | 忘记释放、重复释放、释放后继续使用 |
| 外设寄存器映射对象 | 由目标芯片地址空间和硬件定义 | 型号、基地址、偏移或访问宽度不匹配 |

对象生命周期结束后，原指针不会自动变成安全值。需要在释放或离开作用域后撤销继续使用该指针的路径，并在接口中说明所有权和释放责任。

## 结构体成员偏移与寄存器映射

结构体成员偏移可以帮助表达一组固定布局，但“结构体恰好对应寄存器块”必须由目标芯片参考手册、头文件定义和访问宽度共同支持。概念上的寄存器访问通常包含三步：

```c
/* 仅展示地址、类型和成员访问关系，不代表本轮已在开发板执行。 */
uintptr_t base = GPIOA_BASE;
volatile GPIO_TypeDef *gpio = (volatile GPIO_TypeDef *)base;
gpio->ODR = value;
```

阅读这类代码时按下面顺序核对：

1. 查目标芯片的内存映射，确认外设基地址属于当前型号。
2. 查参考手册的寄存器表，确认成员偏移、访问宽度、读写属性和保留位。
3. 查头文件结构体，确认成员排列与参考手册一致；`offsetof` 只能辅助检查，不能替代手册。
4. 确认外设时钟、复位、引脚复用和板卡连线等前置条件已经单独记录。
5. 把“代码能访问某个地址”“工程成功构建”“芯片产生预期电平”分别记录，不能合并成一个结论。

以 STM32F1 GPIO 为例，RM0008 给出了 GPIO 寄存器的访问方式和相对偏移；不同系列、封装或库版本不能直接套用这组布局。官方资料显示，GPIO 控制寄存器、输入输出数据寄存器和置位复位寄存器具有各自的偏移与访问规则，AFIO 还涉及外设时钟前置条件。使用时必须回到目标型号的官方参考手册核对。

## 函数指针：把操作也纳入接口检查

函数指针保存的是函数入口，类型则描述参数和返回值。先用 typedef 把签名写清楚，再把它当作回调或分发表使用：

~~~c
typedef int (*binary_op)(int, int);

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

binary_op ops[] = {add, sub};
int result = ops[0](7, 2);
~~~

阅读函数指针时按四步核对：

1. 参数个数、参数类型和返回类型是否完全匹配。
2. 指针是否可能为空，调用前是否有明确的未注册分支。
3. 回调需要的上下文由谁提供；C 中通常把结构体指针作为首参数显式传入。
4. 表下标是否在数组范围内，注册和调用是否使用同一套编号。

嵌入式里的命令分发、状态回调和中断入口都可能使用函数地址，但中断入口还受启动文件、链接脚本和工具链约定约束，不能只凭“函数名像”就断定它已经接入向量表。函数指针的具体大小、调用约定和可执行地址布局也以目标工具链为准。

## 实践检查卡

遇到一段指针代码，按以下顺序写下结论：

1. **目标对象**：指针保存的地址来自哪里，目标对象是什么类型。
2. **访问方式**：解引用一次访问多少字节，`p + n` 是否仍在同一个数组对象或尾后位置范围内。
3. **修改权限**：`const` 是否限制目标写入，`volatile` 是否只是硬件或异步变化的访问描述。
4. **生命周期**：目标对象何时创建、何时结束，谁负责释放或维持有效性。
5. **嵌入式前置条件**：型号、基地址、成员偏移、访问宽度、外设时钟和引脚配置是否都有来源。
6. **证据边界**：分别标记语言规则、源码阅读、工程构建、运行输出和硬件现象，缺少哪一层就保留哪一层的不确定性。
7. **回调契约**：如果出现函数指针，补齐签名、空值、上下文、注册表和索引边界。

## 易错清单

1. 返回局部变量地址：函数返回后，局部对象的生命周期已经结束。
2. 认为 `p + 1` 永远只前进 1 字节：步长取决于所指向类型。
3. 认为数组传入函数后仍保留完整容量：函数参数中的数组通常按指针处理，容量需要单独传递。
4. 混淆 `const int *` 与 `int *const`：一个限制目标写入，一个限制指针改指向。
5. 把 `volatile` 当作线程同步或原子操作：它不能替代锁、原子类型或硬件规定的访问序列。
6. `free` 后继续用那个指针：释放后必须阻断后续访问路径。
7. 只凭手算结构体偏移映射寄存器：必须与目标型号参考手册和访问宽度对照。
8. 把空指针当成物理地址 0：空指针是语言层面的无效对象指示，不能替代目标平台的地址约定。
