# 短路求值与空指针：先判 NULL 再碰 data

## 一句话结论

`a || b` 和 `a && b` 都**先算左边**，左边能决定结果就不再算右边。所以空指针检查必须写在解引用**之前**：`p == NULL || p->data` 安全，`p->data || p == NULL` 在 p 为空时直接崩溃。

## 它解决什么问题

新手写"空指针保护"时常把判断顺序写反，结果保护形同虚设：左边解引用 NULL 已经崩了，右边的 NULL 判断永远轮不到执行。理解短路求值，才能写出真正安全的判断。

## 工作机制

```cpp
// || 的短路：左边为真，右边不执行
p == NULL || p->data;   // p 为空：左边真 → 短路，右边不碰 → 安全
p->data || p == NULL;   // p 为空：左边先崩 → 右边永远轮不到 → 崩溃

// && 的短路：左边为假，右边不执行
p != NULL && p->data;   // p 为空：左边假 → 短路，右边不碰 → 安全
p->data && p != NULL;   // p 为空：左边先崩 → 崩溃
```

规律：**凡是"先检查后使用"，把检查放左边**。`||` 配 `== NULL`，`&&` 配 `!= NULL`。

## 最小示例

```cpp
// 错误：空栈时 h->data 直接崩
if (h->data == 0 || h == NULL) return false;

// 正确：先判空，再碰 data（甚至不需要碰 data）
if (h == NULL) return false;
return true;
// 更简：return h != NULL;
```

判断"栈/链表是否为空"只看头指针是不是 NULL，根本不需要访问 data。

## 常见错误与边界

1. **判断顺序反了**：`p->data || p == NULL`，空指针保护失效，崩溃。
2. **解引用赋值**：`l.h->data = 0;` 在 h 为 NULL 时等于对空房放东西，第一行就崩。空状态由 `h == NULL` 表示，不需要 data 标记。
3. **能编译不代表安全**：这类错误编译期不报，运行期才崩，必须靠测试（含空输入用例）暴露。
4. **空容器是合法的输入**：空栈、空链表、空字符串都要作为测试用例，不能假设"输入不会为空"。

## 使用规则

- 解引用任何指针前，问一句：它可能是 NULL 吗？
- 空容器的判断：只用指针和 NULL 比较，不碰成员。
- 短路判断里，检查放左边，使用放右边。
- 测试用例永远包含空输入。
