# 公开知识库的脱敏与发布检查

## 何时用

准备把个人笔记、课程资料、职业调研或项目成果推送到公开 Git 仓库前使用。公开后即使删除，提交历史、搜索缓存和他人克隆也可能保留副本，因此检查必须在提交前完成。

## 输入

- 待发布目录的完整文件列表。
- 来源清单与许可信息。
- 一个可回退的 Git 提交或本地备份。

## 步骤

### 1. 先做发布范围表

不要从私库整库复制。列出每个候选文件的用途、来源、敏感级别和处理结论。

| 文件 | 用途 | 证据/来源 | 风险 | 处理 |
| --- | --- | --- | --- | --- |
| 方法论模板 | 通用方法 | 自写 | 低 | 发布 |
| 学校通知截图 | 校内规则 | 内部材料 | 高 | 不发布 |
| 岗位公开快照 | 公开招聘页 | URL + 获取日期 | 中 | 保留链接和日期 |

### 2. 删除或替换四类内容

- 个人身份与联系方式：姓名、学号、邮箱、手机号、地址、账号、令牌、设备路径中可识别个人的部分。
- 内部信息：校内通知、未公开会议记录、课程群内容、内部系统截图、他人的个人信息。
- 无权再发布的第三方内容：整篇文章、教材扫描件、付费资料、未经许可的图片或代码。
- 不可核验的具体主张：没有来源的薪资、政策、录取、效果承诺。保留时改成个人观察并降低结论力度。

### 3. 做文本扫描，再做人审

在仓库根目录可用 `rg` 搜索常见风险。命中不一定违规，但每个命中都要人工判断。

```powershell
rg -n -i "(password|token|secret|api[_-]?key|身份证|学号|手机号|邮箱|微信|qq|地址)" .
rg -n "[0-9]{11}|[0-9]{17}[0-9Xx]" .
```

再逐一打开图片、PDF、表格和隐藏目录。纯文本扫描无法发现截图中的姓名、二维码或水印。

### 4. 处理来源与许可

自己的文字可以发布，但引用要保留原链接和获取日期。引用第三方时以摘要、观点和链接为主，不复制大段原文。文件中标注许可；不确定时先不发。

### 5. 提交前用干净环境复查

从仓库根 README 出发，检查链接、图片、许可证和公开边界说明。用另一台设备或无登录浏览器打开远程仓库，确认页面没有依赖本地路径。

## 交付物

- 发布范围表。
- 文本扫描记录与人工图片检查记录。
- 公开边界说明、来源链接和许可证。

## 验收

- 每个发布文件都有“发布、脱敏后发布或不发布”的结论。
- 未发现个人账号、令牌、联系方式、内部资料和未授权原文。
- 所有公开链接在未登录环境可打开，或标为失效。
- 推送前的 `git diff --cached` 已逐项审查。

## 常见失败与修正

- 以为仓库私有就可以先上传：私有仓库也会共享、备份和误设公开，敏感资料不要入 Git。
- 只删正文忘了提交历史：发现敏感信息后先停止推送，再按 Git 历史清理流程处理；普通删除不一定足够。
- 用“公开可搜到”判断可转载：可访问不等于获授权，优先链接和摘要。
- 只扫描 Markdown：图片、附件、文档属性和文件名同样需要检查。
