# 低成本验证机会选择

## 何时用

面对竞赛、社团、开源项目、实习准备或新技能方向，无法判断是否值得长期投入时使用。先做一个 7 至 14 天、可退出的试验，再决定要不要加码。

## 输入

- 一个候选机会。
- 当前目标和每周可投入时间。
- 机会的官方规则或任务说明。

## 步骤

### 1. 建候选卡，先排硬风险

| 字段 | 要填内容 |
| --- | --- |
| 目标关联 | 它服务的具体目标 |
| 真实任务 | 你本人要交付什么 |
| 试验窗口 | 开始、结束与最多投入小时 |
| 外部反馈 | 谁在何时如何检查 |
| 最小产物 | 到期能留下什么 |
| 停止条件 | 哪种情况立即退出 |

若没有具体任务、规则来源或可退出点，先不加入候选。职位名称、名气和别人推荐只能帮助发现机会。

### 2. 设计最小试验

试验应只验证一个不确定点。例如，怀疑自己能否接受数据清洗工作，就用一份公开数据在 10 小时内完成清洗、说明和一个可复现分析，而不是直接承诺半年项目。

最小试验需要同时满足：投入上限已写明、产物可检查、能获得外部反馈、结束后可以停止。

### 3. 到期做继续判断

| 结果 | 判断 | 下一步 |
| --- | --- | --- |
| 完成产物且反馈有效 | 有继续证据 | 增加一个周期，但重新定范围 |
| 完成产物但不喜欢任务本身 | 匹配度低 | 保留成果，停止或换方向 |
| 无法获得真实任务/反馈 | 机会信息不足 | 停止投入，补来源后再评估 |
| 成本超上限 | 设计失控 | 缩范围或退出 |

### 4. 保存证据

保留任务说明、版本记录、反馈和 10 行复盘。报名截图、群聊头衔和参与证明不能替代实际产物。

## 交付物

- 一张候选卡。
- 一个有时长上限的最小试验。
- 试验产物、反馈与继续/停止结论。

## 验收

- 试验不超过预设小时数，或超限原因已记录。
- 你能展示个人承担的真实任务。
- 有至少一条外部反馈、测试结果或可复现产物。
- 到结束日做出了继续、缩小或停止的明确判断。

## 常见失败与修正

- 把报名当验证：报名后 3 天内必须交付一个最小任务。
- 并行试太多：同一周期最多两个试验，避免反馈质量下降。
- 没有停止条件：开始前写“超过 X 小时且无任务/反馈则退出”。
- 团队项目只做杂务：入组前确认自己拥有的可交付模块。
