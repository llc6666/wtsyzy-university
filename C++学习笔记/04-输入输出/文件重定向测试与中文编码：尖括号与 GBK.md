# 文件重定向测试与中文编码：< > 与 GBK

## 一句话结论

用 `cmd /c "程序.exe < 输入.txt > 输出.txt"` 可以不改代码完成文件输入输出：`<` 把文件接到程序输入，`>` 把输出写进文件。期望输出文件里的中文必须用 GBK（或 UTF-8）保存，ASCII 编码会把中文写成 `??`，对比必失败。

## 它解决什么问题

手动在控制台输入测试数据既慢又易错。文件重定向让程序从文件读输入、把输出写进文件，配合脚本自动对比期望值，就是最朴素的自动化测试。中文期望值的编码不一致是新手最容易踩的坑。

## 工作机制

```powershell
# 输入重定向：程序从文件读（相当于手动输入）
cmd /c "program.exe < in.txt"

# 输出重定向：程序输出写进文件
cmd /c "program.exe < in.txt > out.txt"
```

代码里的 `cin` / `cout` 一行不用改，重定向自动接管。注意 PowerShell 本身不支持 `<`，必须经 `cmd /c` 包一层。

编码问题：中文字符在 ASCII 里不存在，写入时被替换成 `?`。所以：

| 内容 | 编码 |
| --- | --- |
| 纯数字/英文 | ASCII 即可 |
| 中文（合法、不合法等） | GBK（Windows 中文环境）或 UTF-8 |

期望文件和程序输出**必须同编码**，对比才一致。

## 最小示例

```powershell
# 测试脚本片段：跑一组，对比输出
cmd /c "`"$exe`" < `"$in`" > `"$out`""
$got  = ([System.IO.File]::ReadAllText($out, $gbk)).Trim()
$want = ([System.IO.File]::ReadAllText($exp, $gbk)).Trim()
if ($got -eq $want) { "通过" } else { "失败" }
```

## 常见错误与边界

1. **ASCII 写中文**：`WriteAllText($f, "合法", ASCII)` 得到 `??`，对比必失败。
2. **读写编码不一致**：程序输出 GBK，期望文件 UTF-8，内容一样也对比不上。
3. **PowerShell 直接用 `<`**：PowerShell 不支持输入重定向操作符，报错；必须 `cmd /c`。
4. **Trim 空白**：程序输出的结尾换行会影响对比，对比前 `.Trim()` 掉两端空白。
5. **文件路径含空格**：`cmd /c` 里路径要加双引号。

## 使用规则

- 测试用重定向：`cmd /c "exe < in.txt > out.txt"`。
- 中文期望文件用 GBK 保存，读取对比也用 GBK。
- 对比前 Trim 空白。
- 测试用例覆盖边界：0、1、最大值、空输入、不存在项。
