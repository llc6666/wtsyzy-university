# STM32 Flash 与 Arm：存储器、处理器与地址边界

## 适用场景与准备

看到“Arm、Cortex-M3、STM32、Flash、SRAM、MDK-ARM”混在一张图或工程配置中时，用这页先确定它们各自负责什么，再核对容量和地址。完成后留下文末的资源与证据卡，不凭开发板商品标题修改工程容量。

准备三类资料：

1. 芯片完整型号和封装，例如 `STM32F103C8T6`；不要只写“STM32”或“F103”。
2. 对应该型号的数据手册、参考手册与适用勘误。本文容量示例使用 ST 的 DS5319 Rev 20（2025-07）。
3. 当前工程的目标器件、内存配置、链接脚本或 scatter 文件；如果已有 map 文件，记录它对应的工程版本。没有这些文件时只填资料层，不补写工程结论。

本页是术语、资料阅读与配置核对方法，不提供擦写 Flash 的代码或操作流程。来源未提供运行验证记录；本轮仅整理，未执行测试。

## 1. 先把名词放回各自层级

| 名词 | 它回答的问题 | 本页中的具体含义 |
| --- | --- | --- |
| Arm 架构 | 处理器遵循什么指令与程序员模型？ | 架构规范；Cortex-M3 对应 Armv7-M |
| Cortex-M3 | 哪种处理器执行指令？ | Arm 的处理器 IP，包含内核及相关接口等；芯片厂商把它集成到产品中 |
| STM32F103C8T6 | 正在使用哪颗 MCU？ | ST 的具体微控制器型号，集成 Cortex-M3、片上存储器和外设 |
| Flash | 程序和需断电保留的内容放在哪里？ | 非易失性存储器；常见 F103 工程把固件和部分只读内容放在主 Flash |
| SRAM | 运行时变化的数据放在哪里？ | 易失性存储器，通常承载可写数据、栈、堆和缓冲区 |
| MDK-ARM | 用哪套开发环境处理工程？ | 开发工具套件；其中的编译器、链接器与下载工具承担不同步骤 |

“Arm”还可能指公司或品牌，阅读时先看上下文。架构、处理器 IP、芯片产品、存储器和开发工具属于不同层级，不能用其中一个推断另一个的全部规格。[Arm Cortex-M3 官方资料](https://www.arm.com/-/media/Arm%20Developer%20Community/PDF/Processor%20Datasheets/Arm%20Cortex-M3%20Processor%20Datasheet.pdf)与 [ST 数据手册](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)分别说明处理器和具体芯片的组成。

可以把 Flash 类比为保存程序的书架，Cortex-M3 是按指令工作的执行者，SRAM 是工作台，STM32 是把这些部件连在一起的系统。这个类比只帮助区分职责，不能用来推导访问速度、总线结构或物理位置。

## 2. 从完整型号查容量，再查地址

按下面的顺序填卡，查不到就保留“待查”：

1. 在数据手册的适用器件和订购编码中找到完整型号，确认容量标记。
2. 在器件特性或资源表中分别抄下 Flash 和 SRAM 容量，并记章节或表名。
3. 在 Memory mapping 一节查各存储区起始地址；不要把图上给整个系列预留的区域都当成本型号已实现容量。
4. 用“起始地址 + 实现容量”得到末尾的尾后地址；写成半开区间，明确尾后地址不能当成该区的有效字节。
5. 再与工程 IROM/IRAM 或链接配置比较。不同工具的界面名称会变化，应找实际起始地址和长度字段。

以 `STM32F103C8T6` 的资料值为例：

| 区域 | 本型号容量 | 本区域起点 | 按容量写出的半开区间 |
| --- | --- | --- | --- |
| 主 Flash | 64 Kbytes | `0x08000000` | `[0x08000000, 0x08010000)` |
| SRAM | 20 Kbytes | `0x20000000` | `[0x20000000, 0x20005000)` |

这里按 1 Kbyte = 1024 bytes 换算；区间末端是由资料容量相加得到的地址边界示例。数值依据 [DS5319 的 Memories、Memory mapping 与 Ordering information scheme](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)。它们说明该型号的资源，不代表当前工程已经占用这些空间，也不代表表中任一地址都可以随意读写。

### 三个容易误读的地方

- 数据手册同时覆盖 x8 和 xB：看到“64 or 128 Kbytes”后，还要按型号编码选择；不能给 C8 工程直接套用 CB 的容量。
- `0x00000000` 附近的启动映射可能是已有存储区的别名。别名使同一内容可从另一地址访问，不会凭空增加 Flash 或 SRAM；具体启动映射按当前器件手册确认。
- 32 位处理器可以描述较大的地址空间，芯片只实现其中一部分。地址空间、片上实际容量和工程已用空间是三张不同的表。

工程设置里把 Flash 长度改大，只会改变工具允许安排的地址范围，不会增加芯片的物理存储器。发现容量不一致时先核对型号、配置与保留区，不靠“编译器没报错”放行。

## 3. 对照固件从电脑到芯片的四个阶段

| 阶段 | 应查看什么 | 能说明什么 | 还不能说明什么 |
| --- | --- | --- | --- |
| 编译与链接 | 对应版本的构建日志、AXF/ELF、map 或链接配置 | 工具处理了哪些输入，如何安排代码和数据 | 芯片里的内容已更新 |
| 生成下载文件 | HEX/BIN 等文件的版本、生成时间与来源 | 得到了准备交给下载工具的产物 | 该文件已写进目标器件 |
| 写入与校验 | 下载工具记录、目标型号、写入范围和校验结果 | 记录所覆盖的内容已写入/校验 | 复位后的启动配置和功能必然正确 |
| 启动与运行 | 启动配置及具体版本的运行记录 | 在已记录条件下发生了什么 | 所有路径或其他板卡也正确 |

这是读者以后整理已有证据的表，本轮没有代执行其中任一步骤。下载工具有时可直接接受 AXF/ELF；不要求所有流程都必须先转成 HEX/BIN。

常见“从主 Flash 启动”的 F103 工程中，链接器安排代码与只读内容的装载位置；复位后的启动代码和运行库负责建立运行环境。带初值的可写数据通常在 Flash 中保存初值，运行前复制到 SRAM；零初始化数据通常由启动流程清零。具体段名和实现以当前工具链为准，不能只看变量声明猜最终地址。

启动配置还要单独记录：F103x8/xB 的资料列有主 Flash、系统存储器和 SRAM 启动选项。程序写进主 Flash 与复位后选择从哪里启动是两个检查项，相关连接排查见[最小系统页](STM32最小系统：上电、复位、时钟与下载核对.md)。

## 4. 只读核对当前工程的存储安排

不改配置、不重建工程，也能先完成资料与已有文件的对应：

1. 记下当前 Target 与器件型号；多个 Target 分开记录。
2. 找到代码/只读区、可写数据区的起始地址和长度。使用 scatter 文件或链接脚本时，继续查看实际脚本，不能只抄 IDE 面板。
3. 记录是否存在 bootloader、保留参数区、特殊段或运行地址重定位。有保留区时，不能把整块物理 Flash 都填给应用程序。
4. 如果已有 map 文件，先核对它与哪次构建对应，再找 Code/RO、RW、ZI 或工具链对应段，以及符号地址。
5. 分别记录“装载到哪里”和“运行时在哪里”。同一可写对象可能在 Flash 中有初值副本，在 SRAM 中有运行副本。
6. 找不到对应版本的 map 时写“只有配置，尚无匹配的链接结果记录”，不要拿旧文件补结论。

理解 C 对象时保留两个边界：

- `const` 约束通过相应类型访问对象时的修改行为；它不单独决定对象必须放进 Flash。
- 字符串字面量在常见嵌入式配置中可能放入只读区，但其最终位置仍要看工具链与链接结果；字符串内容比较、指针地址比较与存储位置也应分开判断。

这一节用于把原笔记中的语言概念转成文件阅读顺序。它不保证优化后每个源代码变量都保留可单独定位的存储位置，也不把仅有配置写成实际运行结果。

```text
SRAM：起点 / 容量 / 尾后地址：
当前 Target 与工程版本：
实际使用的链接配置：
代码与只读内容：装载地址 / 运行地址：
可写初始化数据：初值装载位置 / 运行位置：
零初始化数据、栈、堆与缓冲区：
bootloader / 参数区 / 其他保留范围：
已有 map 对应的构建记录：有 / 无 / 无法对应
已有下载与校验记录：有 / 无 / 覆盖范围
已有启动与运行记录：有 / 无 / 条件
不一致项、缺失资料与下一步：
```

读者自查时，只检查这张卡是否满足以下条件：

- 每个容量和地址能回到具体型号、资料版本及章节。
- 能把架构、处理器、MCU、存储器和工具分别说明。
- 能解释物理容量、启动别名和工程可用范围为何不同。
- 能区分装载位置和运行位置，不把“有初值”理解成“一定只占 SRAM”。
- 缺少 map、下载或运行记录时明确留空，不写“已烧录”或“已验证”。

如果芯片换成其他 STM32 系列，或者工程有外部存储器、bootloader、多核或缓存，本页的 F103 容量和地址示例停止套用，重新查该器件的资料。
