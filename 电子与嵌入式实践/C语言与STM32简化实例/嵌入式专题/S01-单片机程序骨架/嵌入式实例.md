# S01 嵌入式实例

## 一、PC 侧：已验证

文件：[mcu-skeleton-demo.c](mcu-skeleton-demo.c)，输出见 [README](README.md)。

它验证的是**程序结构的逻辑**：初始化一次、主循环不断巡检、中断只置标志、主循环先清后处理。这些逻辑与硬件无关，先在 PC 上跑通，上板时只需替换「真实中断源」和「真实标志」。

## 二、SPL 对照：最小工程长什么样

```c
/* 全局：中断与主循环共享 */
volatile uint8_t g_timer_flag = 0;

/* 中断服务函数：名字由启动文件里的向量表决定，写错就不进中断 */
void TIM2_IRQHandler(void)
{
    if (TIM_GetITStatus(TIM2, TIM_IT_Update) != RESET) {
        g_timer_flag = 1;
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);   /* 必须手动清 */
    }
}

int main(void)
{
    SystemInit();          /* 时钟配置（标准库工程里通常已调用） */
    LED_Init();
    Timer2_Init();

    while (1) {
        if (g_timer_flag) {
            g_timer_flag = 0;
            LED_Turn();
        }
        /* 没有事件时可以 __WFI() 进入休眠 */
    }
}
```

（示意写法，未上板验证；函数名以标准库头文件为准。）

四个容易忽略的点：

1. **中断函数名不能自己起**：它必须与启动文件向量表里的名字一致（`TIM2_IRQHandler`、`USART1_IRQHandler`、`EXTI0_IRQHandler`）。写错了不会报错，只是永远不进中断——这是新手最常卡住的地方
2. **中断标志要手动清**：SPL 不会自动清。不清会反复进入中断，表现为程序卡死或主循环几乎不执行
3. **外设时钟要使能**：`RCC_APB1PeriphClockCmd(...)` 忘了开，外设就是「配置写了但没反应」
4. **`SystemInit()` 与时钟树**：默认时钟频率决定了延时、波特率、PWM 频率的实际数值

## 三、排错清单：程序「没反应」时按这个顺序查

| 现象 | 先查什么 |
| --- | --- |
| 完全没反应 | 供电与下载；`main` 有没有跑到（点个 LED 试试） |
| LED 不亮 | 时钟使能 → 引脚配置 → 输出电平 → 硬件接线（限流电阻、共阴共阳） |
| 中断不进 | 函数名对不对 → NVIC 有没有配置 → 中断标志有没有清 → 优先级分组 |
| 进了中断但只进一次 | 忘了清中断标志 |
| 时序不对 | 系统时钟频率是不是以为的那个值 |
| 加了打印正常、去掉就坏 | K10 的优化问题，或时序被打印改变 |

## 四、把本专题带回 PC 的做法

**在 PC 上把「主循环 + 中断标志」这套结构先跑一遍**，特别是下面三种情况：

1. 处理期间又来一次中断（标志会不会被覆盖、会不会漏）
2. 两个中断同时来（处理顺序是否符合预期）
3. 主循环处理时间比中断周期还长（会积压成什么样）

这三种情况在板子上很难复现和观察，在 PC 上加几行打印就能看清楚。
