# 验证、验收与错误处理

## 何时用

Agent 声称“已完成”、要修改源文件、准备提交或推送、形成研究结论时使用。Agent 的自然语言解释只能说明它认为做了什么，不能单独证明结果正确。

## 输入

- 任务的验收标准。
- 变更后的产物。
- 可独立执行的检查方式。

## 步骤

### 1. 先定义完成证据

| 任务类型 | 最低完成证据 | 常用独立检查 |
| --- | --- | --- |
| 文档整理 | 文件存在、目录与链接正确 | 链接解析、人工按步骤试做 |
| 代码修改 | 预期行为与边界行为通过 | 编译、单测、最小运行样例 |
| 数据处理 | 行数、字段、时间范围可追溯 | 源到输出对账、抽样复算 |
| 调研报告 | 结论有来源、日期、边界 | 打开原链接、交叉来源核验 |
| 公开发布 | 内容完整且无敏感信息 | diff 审阅、隐私扫描、未登录打开 |

验收必须尽量独立于生成过程。例如，不能只让 Agent 自己说“代码正确”；至少要让编译器、测试、数据对账或人工任务演练给出第二种证据。

### 2. 用三层检查

- **结构检查**：文件是否存在、格式是否可解析、链接是否可达、字段是否齐全。
- **行为检查**：代码是否运行、表格公式是否计算、流程能否按步骤完成。
- **边界检查**：空输入、错误输入、旧版本、权限不足、重复运行和隐私扫描如何表现。

### 3. 为失败建立记录

```markdown
## 验证记录
| 检查 | 预期 | 实际 | 证据 | 结论 |
| --- | --- | --- | --- | --- |

## 失败处理
- 失败位置：
- 已排除的原因：
- 当前证据：
- 下一步最小实验：
- 是否需要人工判断：
```

失败记录要保留。删掉失败尝试会让下一个 Agent 重复同样的错误，也让人误判系统可靠性。

### 4. 按风险决定停止还是修复

- L0/L1 失败：可在原范围内修复一次，再运行相同检查。
- L2 失败：停止写入，展示差异和失败原因，等待确认。
- L3 失败或不确定：不重试外部动作，先确认对象、权限和幂等性。

### 5. 做交叉核验

关键结论应至少满足两种不同证据：例如官方规则加原始数据、单元测试加人工样例、自动链接检查加随机点击。来源越单一，结论越应保守。

## 交付物

- 一张验收表。
- 结构、行为、边界三类检查结果。
- 失败记录或“无失败项”的检查证据。

## 验收

- 每个验收结论附有命令、链接、截图说明、哈希或可复现步骤。
- 已知边界条件至少测试一个。
- 验收失败时，最终状态写“未完成”或“部分完成”，不写成成功。
- 高风险任务存在独立于 Agent 自述的第二种证据。

## 常见失败与修正

- 只跑正向样例：补空输入、错误路径、重复运行和权限不足样例。
- 用“无报错”代表正确：增加输出对账与业务预期。
- 测试通过但源数据不可信：回到来源卡和采集日期。
- 修复后忘记重跑：验证记录必须包含最后一次执行时间与版本。
