原文说明：指针本质上就是一种内存地址，地址的位数与整数一致，所以把整数强转成指针就能表示某个特定地址。

STM32 的标准库头文件做的正是这件事，只是加了 `volatile` 和解引用，让「地址」直接变成「可以读写的变量」（SPL 对照见 [嵌入式实例.md](嵌入式实例.md)）。

原文紧接着给了一个「查看内存单元」的程序，并提醒：保护模式下程序只能访问分配给它的内存，访问别的地址会**崩溃**。

这句话值得记住：在 PC 上乱转地址会段错误；在 MCU 上乱转地址不会崩，而是**静默地读到一个不确定的值或改动一个你不该动的寄存器**。所以嵌入式里转地址的合法性要靠数据手册确认，不能靠「跑起来没报错」。

## 三、exercism `linked_list.h`：一份写清楚所有权契约的接口

来源：`exercism-c/c-main/exercises/practice/linked-list/linked_list.h`（MIT）

（原示例代码未随公开版复制；此处保留分析结论。）

逐条看这份接口的**约定**：

| 函数 | 约定 |
| --- | --- |
| `list_create` | 返回指向新链表的指针 —— 堆上的对象由函数创建，调用方持有 |
| `list_count` | 参数是 `const struct list *`：**只读，不改链表**，这是给调用方的承诺 |
| `list_push/pop` | 参数非 const：会改链表内容 |
| `list_destroy` | 释放全部节点；头文件注释明确写了「调用后 `list` 变成悬空指针」 |

最后那条注释是关键：C 的接口靠**注释约定**表达所有权，编译器不管。谁申请、谁释放、释放后指针还能不能用，全靠文档说清楚。这正是 K09「动态内存与所有权」要系统处理的问题。

对比 K01 的 `two-fer`：`void two_fer(char *buffer, const char *name)` 是另一种约定——**调用方提供空间**，函数只往里写，不涉及分配与释放。C 里这两种约定都很常见，看到接口先分清是哪一种。

## 四、`circular_buffer.h` 是空的

`circular-buffer/circular_buffer.h` 只有一个空的 include guard，接口要自己设计。

这道题值得单独重视：环形缓冲是**串口收发最常用**的结构，K12 会正式做它。设计时要想清楚三件事：容量怎么定、满和空怎么区分（`head == tail` 时是满还是空）、写满后是覆盖还是报错。

## 读码小结

1. 看接口先看 `const`：它标出了「这个函数会不会改你的数据」
2. 看返回指针的函数先问：这块内存是谁的、什么时候失效
3. 把整数转成指针在 PC 上会崩，在 MCU 上不崩但更危险
