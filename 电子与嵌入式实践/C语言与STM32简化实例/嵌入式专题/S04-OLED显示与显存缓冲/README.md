# S04 OLED 显示与显存缓冲

## 一句话结论

**OLED 编程的标准结构是：所有绘制只改显存数组（快、可反复改），刷新时整页连发字节（慢、按页列寻址）。** 改一个像素也要重发整页数据，所以动画先在显存里攒完一帧、只刷一次。


爱心故意放在 y=1：**一个 8x8 图形跨了两页，代码不用做任何特殊处理**——`gram[y>>3][x]` 自动落进两个页。这就是显存数组的价值。

对图形本身 XOR 一遍（闪烁的原理）：

```text

```

只改 1 个像素再刷新：

```text
只改 1 个像素，仍发送：命令 6 字节，数据 64 字节
-> 所以动画的标准做法：先在显存里把整帧画完，再 update 一次。
```

## 一、显存为什么是 `[页][列]` 不是 `[行][列]`

SSD1306 的显存按**页**组织：每页 8 行，一个字节是一列的 8 个点，**最低位是最上面那行**。于是：

```c
oled_gram[y >> 3][x]          /* 页 = y / 8 */
mask = 1u << (y & 7);         /* 页内行 = y % 8 */
```

画点、擦点、翻转全部由这一对运算定位。控制器收数据时，`0xB0|页` 定页、`0x10|列高4位`、`列低4位` 定列，然后**整页 128 字节连发**，控制器自动列 +1。

人脑按行想图形，硬件按列收字节——**字模就是把行视角转成列视角**。

## 二、字模：从行位图到列字节

demo 里爱心按行写成 `0x66, 0xFF, 0xFF, 0xFF, 0x7E, 0x3C, 0x18, 0x00`（直接对着形状读，`0x66` = 顶行两个圆弧）。`bitmap_to_columns` 做双重循环位搬运把它转成控制器要的列格式。**转换本身就是一次 K03 位运算练习**；真实工程的 `OLED_Font.h` 存的是转换结果（`F8x16[][16]`，前 8 字节上半页、后 8 字节下半页）。

## 三、三种颜色就是三种位运算

```c
gram[page][x] |= mask;              /* 亮 */
gram[page][x] &= (uint8_t)~mask;   /* 灭 */
gram[page][x] ^= mask;             /* 翻转（闪烁） */
```

| 颜色 | 运算 | 语义 |
| --- | --- | --- |
| WHITE | `\|=` | 置位，不影响其他像素 |
| BLACK | `&= ~` | 清位，不影响其他像素 |
| XOR | `^=` | 同一位置两次调用回到原样 |

## 四、改一个像素也要整页重发

I2C 上没有「只改一个字节」的便宜通道时（课程式驱动整屏连发），单像素修改与整帧重画**发送字节数一样**。所以工程里有两个配套开关：攒帧（`SetAutoUpdate(0)`，画完整帧再 `Update()` 一次）与越界丢弃（画点函数入口判 `x/y` 范围，出界直接 return，不崩溃）。
