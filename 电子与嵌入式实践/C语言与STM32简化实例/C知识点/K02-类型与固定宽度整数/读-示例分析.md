# K02 读：两份官方参考解里的类型选择

## 一、`grains`：为什么必然是 64 位

来源：`99-素材库/exercism-c/K02-类型与固定宽度整数/grains_参考解.c`（exercism/c，MIT）

（原示例代码未随公开版复制；此处保留分析结论。）

逐条看它的选择：

| 写法 | 为什么 |
| --- | --- |
| 返回 `uint64_t` | 第 64 格是 2⁶³，`uint32_t` 装不下，`int` 更装不下 |
| 参数 `uint8_t index` | 取值只有 1–64，用 8 位足够，且**无符号**避免了负数判断 |
| `if ((!index) || (index > 64)) return 0;` | 边界检查：0 和超过 64 都返回 0（题目约定的失败值） |
| `(uint64_t)1 << (index - 1)` | 移位前先把 1 转成 64 位，否则 `1` 是 `int`，移到 32 位以上就溢出 |

最后一条是关键中的关键：**移位前先定宽度**。写 `1 << 63` 是未定义行为，写 `(uint64_t)1 << 63` 才是正确的。这与 K03 的 `1u << n` 是同一条规则，只是这里需要 64 位。

`total()` 的做法是循环累加 64 次，结果正好是 2⁶⁴ − 1 = `18446744073709551615`，即 `uint64_t` 能表示的最大值——题目的数据就是照着这个类型的边界设计的。

## 二、`gigasecond`：一个典型的 C 接口契约

来源：`99-素材库/exercism-c/K02-类型与固定宽度整数/gigasecond_参考解.c`

（原示例代码未随公开版复制；此处保留分析结论。）

三点值得学：

1. **不返回字符串，而是写进调用方的缓冲区**，并且额外收一个 `size` 参数表示缓冲区大小——这是 C 里防越界的标准做法，和 K01 的 `two_fer` 是同一类契约，只是多了一个长度
2. `time_t` 的宽度由平台决定，参考解没有假设它是 32 位——这正是「不要猜类型宽度」的示范
3. 十亿这个常量写成 `1000000000`，它接近 `int` 上限（2147483647）的一半；如果再乘 3 就会溢出，所以涉及大常量时要先想清楚类型

## 三、CrashCourse《05-基本类型》

来源：`99-素材库/hairrrrr-C-CrashCourse/K02-类型与固定宽度整数/05-基本类型.md`（本地未发现 LICENSE，本批按特批入库，许可状态不变）

这一章讲 `int`、`short`、`long`、`float`、`double`、字符类型与类型转换。读的时候抓两点：

- 标准只规定**最小宽度**（如 `int` 至少 16 位），不规定确切宽度
- 无符号与有符号混用时的转换规则，是本知识点四个坑的来源

本库的处理：教程用来理解规则，`stdint.h` 用来写代码。两者不是替代关系——规则解释了为什么需要 `stdint.h`。

## 读码小结

1. 看到移位，先看左边那个 1 是什么类型
2. 看到返回字符串的接口，先看是「返回指针」还是「写入调用方缓冲 + size」
3. 大常量先估算上界，再决定类型
