# 前缀和与差分：一对互逆的区间运算

## 一句话结论

- 数组不变、需要多次查询区间和：先建前缀和，每次查询 O(1)。
- 需要多次做区间加、最后统一读取结果：先建差分，每次操作只改左右两个边界，最后做一次前缀和还原。

前缀和与差分互为逆运算。写代码前先标记当前数组是原数组 a、前缀和 s 还是差分 d，否则最容易出现下标错位。

## 前缀和：把区间查询换成两次相减

采用 1-based 下标，定义：

`text
s[0] = 0
s[i] = s[i - 1] + a[i]
`

则区间 [l, r] 的和为：

`text
s[r] - s[l - 1]
`

s[r] 包含前 r 个数，减去 s[l-1] 后，区间左侧的部分被抵消。预处理 O(n)，每次查询 O(1)，总复杂度 O(n+q)。

### 前缀和最小示例

`cpp
#include <cstdio>

int main() {
    int n = 0;
    int q = 0;
    std::scanf("%d%d", &n, &q);

    static long long s[200005]{};      // s[i] 保存 a[1..i] 的和
    for (int i = 1; i <= n; ++i) {
        long long x = 0;
        std::scanf("%lld", &x);
        s[i] = s[i - 1] + x;           // 读入时直接完成递推
    }

    while (q-- > 0) {
        int l = 0;
        int r = 0;
        std::scanf("%d%d", &l, &r);
        std::printf("%lld\n", s[r] - s[l - 1]); // 两个前缀相减
    }
}
`

## 差分：把区间加换成两个边界修改

定义 d[i] = a[i] - a[i-1]，并约定 a[0] = 0。对 [l, r] 中每个元素加 v 时：

`text
d[l]   += v
d[r+1] -= v
`

原因是区间内部相邻元素同时增加 v，差值不变；只有左端点开始多出一个 v，右端点之后需要减回一个 v。所有操作完成后，对 d 做一次前缀和，就能还原修改后的 a。预处理 O(n)，每次区间加 O(1)，最后还原 O(n)。

### 差分最小示例

`cpp
#include <cstdio>

int main() {
    int n = 0;
    int m = 0;
    std::scanf("%d%d", &n, &m);

    static long long d[200005]{};      // n+2：右端点可能写到 d[n+1]
    long long previous = 0;
    for (int i = 1; i <= n; ++i) {
        long long x = 0;
        std::scanf("%lld", &x);
        d[i] = x - previous;           // 根据相邻元素建立差分
        previous = x;
    }

    while (m-- > 0) {
        int l = 0;
        int r = 0;
        long long v = 0;
        std::scanf("%d%d%lld", &l, &r, &v);
        d[l] += v;                     // 从 l 开始增加 v
        d[r + 1] -= v;                 // r 之后恢复原来的增量
    }

    long long current = 0;
    for (int i = 1; i <= n; ++i) {
        current += d[i];               // 前缀和还原修改后的 a[i]
        std::printf("%lld%c", current, i == n ? '\n' : ' ');
    }
}
`

## 最容易错的边界

### 1. d[r+1] 需要额外空间

当 r=n 时，右边界修改会写入 d[n+1]。这个位置不需要被最终输出，但必须有合法存储，所以数组至少按 n+2 规划。

### 2. 下标约定不要混用

0-based 和 1-based 都能写对。风险在于让 a 使用 0-based、让 s 使用 1-based，却没有明确说明偏移。推荐整篇代码统一使用 1-based；如果必须混用，把“s[i] 对应 a[i-1]”写在定义旁边。

### 3. 先算范围，再选类型

如果 n=2×10^5 且每项绝对值可能达到 10^9，累计值可能达到 2×10^14，int 不够。前缀和、差分和还原过程中的累计变量使用 long long，不要只给最终输出变量换类型，因为溢出可能已经发生在中间表达式里。

### 4. 这两种方法都有适用范围

| 需求 | 选择 |
| --- | --- |
| 数组不变，多次区间和查询 | 前缀和 |
| 多次区间加，最后统一读取 | 差分 |
| 多次区间加，同时多次查询 | 树状数组或带懒标记的线段树 |
| 多次单点修改，同时查询区间和 | 树状数组 |
| 区间最大值或最小值 | 不能直接靠“前缀减法”恢复，考虑 ST 表或线段树 |

前缀和依赖“区间结果可以由两个前缀合并得到”。求和、异或和计数可以使用类似结构；最大值没有对应的逆运算，不能照搬减法公式。

## 读者自查卡

1. 数组是否明确采用 0-based 还是 1-based？
2. s[0] 是否初始化为 0？
3. 差分数组是否预留 n+1 位置？
4. 所有可能累计到 n×值域的变量是否使用了足够宽的类型？
5. 是否分别写过 n=1、l=r=n、全负数和多次覆盖同一区间的情况？
6. 如果操作和查询交错，是否已经换用支持动态维护的数据结构？
