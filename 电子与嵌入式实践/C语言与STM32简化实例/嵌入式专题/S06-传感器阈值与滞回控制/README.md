# S06 传感器阈值与滞回控制

## 一句话结论

**单阈值控制在边界必然抖动：读数在阈值附近 ±2 波动，输出就开关开关地翻。** 修法是滞回（开、关用两个阈值，中间维持原状态），要更稳再加持续去抖（连续 N 个采样要求切换才动）。

## 实测（PC 模拟）

文件：[sensor-hysteresis-demo.c](sensor-hysteresis-demo.c)。光敏 AO/ADC 读数序列（值越大越暗），动作值 1000、滞回释放值 800：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic sensor-hysteresis-demo.c -o sensor-hysteresis-demo.exe
```

```text
采样  读数   直通LED  滞回LED  滞回+去抖LED
   4    999    关      关       关
   5   1001    开      开       关
   6    999    关      开       关    <- 直通翻了，滞回没动
   7   1001    开      开       开    <- 去抖第 3 拍才真正开
   8   1000    关      开       开    <- 直通又翻了
  11   1000    关      开       开
  14    850    关      开       开
  15    799    关      关       开    <- 低于 800 滞回才关
  16    801    关      关       开    <- 回到带内，维持关
  17    799    关      关       关

翻转次数：直通 6 次，滞回 2 次，滞回+去抖 2 次
```

（完整 20 行对照表见程序输出。）三个层次一眼分开：**直通 6 次翻转全在 999/1001 边界；滞回只在真正越过两个阈值时动 2 次；去抖版把单点毛刺再滤掉一层，代价是最多晚 N 拍响应。**

## 一、原型工程在哪一层

`本地传感器工程原型` 现在是 **DO 数字量直通**：

```c
GPIO_WriteBit(GPIOB, GPIO_Pin_12, GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13));
```

光敏模块的 DO 引脚输出 0/1，**阈值由模块板上的电位器（硬件比较器）决定**，软件只搬运电平。这一层没有软件阈值可言；要可编程的阈值、滞回、去抖，前提是 **AO 接 ADC 读数值**——本 demo 模拟的就是这一步（`传感器示例工程` 的 `bark.c` 目前为空，蜂鸣器报警正是这一层的应用）。

## 二、滞回：状态记忆 + 两个阈值

```c
if (!state && light > ACTION_LEVEL)  return 1;   /* 关 -> 开：过动作值 */
if (state && light < RELEASE_LEVEL)  return 0;   /* 开 -> 关：低于释放值 */
return state;                                    /* 带内：维持 */
```

两个阈值之间的 200（800~1000）叫**滞回带**：带内读数再怎么抖，输出都不动。硬件世界里它叫施密特触发器，原理相同。`state` 是**上一次的输出**——这是 K04 状态机最小形态：输出不只取决于输入，还取决于历史。

## 三、持续去抖：和按键消抖同一招

读数毛刺（闪电、阴影、电磁干扰）表现为一两个采样的跳变。**连续 N=3 个采样都要求切换才动**，单点毛刺自然滤掉。注意与 S02 按键消抖的区别：按键抖动在**毫秒级时间轴**（等 20ms 再读），传感器毛刺在**采样序列轴**（数连续 3 个）——结构同源，判据不同。

## 四、代价与选择

| 策略 | 翻转（实测） | 响应速度 | 适用 |
| --- | --- | --- | --- |
| 直通 | 6 次 | 立即 | 输入本身干净、无所谓抖 |
| 滞回 | 2 次 | 立即 | 边界抖动明显的模拟量 |
| 滞回 + 去抖 | 2 次 | 晚 ≤3 拍 | 报警类：宁可慢，不可误报 |

去抖的 N 与采样周期相乘才是真实延迟：N=3、每 100ms 采一次 = 最多晚 300ms。报警觉得太钝就减 N，误报太多就加 N。
