# S05 嵌入式实例

## 一、PC 侧：已验证

文件：[tick-frame-demo.c](tick-frame-demo.c)，输出见 [README](README.md)。

验证的是：阻塞空转导致并行任务停摆、非阻塞时刻表让多任务同轮进行、`uint32_t` 回绕时有符号差值判法正确而直接比较误判。

## 二、工程原型对照（OLED 示例工程）

该工程的 `User/main.c` 里就是本专题的结构，原样抄关键段：

```c
/* 由 SysTick_Handler 每 1 ms 加 1。 */
volatile uint32_t g_OLED_Millisecond = 0;

static void OLED_WaitUntil(uint32_t Target)
{
    while ((int32_t)(g_OLED_Millisecond - Target) < 0)
    {
    }
}
```

`main` 里配置 1ms 时基（CMSIS 标准 API，`SystemCoreClock / 1000` = 每 1ms 一次中断）：

```c
SysTick_Config(SystemCoreClock / 1000U);
```

帧调度（每 100ms 一帧、10s 一轮）：

```c
#define OLED_CYCLE_MS    10000U
#define OLED_FRAME_MS    100U

while (1)
{
    CycleStart = g_OLED_Millisecond;
    for (Frame = 0; Frame < OLED_FRAME_COUNT; Frame++) {
        OLED_WaitUntil(CycleStart + (uint32_t)Frame * OLED_FRAME_MS);
        OLED_RenderLoveFrame(Frame);        /* 到点画一帧 */
    }
    OLED_WaitUntil(CycleStart + OLED_CYCLE_MS);
    OLED_ClearBuffer();
    OLED_Update();
}
```

基准时间加偏移与 `next += period` 都能保持计划周期；真正容易累积漂移的是每次处理完成后重新设 `next = now + period`。此外，`OLED_WaitUntil` 内部仍在空循环等待，属于阻塞式写法。非阻塞主循环应每轮只判断是否到期，到期才执行一次任务，然后继续调度其他任务。

中断服务函数（工程 `User/stm32f10x_it.c`，SPL 标准写法）：

```c
void SysTick_Handler(void)
{
    g_OLED_Millisecond++;
}
```

## 三、阻塞 Delay 长什么样（课程中的 Delay 实现）

```c
void Delay_us(uint32_t xus)
{
    SysTick->LOAD = 72 * xus;              /* 重装值 = 72MHz * 微秒数 */
    SysTick->VAL  = 0x00;                  /* 清当前计数 */
    SysTick->CTRL = 0x00000005;           /* HCLK 时钟源，启动 */
    while (!(SysTick->CTRL & 0x00010000)); /* 轮询 COUNTFLAG，CPU 空转 */
    SysTick->CTRL = 0x00000004;           /* 关闭 */
}
```

它单独占用 SysTick（用完就关），与同一定时器上的中断时基配置冲突。要用非阻塞时基，主循环每轮读一次当前时刻，判断未到期就继续做其他任务，而不是换成另一个空循环等待函数。等待按键释放的 `while(按下);` 同样会阻塞主循环。

## 四、SysTick 是什么

Cortex-M3 内核自带的 24 位倒数定时器，不需要 init 外设时钟：

| 寄存器 | 作用 |
| --- | --- |
| `LOAD` | 重装值，数到 0 自动回填 |
| `VAL` | 当前计数 |
| `CTRL` | 时钟源选择、中断使能、启动 |
| `COUNTFLAG` | 数到 0 置位（Delay 轮询它，时基中断不用它） |

`SysTick_Config(ticks)` 一次配完三件事并把中断挂到 `SysTick_Handler`。72MHz 下 `LOAD` 上限约 233ms（`72*xus` 注释里 0~233015us 的来历）。

## 五、上板前要核对的

- `SystemCoreClock` 与实际主频一致（72/8MHz 配错，所有时间差倍数——和串口波特率乱码同源）
- 工程里是否还有别的 `Delay_ms` 在抢 SysTick
- 中断优先级：SysTick 时基通常低于外设中断，被 `NVIC_SetPriority` 改过要知道

## 六、把本专题带回 PC 的做法

时间类逻辑的 PC 验证法：**变量当时基，for 循环推时间，printf 出时间线**。能覆盖：多任务是否互不阻塞、时刻表是否漂移（打印值和预期值逐行对）、回绕边界（把初值拨到 `0xFFFFFFF0` 附近跑）。上板后才需要看的只剩：SysTick 配置寄存器、中断函数是否真的被挂上（示波器/逻辑分析仪量 100ms 引脚翻转）。
