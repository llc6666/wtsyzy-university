# K05 读：两份参考解里的字符数组处理

## 一、`reverse-string`：从后往前写入的写法

来源：`99-素材库/exercism-c/K05-数组与字符数组/reverse-string_参考解.c`（exercism/c，MIT）

（原示例代码未随公开版复制；此处保留分析结论。）

逐行看：

| 行 | 在做什么 |
| --- | --- |
| `malloc(value_len + 1)` | 容量 = 字符数 + 1，这一行的 `+1` 就是本知识点的第一条规则 |
| `dest = result + value_len` | 指针指向数组最后一个字节的**后一位** |
| `*dest = '\0'` | 先把结尾字符放好（此时 dest 在最后） |
| `--dest; *dest = *value;` | 先退再写，所以第一次写落在 `result[value_len - 1]` |
| `while (*value)` | 循环条件就是「还没读到 `\0`」 |

这种「先算长度、再从后往前写」的写法值得记住，它把「找结尾」和「反转」合成一趟。

所有权的约定：函数 `malloc`，**调用方负责 `free`**。头文件里没写，但这是 exercism 的惯例，也是 C 里最常见的契约之一。

## 二、`acronym`：靠前一个字符判断单词边界

（原示例代码未随公开版复制；此处保留分析结论。）

三个细节：

1. **判断单词开头靠的是「前一个字符是什么」**，而不是去切分字符串。这个思路在解析串口数据时同样好用
2. `isalpha` 的参数要转成 `unsigned char` 再传（标准规定 `isalpha` 只接受能表示为 `unsigned char` 的值或 EOF），传 `char` 且值为负时是未定义行为
3. 连字符 `-` 与下划线 `_` 都算分隔符，其他标点直接跳过（题面要求）

## 三、CrashCourse《09-数组》《14-字符串》

来源：`99-素材库/hairrrrr-C-CrashCourse/K05-数组与字符数组/`（本地未发现 LICENSE，本批按特批入库，许可状态不变）

读的时候抓三点：

- 数组下标从 0 开始，最后一个有效下标是 `长度-1`
- 数组初始化时未指定的元素会被填 0
- `<string.h>` 里各函数对 `\0` 的处理差异（`strcpy` 不检查容量、`strncpy` 不保证补 `\0`、`strncat` 会补）

第三条是本知识点最容易出事故的地方：这些函数名字只差一个字母，行为差别却很大。

## 读码小结

1. 看到 `malloc(n + 1)` 就知道作者在给 `\0` 留位置；看到 `malloc(n)` 就要警惕
2. 看到操作字符数组，先找 `\0` 在哪
3. `isalpha` / `toupper` 这类函数传参前先转 `unsigned char`
