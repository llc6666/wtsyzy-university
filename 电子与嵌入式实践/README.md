# 电子与嵌入式实践

这里整理从电子基础到嵌入式小项目的可执行方法。目标不是收集开发板、视频或工程压缩包，而是每一步都留下可复现的接线、代码、测量或版本记录。

## 何时使用

- 刚开始学习单片机，不知道先做什么、如何判断是否学会时。
- 第一次给 STM32 开发板上电、烧录或调串口时。
- 做小型硬件项目，需要避免“代码、原理图和实际板子对不上”时。

## 输入

1. 一块明确型号和版本的开发板，以及对应芯片丝印。
2. 调试器或下载器、数据线、万用表；需要串口时再准备 USB 转串口模块。
3. 芯片数据手册、参考手册、开发板原理图的官方或板卡提供方链接。
4. 一个可用的本地 Git 仓库，用于保存配置、代码和测试证据。

## 使用顺序

1. 先完成[基础到 STM32：阶段任务与验收](基础到STM32：阶段任务与验收.md)，选择当前阶段的一项最小任务。
2. 第一次使用一块板子时，执行[STM32 最小实验：从资料核对到串口回显](STM32%20最小实验：从资料核对到串口回显.md)。
3. 每次实验按[硬件实验记录与故障定位](硬件实验记录与故障定位.md)留下记录，不凭印象下结论。
4. 项目开始出现多个板卡、固件或成员协作时，执行[嵌入式项目的版本对应与发布检查](嵌入式项目的版本对应与发布检查.md)。
5. 进入 ADC、PWM、I2C 或信号处理时，先阅读对应主题页，再按实验记录模板保存原始证据。

## 交付物

- 一张板卡事实卡：芯片、板卡版本、供电、调试接口和原理图链接。
- 一个能重新编译、烧录并观察结果的最小实验。
- 一份实验记录和一张硬件、固件、测试结果对应表。

## 验收

- 任何实验结论都能回答：用的是什么板、哪个版本、怎样接线、如何复现、看到什么现象。
- 代码仓库不包含密钥、付费软件破解文件、未授权固件、他人完整工程包或成员个人信息。
- 更换电脑或清理构建目录后，按记录能重新配置并得到同一类结果。

## 公开边界

本目录是个人学习方法的公开编译，不代表任何社团或组织的官方规则。原始培训材料、逐页转录、第三方项目包、私有仓库、成员分工、未公开原理图与二进制固件不进入本仓库。公开引用只给出必要结论和原始公开链接。
