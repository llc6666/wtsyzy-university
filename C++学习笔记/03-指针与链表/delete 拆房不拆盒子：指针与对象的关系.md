# delete 拆房不拆盒子：指针与对象的关系

## 一句话结论

指针变量（盒子）和它指向的对象（房子）是两回事。`delete p` 释放的是 p 指向的**对象**（拆房），不是指针变量本身（盒子还在，门牌号还在，但指向的内存已归还）。多个指针指向同一对象时，一次 delete 让所有指向它的指针全部变成悬空指针。

## 它解决什么问题

很多新手以为 `delete p` 是"删除 p 这个变量"，导致删错对象、悬空访问、堆损坏。理解"盒子与房子分离"，才能安全地写释放逻辑，也是理解"先存 next 再 delete""先取值再 delete"这类顺序规则的基础。

## 工作机制

```cpp
Node* p = top->next;   // p 盒子装进 20 的门牌号
top = p;               // top 盒子也装进 20 的门牌号
// 现在两个盒子都指向 0x500（20 那间房）

delete p;              // 拆掉 0x500 这间房，归还内存
                       // p 盒子还在，top 盒子也在
                       // 但 0x500 已成废墟，两个盒子全是悬空指针

return top->data;      // 走进废墟翻东西 → 垃圾值 / 崩溃
```

关键机制：

1. 指针变量存的是**地址**（门牌号），不是对象本身。
2. `delete p` 的语义是"结束 p 指向对象（若有）的生命周期并释放存储"，**不修改 p 的值**。
3. delete 后，p 里仍保留原地址，但该地址的内存已不归程序所有，读它是未定义行为。
4. 多个指针指向同一对象时，delete 一次，所有指向它的指针同时悬空。

## 最小示例

```cpp
int* a = new int(7);
int* b = a;        // b 和 a 装同一个门牌号
delete a;          // 拆房
// *b 已经是未定义行为，b 悬空
```

## 常见错误与边界

1. **悬空指针访问**：delete 后再解引用，拿到垃圾值或崩溃。`delete p; cout << *p;` 是典型的未定义行为。
2. **双重删除**：同一地址 delete 两次，第二次行为未定义，可能堆损坏。
3. **删错对象**：换顶/跳链操作中，没有抓住"要删的那个节点"就 delete，把还在使用的节点删了（practice9 的 pop 曾把新栈顶删掉）。
4. **"先存 next 再 delete"的原理**：delete p 后 p->next 不可读，所以必须提前把下一站门牌抄进临时变量。
5. **delete 后置空是习惯不是保证**：`delete p; p = nullptr;` 只让 p 自己安全，其他指向同一对象的指针依然悬空。

## 如何验证

让动态对象的析构函数输出一行文字，执行 `delete p` 后应只看到对象析构；变量 `p` 本身仍存在但不再指向可用对象。随后写 `p = nullptr`，再检查 `p == nullptr` 为真。不要在删除后访问 `p->成员`。

## 使用规则

- 写释放逻辑前，先问：**delete 会拆掉哪间房？还有谁装着这间房的门牌号？**
- 要用的东西（值、下一站指针）必须在 delete **之前**拿出来。
- delete 后不再解引用该指针，除非重新赋值。
- 同一对象只 delete 一次，所有权要明确（谁 new 谁 delete）。
- 析构函数里释放成员指针时，遍历顺序和"先存后删"必须严格。
