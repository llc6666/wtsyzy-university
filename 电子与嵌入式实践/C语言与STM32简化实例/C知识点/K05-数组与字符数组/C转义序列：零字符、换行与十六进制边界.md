# C 转义序列：零字符、换行与十六进制边界

## 这篇笔记解决什么问题

转义序列把源代码中的可读写法映射到字符值或字节。它常出现在串口帧、日志、路径、格式化输出和字符数组初始化中。排查时不要只看屏幕上的字形，要把下面三层分开：

1. 源码中的字符组合，例如反斜杠和 `n`。
2. 编译后字符串中的实际字节。
3. C 字符串额外使用的结尾 `\0`。

## 最容易混淆的几组写法

| 写法 | 含义 | 读代码时要问 |
| --- | --- | --- |
| `'\0'` | 数值为零的字符，常用作字符串结束标记 | 它是否位于有效缓冲区内 |
| `'0'` | 字符 `0`，不是零字节 | 协议需要数字字符还是结束标记 |
| `'\n'` | 换行控制字符 | 接收端是否把它当作一行结束 |
| `'\r'` | 回车控制字符 | 发送端是否采用 `\r\n` 组合 |
| `'\\'` | 一个反斜杠字符 | 后面的内容是否会继续被解释 |
| `'\t'` | 制表控制字符 | 显示宽度是否影响日志阅读 |
| `'\x41'` | 十六进制转义，对应一个字符值 | 后面是否紧跟其他十六进制数字 |
| `'\101'` | 八进制转义，对应一个字符值 | 数字是否仍处于允许的八进制范围 |

`"\r\n"` 是两个控制字符组成的字符串；它后面还会自动带一个字符串结尾 `\0`。如果协议只接受一个换行字节，不能把 `\r\n` 当成一个字符。

## `\0`、`0` 和字符数组长度

```c
char message[] = "OK";
char raw[] = {'O', 'K'};
```

`message` 是一个可直接交给字符串函数的字符数组，数组中包含 `O`、`K` 和 `\0`。`raw` 只有两个元素，不自动追加 `\0`，因此只能按长度处理。若需要把 `raw` 变成字符串，必须确认数组还有一个可写字节，再明确写入终止字节。

这条规则同样适用于串口接收：收到的字节数是 `length`，并不等于字符串长度；只有在协议允许、缓冲区容量足够时，才可以在 `buffer[length]` 写入 `\0`。

## 八进制和十六进制会吞掉后续数字

八进制转义最多读取三个八进制数字。十六进制转义会继续读取后面的十六进制数字，直到遇到非十六进制字符。因此，下面这种写法的边界不直观：

```c
const char *ambiguous = "\x41B";
```

如果本意是字符值 `0x41` 后面紧接字母 `B`，用相邻字符串字面量把边界写出来：

```c
const char *clear = "\x41" "B";
```

相邻字符串字面量会在编译阶段连接，读者能直接看到转义序列在哪里结束。对协议字节更推荐使用明确的整数或字节数组，并在注释中写出字节数，减少视觉表示带来的误读。

## 路径和反斜杠

反斜杠在 C 字符串中有特殊含义。路径、正则表达式或其他需要保留反斜杠的文本，要么使用两个反斜杠表示一个实际反斜杠，要么选择协议允许的其他分隔符：

```c
const char *path = "logs\\today";
```

看到未知转义或编译器警告时，先确认本意是控制字符、实际反斜杠，还是漏写了一个反斜杠。修复前不要只根据显示出来的字符串猜测内存内容。

## `printf` 的百分号是另一套规则

转义序列处理的是 C 字符常量和字符串字面量；`printf` 格式串中的 `%` 由格式化函数解释。若要输出一个百分号，应写成：

```c
printf("100%%\n");
```

这里的 `%%` 不等于一个 C 字符串转义序列。遇到“源码看起来正确但输出不对”时，先判断问题属于字面量解析还是格式化解析。

## 字节核对卡

整理一段包含控制字符的文本时，按下面顺序记录：

| 项目 | 记录 |
| --- | --- |
| 源码写法 | 字符常量、字符串字面量或字节数组 |
| 实际内容 | 每个字节的十六进制值 |
| 有效长度 | 不含 `\0` 的数据长度 |
| 终止规则 | 是否需要额外写入 `\0` |
| 消费方 | 字符串函数、长度接口、协议解析器或格式化函数 |
| 易错边界 | `\x` 吞数字、`\r\n` 双字节、路径反斜杠或 `%` |

读者自查时至少写出一个“源码字符数”和“实际字节数”不同的例子，再说明差异来自控制字符、转义边界还是字符串终止符。
