# C++ 错误复盘方法：从症状到判据

## 这页解决什么问题

错误集的价值不在于记住某道题错过什么，而在于把一次错误压缩成下次可以提前检查的规则。

一条可复用的错误记录至少要回答六个问题：

1. 看到什么症状。
2. 哪个输入或状态能让症状出现。
3. 代码原本假设了什么。
4. 实际语言规则、数据范围或题目模型是什么。
5. 修复动作改变了哪条规则。
6. 下次在什么位置提前检查。

只写“粗心”“边界错了”“多练习”不能形成方法。它没有告诉读者下一次应该看哪一行、写哪张表、构造什么反例。

> 来源边界：本页由个人 C++ 错误集中的通用规律改写而来。来源包含历史编译、运行和对拍记录；本轮只做筛选与改写，没有重新编译、运行或测试。

## 一、先按错误出现的阶段定位

| 阶段 | 典型症状 | 先查什么 |
| --- | --- | --- |
| 编译阶段 | 语法错误、类型不匹配、找不到成员、链接失败 | 声明、头文件、命名空间、成员定义、函数签名和多文件定义 |
| 运行阶段 | 崩溃、退出码异常、输出中途停止 | 空指针、数组边界、对象生命周期、栈容量、整数溢出和状态复位 |
| 结果阶段 | 能运行但答案错误、样例碰巧通过 | 输入顺序、模型、不变量、端点、变量职责、输出格式和计数口径 |
| 性能阶段 | 小数据正常，大数据超时或内存不足 | 最坏操作量、存储规模、重复计算、是否把结构化问题硬模拟 |
| 证据阶段 | 只凭一个样例或一次输出下结论 | 最小反例、边界分类、独立参照、历史记录和当前验证是否混淆 |

先分阶段，能避免把运行时越界当成算法错，也避免用“样例过了”替代模型推导。

## 二、写代码前先落五张小表

面对新题或新模块，先写下列内容。每张表只写与当前任务有关的字段。

### 1. 输入契约表

| 项目 | 要写的内容 |
| --- | --- |
| 数量 | 测试组数、元素个数、操作次数 |
| 范围 | 最小值、最大值、是否允许负数 |
| 顺序 | 坐标是否有序、输入是否分组、字符串和数字的读取顺序 |
| 空状态 | 空容器、找不到目标、没有可行解时怎么表示 |
| 输出 | 每组输出几次、是否需要换行、是否要求固定精度 |

### 2. 变量职责表

给每个变量写一句唯一职责：

- n 只表示原始输入数量。
- i 只表示当前循环位置。
- count 只表示当前结果数量。
- found 只表示当前分支是否找到目标。
- state 只表示状态机状态。

如果一个变量同时承担“循环上限”和“结果数量”，优先拆开。循环中修改边界变量，是许多漏读、少算和提前退出的来源。

### 3. 存储与生命周期表

写清楚：

- 数据放在裸数组、vector、链表还是映射表。
- 容器什么时候获得容量。
- 指针可能为空吗。
- 谁创建对象，谁负责销毁。
- 删除对象前还要读取哪些字段。
- 循环链表、树或图是否需要额外的终止条件。

### 4. 模型表

把题目对象、状态转移和目标函数写成三行：

- 对象：实际要表示什么。
- 变化：一次操作如何改变状态。
- 目标：要判断存在性、求最优值、统计方案数，还是输出过程。

如果题目中的坐标很大、时间可以无限推进或状态可以压缩，先找不变量和充要条件，再决定是否需要模拟。

### 5. 证据表

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 读懂定义 | 能解释语义 | 不能说明已经能独立写出 |
| 通过一个样例 | 该样例下没有显性错误 | 不能说明覆盖边界 |
| 编译通过 | 语法、类型和链接在该环境下成立 | 不能说明算法正确或硬件可用 |
| 一组边界记录 | 这些边界曾被覆盖 | 不能替代所有变式 |
| 独立实现或参照 | 当前版本与参照一致 | 不能自动证明所有输入 |

## 三、把症状缩成最小触发条件

复盘时不要先重写整段代码，先把错误缩小到一个最小触发条件。

常见缩减方式：

- 指针：空表、空栈、目标不存在、删除最后一个节点。
- 数组：长度为 0、访问首尾、访问 i + 1 或 i - 1。
- 数值：最小值、最大值、乘法前后、负数、类型提升前的除法。
- 循环：只执行一次、最后一次、条件永远不成立、状态没有复位。
- 排序：相等元素、重复关键字、比较器返回相等、前后方向反转。
- 输入输出：多组数据、空行、行尾空格、最后一行没有换行。

然后写成一句话：

> 当条件 A 出现时，代码在位置 B 使用了假设 C；因此产生症状 D。

这句话比“这里容易越界”更有用，因为它给出了可搜索、可检查、可迁移的定位条件。

## 四、最常见的高风险检查

### 1. 指针、容器与生命周期

- 解引用前先确认对象存在。
- 短路表达式把保护条件放在使用条件之前，例如先判断 p == nullptr，再访问 p->field。
- 删除对象前先保存仍要使用的值或下一个节点。
- 删除链表节点时同时检查头节点、尾节点和中间节点。
- vector 先取得容量，再使用下标写入；只调用 reserve 不会增加可写元素数量。
- 记录迭代器、引用或指针在容器扩容、插入、删除后是否仍然有效。

### 2. 类型、范围与中间表达式

最终变量写成 double，不能挽回前面已经发生的整数除法：

~~~cpp
double result = a / b;                              // a、b 都是整数时先整除
double ratio  = static_cast<double>(a) / b;         // 在除法发生前提升类型
~~~

乘法和累加也要在运算前估算上界。只把接收结果的变量改成 long long，无法修复两个 int 已经完成的溢出。

### 3. 变量职责与状态复位

多组数据、递归分支和循环阶段都要检查：

- 上一组数据的标记是否清空。
- 内层循环是否修改了外层循环变量。
- 一个容器是否被两个阶段复用却没有清空。
- 当前状态、历史状态和事件是否被混为一个变量。
- 删除一项后，数量、边界和指针是否同步更新。

### 4. 算法模型与直接模拟

出现下列信号时，暂停写循环：

- 坐标或范围达到无法开数组的规模。
- 过程时间很长，但只需要判断“是否会发生”。
- 每一步都重复扫描相同数据。
- 题目存在不变量、单调性、周期或分组结构。

先写出“哪些对象永远不变”“哪些对象只会向一个方向变化”“答案是否具有单调性”。没有证明时，把当前算法当作候选方案，不能把样例通过写成正确性结论。

### 5. 排序与比较器

比较器回答的是“左参数是否应该排在右参数前面”，不是“两个值是否相等”。

~~~cpp
bool cmp(const Node& a, const Node& b) {
    if (a.score != b.score) return a.score > b.score;
    return a.id < b.id;
}
~~~

使用 std::sort、set 或 priority_queue 时分别确认比较器的位置和方向。不要用 <= 代替严格比较，也不要把堆顶方向机械地套成排序方向。

### 6. 输入、输出与交付格式

- 输入顺序按题面逐项落成变量，不要凭变量名猜顺序。
- 每组数据的输出次数要和循环层级一致。
- 需要换行就明确写换行符。
- 题目要求的字符、空格、精度和大小写都属于输出契约。
- 修改源码后，先确认运行对象确实来自当前源码对应的构建产物；历史产物的输出不能反推当前代码。

## 五、一次复盘的固定模板

~~~text
标题：
症状：
最小触发条件：
原始假设：
实际规则：
错误层级：输入 / 模型 / 边界 / 实现 / 性能 / 证据
修复动作：
为什么这个修复覆盖根因：
下次写码前的检查：
还没有覆盖的变式：
证据状态：来源记录 / 读码结论 / 读者自测待完成
~~~

“还没有覆盖的变式”必须保留。它防止一条错误记录被误读为某个算法已经完全掌握。

## 六、把错误记录变成复习动作

每周维护一次错误集时，按以下顺序处理：

1. 删除只描述情绪或结果、没有触发条件的条目。
2. 合并同一根因的多个实例，例如“下标错一位”“端点漏一项”可以归入边界检查，再保留不同触发例。
3. 给每条规则补一个最小反例或读码问题。
4. 把错误映射到知识点，而不是只挂在某道题名下。
5. 把仍未覆盖的变式单独列为下一轮任务。
6. 复盘结束后重新扫一遍输入、存储、边界、状态、模型和输出六项。

复盘的产物应当是下一次写码时能直接使用的检查卡，而不是越写越长的流水账。

## 七、可直接使用的收尾清单

- [ ] 输入数量、范围、顺序和空状态已写清。
- [ ] 每个变量只有一个职责。
- [ ] 所有下标、端点和 i + 1、i - 1 访问都能说明范围。
- [ ] 指针、引用、迭代器的有效期明确。
- [ ] 整数除法、乘法、累加和转换发生在正确的类型上。
- [ ] 多组数据的状态会在正确位置复位。
- [ ] 算法使用了题目模型，而不是未经估算的逐步模拟。
- [ ] 排序比较器满足严格排序要求。
- [ ] 输出次数、字符、空格、换行和精度符合契约。
- [ ] 记录了仍未覆盖的变式与证据等级。
