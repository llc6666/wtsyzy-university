# 基础到 STM32：阶段任务与验收

> 目标：用一串可检查的小任务建立嵌入式能力。没有通过本阶段验收，就不靠购买更多模块或复制更大工程跳到下一阶段。

## 何时使用

- 想从零开始学单片机，或者已有碎片教程但没有清晰进度时。
- 发现自己“看过 GPIO、串口、PWM”，但无法独立完成一个最小实验时。

## 输入

1. 每周稳定可投入的时间，例如 4 到 8 小时。
2. 一块型号明确的开发板、调试器和基础测量工具。
3. 芯片数据手册、参考手册、开发板原理图的链接。
4. 一个本地 Git 仓库和实验记录模板。

## 阶段任务

| 阶段 | 只解决的问题 | 最小任务 | 必须留下的证据 | 通过条件 |
| --- | --- | --- | --- | --- |
| C 语言 | 能否读懂和修改固件逻辑 | 写一个读取输入、更新状态、输出结果的小程序 | 源码、三组输入输出 | 能解释变量、条件、循环、函数和数组在程序中的作用 |
| 板卡事实核对 | 板子实际连了什么 | 从原理图标出电源、复位、调试、一个 LED 和一个串口接口 | 板卡事实卡、原理图页码 | 不把丝印猜测当作接线结论 |
| GPIO | MCU 能否控制一个确定的外设 | 以原理图为准让 LED 按固定周期翻转 | 工程、烧录记录、现象视频或测量记录 | 复位后行为稳定，且能说清引脚、时钟和电平逻辑 |
| UART | PC 与 MCU 能否双向交换数据 | 接收一个字符并返回带版本号的回应 | 串口日志、波特率与接线表 | 至少连续 20 次发送接收无乱码、无丢失 |
| 定时器和 PWM | 时间参数是否可控 | 输出一个指定周期的 PWM，并测量频率或脉宽 | 配置截图、测量记录 | 测量值与目标值的误差写清楚，不能只写“能动” |
| ADC 与 DMA | 模拟信号是否被可靠采样 | 固定采样数写入缓冲区，输出最小值、最大值和平均值 | 采样率、缓冲区长度、原始数据片段 | 参数与代码配置一致，断开输入后现象可解释 |
| 小型项目 | 能否把模块接成闭环 | 做一个输入、处理、输出齐全的小项目 | 版本表、测试表、复盘 | 新环境按说明可以构建，关键用例通过 |

## 操作步骤

1. 从表中只选当前一行任务，写下完成日期和可用时间上限。
2. 先建立板卡事实卡，再新建工程；禁止从不明来源复制整个工程。
3. 每完成一个模块，记录输入、期望现象、实际现象和原始数据。
4. 未通过验收时，只定位本阶段的问题。不要把“升级芯片、换 IDE、加模块”当作默认修复。
5. 通过后提交代码和记录，再开始下一阶段。

## 交付物

- 每个通过阶段一个独立目录或 Git 提交。
- 一张阶段清单，包含目标、实际参数、证据路径和遗留问题。
- 最后一个小项目的版本对应表和测试表。

## 已做过的阶段：怎样独立重建一次

适用于跟着教程或 Agent 完成过工程，却不确定自己能否重新写出关键部分的情况。第一次接触外设时先学习资料，不用闭卷练习替代必要的讲解。

下面是一套复习操作约定，计时、参考权限和复查间隔应按任务调整；它不提供统一评分，也不承诺固定天数内掌握技能。文中的运行、测量和重建动作由学习者另行实施，本轮笔记整理没有代做。

### 1. 先限定一项能力和参考权限

一次只选一个阶段中的一个动作，例如“独立写出按键事件处理的核心结构”，不要同时要求显示、通信和电机联动。

开始前写一张任务卡：

```text
本轮唯一目标：
给定的工程基础设施：
我必须自己实现的部分：
允许改动的文件或模块：
不能影响的已有功能：
允许查阅的资料：
本轮不看的答案、旧实现和项目指导：
开始与停止时间：
卡住多久后记录并跳过：
代码、机制解释、硬件现象分别怎样留证：
```

参考权限要具体到材料类型：

| 材料 | 独立尝试时的约定 | 怎样记录 |
| --- | --- | --- |
| 数据手册、参考手册、函数签名 | 事先约定后可以查 | 记下查了哪个接口或参数 |
| 自己以前的完整实现、项目解答、逐步教程 | 暂时关闭，首次作答后再对照 | 若中途看了答案，将本次记为有辅助练习 |
| Agent | 先约定只澄清题意或解释术语，不给当前任务实现 | 记录获得了哪一级帮助 |
| 已提供的启动、时钟或驱动模块 | 列出哪些可直接调用、哪些必须自己写 | 不把给定模块算进个人独立实现范围 |

不必为了显得独立而重新搭建全部工程。把原有工程保留为历史记录，在独立练习副本中动手，避免用后来修正的版本覆盖最初的作答。

### 2. 把环境基线与能力缺口分开

先记录提供方给出的工程版本、已有告警、可用接口和已知限制。提供方声称“可编译”，只是一条来源记录；若学习者没有亲自构建或核对，不写成自己已确认。

若实际练习被缺失工具链、无法连接设备或工程配置错误阻断，保留报错并暂停该项计时。环境没有就绪时，不从未完成任务推断原理掌握程度。反过来，工程能构建，也不能替代独立解释或硬件现象。

计时规则可从“环境准备完成后，开始阅读本次需求”算起，提前写清即可。目的在于观察卡点，不用赶时间掩盖危险接线或跳过供电核对。

### 3. 保存第一次作答，卡点写成可处理的问题

先用自己的话列出输入、状态、输出和处理顺序，再写实现。到了约定停止时间就保存当前版本，允许未完成，不要求先修成漂亮答案再交给审阅者。

| 卡在哪一步 | 当时已知什么 | 还缺什么 | 已尝试什么 | 下一步最小动作 |
| --- | --- | --- | --- | --- |
| 不知道如何区分保持按下与新的一次按下 | 当前读取值和目标行为 | 需要保存什么历史状态 | 写出了连续两次采样的情形 | 先画状态表，不加新功能 |
| 调用现有驱动前不确定接口 | 已知功能名称 | 参数、返回值或声明位置 | 查到头文件但未读实现 | 查接口约定，记录查阅行为 |

“不会”“调不通”“再看看”不足以指导下一步。尽量写到某个参数、某个分支、某条依赖或某个尚未取得的观察。

### 4. 让审阅者指出问题，不覆盖你的作答

首次作答后，再请求人工或 Agent 审阅。可以直接使用这段要求：

```text
只审阅我提供的当前版本，不修改文件，不给替换实现，不执行代码或硬件操作。
每个问题列出：位置、违反的需求、可能后果、判断依据和仍需什么证据。
请把确定的静态问题与需要运行或测量才能确认的现象分开。
最后提出三个解释问题，等待我自己回答和修改。
```

三个解释问题可围绕以下方向选取：

1. 为什么选择这个状态、顺序或参数？依据在哪里？
2. 若去掉一项前提或改变一个约束，哪一步需要调整？
3. 哪种错误最容易被正常现象掩盖，读者应观察什么才能区分？

审阅者预测“可能漏掉事件”，不等于已经测到漏事件；来源中已有的构建记录，也不能变成本轮复现记录。自己完成修正后，保留修正前后差异及理由。

### 5. 合上解答重建，再按缺口回填笔记

关闭旧实现、审阅答案和项目指导，在事先约定的短时间内写出：

- 模块或函数有哪些、谁调用谁。
- 哪些变量跨多次处理保留，各自表示什么。
- 初始化与循环处理的先后顺序。
- 关键参数的来源、适用条件和不能影响的其他功能。
- 一个未解决问题，以及准备取得哪条证据。

不要求逐字符背代码，也不把记不住一个 API 名称等同于不会原理。若需要查函数签名，按事前约定记录；若重新看了完整实现，本次就保留“有辅助”的边界。

重建结束后才对照解答，写自己的修正规则。例如：“我只保存了当前输入，无法表示一次状态变化；下次先列前后状态表。”不要把整份答案复制进错误笔记。

“先尝试再回填”只约束这类复习练习。学习前的术语查询、资料摘录、来源登记和安全记录仍然可以正常进行。

### 6. 用证据表结束，不用总分代替结论

```text
任务与参考权限：
首次作答保存位置：
本次得到的帮助：
主要卡点：
本人修正及理由：
独立重建：未做 / 有辅助 / 无答案辅助完成；缺口：
机制解释：未解释 / 解释不完整 / 已解释；依据或疑问：
构建状态：未做 / 来源已有记录 / 本人执行记录；版本与告警：
硬件状态：未观察 / 仅预测 / 已观察；接线、版本与记录：
下一次只复查什么、何时复查：
```

同一任务允许同时处于“结构已独立重建、硬件未观察”。评分再高也不能填补未取得的证据；看过答案也不意味着永久不会，后续可在说明参考条件后重新尝试。

若关键机制仍解释不清，下一次只补这一项前置概念。若只是硬件条件暂缺，保留缺口，不为完成表格编造现象；隔一段时间再尝试时，记录实际间隔，不把固定间隔当作所有人的学习规律。

本节完成后应留下任务卡、首次作答、卡点表、本人修正记录和分层证据表。验收重点是这些记录能否对应同一个任务，并准确区分已有证据与尚未实施的动作。

## 验收

- 每个阶段都有运行或测量证据，不能只附截图。
- 所有关键参数，例如芯片型号、供电、引脚、波特率、采样率和工具版本可定位。
- 当前阶段出现的未知项明确标为“待验证”，没有被写成原理结论。

## 常见失败与修正

- **跟完视频但没有自己的工程**：把每节内容压缩成一个独立最小实验，再自己从空工程复做一次。
- **GPIO 成功就直接堆 OLED、蓝牙和舵机**：每增加一个外设，先建立单独测试，再集成。
- **用“串口没反应”描述问题**：拆成供电、接线、复位、烧录、时钟、波特率、收发方向逐项排查。
- **ADC 只看显示数值**：保存一小段原始采样，才有资格讨论滤波或 FFT。

## 边界

任务表不绑定 51、STM32 或某一款开发板。不同芯片的电压、引脚复用、启动方式和工具链不同；操作前以该型号的官方文档和板卡原理图为准。
