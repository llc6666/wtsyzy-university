# K08 结构体、对齐与内存布局

## 一句话结论

**结构体成员之间可能有编译器插入的填充字节**；成员顺序一变，结构体大小就变。把结构体映射到硬件寄存器时，这条是硬约束。

## 实测：顺序不同，大小不同

```text
1) bad_order  大小=12，成员大小之和=6（差的就是填充字节）
   good_order 大小=8（把大的放前面更省空间）
2) 各成员偏移：
   bad_order:  a@0 b@4 c@8
   good_order: b@0 a@4 c@5
```

两个结构体成员完全一样，只是顺序不同：一个 12 字节，一个 8 字节。

原因：CPU 访问内存时按对齐要求读（4 字节成员通常要放在 4 的倍数地址上），编译器就在中间补空字节。

## 为什么寄存器映射要求「无填充」

```text
3) 全 32 位成员的寄存器组：大小=16，偏移 CRL@0 CRH@4 IDR@8 ODR@12
   每个成员都比前一个大 4，没有填充
```

全是 `uint32_t` 时成员自然对齐，不需要填充，于是 `结构体基址 + 偏移` 正好等于手册里的寄存器地址。这就是 K07 里 `GPIOA->ODR` 能正确工作的前提，也是本知识点存在的理由。

一旦混进 `uint8_t` 成员，就可能出现填充，`->ODR` 就会指向错误的地址。

## 位域能用，但谨慎

```text
4) 位域：sizeof=4 字节，tx_done=1 rx_done=0
```

位域能把几个标志塞进一个整数，但**位的排列顺序由编译器决定**。做通信协议解析（字节流有确定位序）时不要依赖位域；做普通标志位（不关心具体哪一位）时可以省空间。

## 结构体按值传参会整体拷贝

```text
5) 按值传参后：x=1（没变，传的是副本）
   按指针传参后：x=11（变了）
6) 结构体可以直接赋值（数组不行）：q.x=11 q.y=2
```

结构体能整体赋值、能作为返回值，这是它比数组方便的地方；代价是拷贝开销，大结构体要传指针。

## 易错清单（本节）

1. 以为 `sizeof(结构体)` 等于成员大小之和
2. 成员顺序随意排，导致结构体变大
3. 把带填充的结构体直接映射到寄存器
4. 用位域解析有确定位序的协议
5. 大结构体按值传参，拷贝开销大
