# K10 嵌入式实例

形式：**PC 可编译最小例 + 汇编对比**（已实测）+ **SPL 对照片段**（未上板，未验证）。PC 线程示例使用原子变量；`volatile` 的编译器差异由汇编探针展示。

## 一、PC 侧：已验证

### 汇编探针

文件：[volatile-asm-probe.c](volatile-asm-probe.c)

```bash
gcc -std=c17 -O2 -S volatile-asm-probe.c -o volatile-asm-probe.s
```

关键片段（实测，gcc 16.2.0）：

```asm
wait_plain:
	movl	flag_plain(%rip), %eax      ; 只读一次
	testl	%eax, %eax
	je	.L3
	ret
.L3:
	jmp	.L3                             ; 死循环

wait_volatile:
.L6:
	movl	flag_volatile(%rip), %eax   ; 每轮都读
	testl	%eax, %eax
	je	.L6
	ret
```

### 可运行版本

文件：[volatile-demo.c](volatile-demo.c)

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -O2 -pthread volatile-demo.c -o volatile-demo.exe
```

```text
1) 原子版本：循环次数约为 50，flag=1
2) 说明：跨线程通知不能用普通变量或单靠 volatile
```

这里不把循环次数当作固定验收值：线程调度和系统定时精度会让它变化。普通变量跨线程读写属于数据竞争；`volatile` 不能替代原子操作、锁或临界区。**纯空循环的编译器优化差异**由汇编探针单独验证。

## 二、SPL 对照：中断标志的标准写法

```c
volatile uint8_t uart_rx_flag = 0;      /* 中断里置位，主循环里读 */
volatile uint8_t uart_rx_byte = 0;

void USART1_IRQHandler(void)            /* 中断服务函数 */
{
    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET) {
        uart_rx_byte = USART_ReceiveData(USART1);
        uart_rx_flag = 1;               /* 只放标志与数据，不做重活 */
        /* STM32F1：读 DR 清 RXNE；错误标志按参考手册分别处理。 */
    }
}

int main(void)
{
    /* 初始化… */
    while (1) {
        if (uart_rx_flag) {             /* 主循环里处理 */
            uart_rx_flag = 0;
            handle_byte(uart_rx_byte);
        }
    }
}
```

（示意写法，未上板验证；函数名以标准库头文件为准。）

三个要点：

1. `uart_rx_flag` 必须是 `volatile` —— 否则主循环可能永远看不到它被置起
2. 中断服务函数里只做最少的活，处理逻辑放主循环（与上面 K09 说的「中断里不 malloc」是同一条原则）
3. RXNE 在读取接收数据时清除，不套用外部中断的清除方法。这个单字节邮箱会覆盖尚未处理的字节，也存在读取与清标志交错的风险，仅用于说明职责划分；连续接收应使用经过同步验证的队列。

## 三、volatile 的两个边界

### 边界一：不保证原子

```c
volatile uint32_t counter;    /* 中断里 ++，主循环里读 */
```

`counter++` 是「读—改—写」操作，多个写入方可能丢失更新。对 Cortex-M3，满足架构对齐条件的单条 32 位访问与多步操作要区别；不能笼统断言每次读 32 位值都会读到一半。64 位数据和多个字段的一致快照仍需要同步。

正确做法：读之前关中断，读完再开：

```c
uint32_t saved_primask = __get_PRIMASK();
__disable_irq();
uint32_t snapshot = counter;
__set_PRIMASK(saved_primask);   /* 恢复原中断状态，不无条件开启 */
```

此例只讨论同一内核上的中断抢占，不覆盖 DMA 或其他内核并发；变量缩为 8 位也不能让 `++` 自动成为原子操作。

### 边界二：不保证顺序

有先后关系的易变访问受到语言与实现语义约束，不能写成“所有 volatile 访问都可以随意重排”。关键边界是：`volatile` 不建立线程间同步，也不保证普通内存相对易变标志的发布顺序。涉及一致性时应使用平台同步方案；编译器屏障与硬件屏障的职责也要区分。见 [GCC 官方说明](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html)。

## 四、调试时的典型现象

| 现象 | 常见原因 |
| --- | --- |
| 开 -O0 正常，-O2 就失灵 | 缺 `volatile`（或其他优化相关问题） |
| 加了打印就正常，去掉打印就坏 | 打印是外部调用，阻止了优化；或时序被改变 |
| 单步调试正常，全速跑就坏 | 同上，调试器会影响优化与时序 |

第一条几乎就是本知识点的招牌症状。

## 五、把本知识点带回 PC 的做法

遇到「值明明改了却读不到」时，先在 PC 上写个最小复现并看汇编，确认是不是优化问题，再回板子上改。直接上板反复试，是最慢的一条路。
