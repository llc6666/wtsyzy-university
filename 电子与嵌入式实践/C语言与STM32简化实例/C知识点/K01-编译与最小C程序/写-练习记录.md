## hello-world

- 位置：`exercism-c/c-main/exercises/practice/hello-world/` （原始目录路径，随库搬运后失效；题面与参考解副本见本知识点 README 的素材表）
- 要改的文件：`hello_world.c`（骨架当前返回 `"Goodbye, Mars!"`）
- 接口：`const char *hello(void)`
- 题面要点：返回字符串字面量即可，不要 `malloc`，也不要返回局部数组地址

### 验收标准（用例表 + 五类边界）

拿这份标准即可生成测试，不需要原始测试文件。

- 签名：`const char *hello(void)`
- 用例表：

| 输入 | 期望返回 |
| --- | --- |
| 无参数 | `"Hello, World!"` |

- 五类边界：

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 无输入参数 | 固定返回该字符串 |
| 最小 | 最短可能返回值 | 不为空字符串 |
| 最大 | 返回值长度 13 字符 + 结尾 `\0` | 逐字符相等，含空格、逗号与感叹号 |
| 相等 | 连续调用两次 | 内容相同 |
| 非法 | 不允许在返回前 `malloc` 且不释放 | 返回字符串字面量，无分配 |

- 不变量：返回指针在程序整个生命周期内有效；函数无副作用；不得返回局部数组地址

### 复盘中要回答的三问

1. **为什么对**：返回的是字符串字面量，它存放在只读静态区，函数返回后仍然有效；返回局部数组地址则会失效
2. **暴力做法为什么不行**：这一题没有复杂度问题，暴力与否的差别在「返回什么」——返回栈上数组是最常见的错法
3. **哪里最容易错**：把 `char[]` 定义在函数里再返回它的地址

## two-fer

- 位置：`exercism-c/c-main/exercises/practice/two-fer/` （原始目录路径，随库搬运后失效；题面与参考解副本见本知识点 README 的素材表）
- 接口：`void two_fer(char *buffer, const char *name)`
- 题面要点：
  - 有名字 → `"One for Alice, one for me."`
  - 无名字 → `"One for you, one for me."`
  - 结果写进 `buffer`，由调用方提供空间
- 这个接口形状本身就是 C 的惯例：**不返回新分配的内存，而是写入调用方给的缓冲区**，所有权留在调用方，省掉 `malloc/free`

### 验收标准（用例表 + 五类边界）

- 签名：`void two_fer(char *buffer, const char *name)`，官方测试用的缓冲区是 100 字节
- 用例表（取自官方测试）：

| `name` | `buffer` 期望内容 |
| --- | --- |
| `NULL` | `One for you, one for me.` |
| `"Alice"` | `One for Alice, one for me.` |
| `"Bob"` | `One for Bob, one for me.` |

- 五类边界：

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | `name == NULL` | 输出 `One for you, one for me.`（**官方用 NULL 表示无名，不是空字符串**） |
| 最小 | 单字符名字 `"A"` | `One for A, one for me.` |
| 最大 | 名字长度接近 100 字节 | 不得越界写入，超出部分截断，结果仍以 `\0` 结尾 |
| 相等 | 连续两次调用，第二次换名字 | 结果互不被上一次残留影响 |
| 非法 | `name` 为 `NULL` 时 | 不得解引用 NULL；不得 `malloc` |

- 不变量：调用方提供 `buffer`，函数不分配内存；结果始终以 `\0` 结尾；函数无全局状态

> 官方测试文件里后续用例带 `TEST_IGNORE()`，需要手动删掉那一行才会跑下一个用例。自己生成测试时不必保留这个机制，一次跑全部即可。

### 复盘中要回答的三问

1. **为什么对**
2. **暴力做法为什么不行**
3. **哪里最容易错**：`name` 为 NULL 时怎么判断；`buffer` 容量够不够；用 `strcat` 拼接前 `buffer` 是否已被清空
