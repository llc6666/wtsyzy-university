# S02 嵌入式实例

## 一、PC 侧：已验证

文件：[gpio-key-demo.c](gpio-key-demo.c)，输出见 [README](README.md)。

验证的是三件事：配置字段的「先清后写」、位读取的「判非零」、状态机滤抖的迁移逻辑。这些都不依赖真实硬件。

## 二、SPL 对照

标准库把配置过程包成了结构体 + 函数：

```c
GPIO_InitTypeDef gpio;

RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);   /* 1. 开时钟 */

gpio.GPIO_Pin   = GPIO_Pin_5;        /* 2. 填结构体 */
gpio.GPIO_Mode  = GPIO_Mode_Out_PP;  /*    推挽输出 */
gpio.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(GPIOA, &gpio);             /* 3. 写进寄存器 */

/* 读按键：PA0 上拉输入，按下为低 */
GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0);

/* 翻转 LED */
GPIO_WriteBit(GPIOA, GPIO_Pin_5,
              (BitAction)(1 - GPIO_ReadOutputDataBit(GPIOA, GPIO_Pin_5)));
```

（示意写法，未上板验证；标识符以库头文件为准。）

**库函数做的事，正是 PC 示例里那几行位运算**：`GPIO_Init` 内部就是按引脚号算出 CRL/CRH 的位偏移，先清后写；`GPIO_ReadInputDataBit` 内部就是 `IDR & pin` 判非零。

先自己写过一遍位运算，再看库函数就不会觉得它是黑箱。

## 三、输入模式的四种选择

| 模式 | 什么时候用 | 说明 |
| --- | --- | --- |
| 浮空输入 | 外部已有确定电平 | 悬空时电平不定，容易误触发 |
| 上拉输入 | 按键接 GND（常见） | 未按下时为高，按下为低 |
| 下拉输入 | 按键接 VCC | 未按下时为低，按下为高 |
| 模拟输入 | ADC 采集 | 走 ADC 通道，不走数字输入 |

按键最常用**上拉输入**：按键一端接引脚、一端接地，按下把引脚拉低。若配置成浮空，松开时引脚悬空，电平随机，表现为「没按也触发」。

## 四、核对顺序：引脚没反应时

这是本专题最实用的一张表，按从「最常出错」到「最少见」排列：

1. **外设时钟开了吗**（`RCC_APB2PeriphClockCmd`）—— 忘了开，配置写了也没反应
2. **引脚号对不对**（`GPIO_Pin_5` 与实际焊接的引脚）
3. **CRL 还是 CRH**（引脚 0–7 用 CRL，8–15 用 CRH，写错寄存器就配到别的引脚上）
4. **输入/输出方向**（读一个配置成输出的引脚，读到的是输出锁存值，不是外部电平）
5. **上下拉与硬件接法是否配套**
6. **硬件层面**：限流电阻、LED 方向、虚焊、杜邦线接触

第 3 条尤其容易被忽略：`GPIO_Pin_9` 属于 CRH，如果把配置代码写成操作 CRL，现象是「怎么配都没反应」，而且看代码很难发现。

## 五、把本专题带回 PC 的做法

**改引脚、改模式之前，先在 PC 上算一遍位偏移**：

```c
printf("引脚 %d 属于 %s，位偏移 %u\n",
       pin, pin < 8 ? "CRL" : "CRH",
       (pin % 8) * 4);
```

确认偏移和手册一致再去写寄存器。K08 里用 `offsetof` 核对结构体偏移，是同一类检查。
