# 工具权限、风险与人工审批

## 何时用

Agent 需要读取文件、编辑代码、运行命令、发消息、发布内容、访问账号或调用外部系统时使用。核心原则是权限与风险匹配，而不是为了省一步确认而一次性放开全部权限。

## 输入

- 任务契约。
- 当前可用工具和账号范围。
- 每项动作的可逆性、影响对象和成本。

## 步骤

### 1. 给动作分四级

| 级别 | 典型动作 | 默认权限 | 例外 |
| --- | --- | --- | --- |
| L0 只读 | 搜索、查看、解析、计算 | 可直接执行 | 敏感来源仍需最小化读取 |
| L1 本地可回退写入 | 在暂存副本改文档、生成报告 | 可执行后报告 | 覆盖已有文件前先读当前版本 |
| L2 有状态写入 | 提交 Git、更新数据库、改共享文件 | 先展示范围与验证计划 | 明确授权后执行 |
| L3 外部或不可逆动作 | 推送公开仓库、发邮件、下单、删除、支付 | 必须逐次人工确认 | 无 |

实际环境中应再看影响：同样是“写文件”，修改临时草稿和覆盖生产配置的风险不同。

### 2. 为每个工具写能力边界

```markdown
| 工具 | 可做 | 禁止做 | 输入限制 | 输出验证 |
| --- | --- | --- | --- | --- |
| 文件读取 | 读取已授权目录 | 扫描整盘 | 只读候选文件 | 报告读取清单 |
| 文件编辑 | 改暂存副本 | 覆盖未知文件 | 精确路径 | diff + 哈希 |
| Git | 查看状态、创建本地提交 | 未确认的远程推送 | 指定仓库与分支 | diff --check + status |
| 网络 | 查官方来源 | 上传私密资料 | 仅公开信息 | 链接与日期 |
```

工具描述要以“动作和验证”写，不只写工具名称。官方指南建议按工具风险、可逆性、权限和资金影响设置保障措施，并在人类审批点控制高风险操作。[OpenAI 实践指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/)

### 3. 采用“先审计，后最小写入”

执行任何写入前，要求 Agent 输出：目标路径、现有状态、计划改动、影响文件、回退方式、验证命令。先在暂存副本完成，检查差异通过后才写回目标位置。

### 4. 对高风险动作使用双门槛

第一道是结构门槛：目标、范围、账号、对象齐全。第二道是业务门槛：人确认内容、金额、收件人、公开范围或删除列表。任一缺失时停止。

### 5. 管理秘密

密钥、令牌、密码、Cookie、身份证明和未公开业务数据不进入提示词、日志、Git、公开文档或截图。Agent 只应知道“凭据已配置/未配置”和需要调用的权限，不需要看到明文。

## 交付物

- 当前任务的权限分级表。
- 一份工具能力边界表。
- 高风险动作的人工确认记录。

## 验收

- 每项工具动作都有对应的风险级别与验证方法。
- 外部发布、删除、资金和消息发送没有被默认授权。
- 写入前能得到精确路径和变更清单。
- 凭据不出现在日志、补丁、提交记录和公开产物中。

## 常见失败与修正

- 把“能访问”当成“能修改”：单独声明读取、写入、发布三种权限。
- 为了自动化关闭确认：保留审批点，只减少低风险重复动作。
- 在终端输出密钥排错：改为输出变量是否存在、长度或掩码状态。
- 先改后备份：先读取现状，创建暂存副本或可回退提交。
