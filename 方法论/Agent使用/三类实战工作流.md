# 三类实战工作流

## 何时用

你已会写任务契约，但仍不知道怎样把它落到日常工作时使用。以下三类工作流覆盖资料整理、代码改动与研究判断；它们共享同一条底线：先保留证据，再生成结论，最后验收。

## 输入

- 一个已填的任务契约。
- 已授权的来源与工具。
- 一项最小交付物和对应验收。

## 步骤

### 工作流 A：资料到可复用知识

```text
来源清单 → 读取原始材料 → 来源卡 → 提炼一个结论 → 标注边界/反例
→ 更新地图入口 → 链接与隐私检查 → 维护报告
```

**实例任务**：把三份公开课程规则整理为一张来源表和一篇“如何核验课程规则”的方法页。

**验收**：每条规则有链接和日期；方法页有适用条件；从根入口可到达；不含内部截图或个人信息。

**停止条件**：来源只有转述、规则版本冲突、或资料包含未公开内容时，停在来源或待核验区，不晋升结论。

### 工作流 B：代码修改到可交付变更

```text
读 README/规则 → 查看当前代码与测试 → 复述 bug 或需求
→ 在暂存副本最小修改 → 编译/单测/样例运行 → 审阅 diff
→ 经授权提交或发布 → 交接卡
```

**实例任务**：修复一个输入为空时崩溃的脚本，并添加一个回归测试。

**验收**：旧失败样例不再崩溃；正常样例未回归；测试命令和输出已记录；差异只包含授权范围内文件。

**停止条件**：复现不了问题、测试环境不完整、修改会覆盖用户未提交改动，或需要改变公共接口时，先报告证据并等待确认。

### 工作流 C：问题到受边界约束的研究结论

```text
写研究问题 → 收集原始或官方来源 → 区分事实/假设
→ 设计最小验证 → 只改一个核心变量 → 比较结果与反例
→ 标注证据等级和失效条件 → 报告下一步
```

**实例任务**：比较两种学习安排是否会减少遗漏任务。先定义遗漏，再以两周记录对比，而不把一周感受当结论。

**验收**：问题、样本、指标、数据来源、反例和限制都已写出；结论强度与证据相称。

**停止条件**：样本不足、指标未定义、来源不可复查、结果对关键假设敏感时，只能报告“未验证”或“待研究”。

### 统一收尾

三个工作流都要输出：变更或产物清单、验证结果、未解决风险、下一步最小动作。Agent 可以帮助快速执行这些步骤，人仍负责价值判断、风险承担与最终外部动作。

## 交付物

- 一条已选择的工作流。
- 该工作流的任务契约、产物和验收表。
- 一张交接卡。

## 验收

- 流程中存在来源检查、最小实施、独立验证和停止条件四个节点。
- 当前任务只使用一条主工作流，避免把资料、代码与研究的状态混在一起。
- 交付物能由另一个人或 Agent 复跑关键步骤。

## 常见失败与修正

- 直接从“生成答案”开始：先完成来源或当前状态审计。
- 一次改多个变量：锁定一个核心假设，其他条件保持不变。
- 研究结论直接驱动外部行动：加人审与单独的风险检查。
- 工作流过长：删除不能产生新证据、产物或决策的步骤。
