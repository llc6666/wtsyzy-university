# K07 嵌入式实例

形式：**PC 可编译最小例**（已跑通，输出实测）+ **SPL 对照片段**（未上板，未验证；寄存器地址以 RM0008 参考手册为准）。

## 一、PC 侧：用真实变量模拟一块寄存器

文件：[register-address-demo.c](register-address-demo.c)

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic register-address-demo.c -o register-address-demo.exe
```

实测输出（gcc 16.2.0，2026-09-30）：

```text
1) x=42  &x=0000007F1E1FFE1C  p=0000007F1E1FFE1C  *p=42
   改后 x=100
2) q=0000007F1E1FFE10  q+1=0000007F1E1FFE14  相差 4 字节（sizeof(int)=4）
   同一个地址当 uint8_t* 看：+1 前进 1 字节
3) arr[2]=30  *(arr+2)=30  2[arr]=30（下标写法只是语法糖）
4) 基址=00007FF6A80A7020
   CRL 偏移  0 字节 -> 00007FF6A80A7020
   CRH 偏移  4 字节 -> 00007FF6A80A7024
   IDR 偏移  8 字节 -> 00007FF6A80A7028
   ODR 偏移 12 字节 -> 00007FF6A80A702C
5) ODR=0x00000020  CRL=0x00300000
6) 直接按地址操作后 ODR=0x00000000（与 5 的结果一致说明两条路等价）
7) 不要返回局部变量地址，也不要把已 free 的内存地址留着用
```

第 4 步是关键：**结构体成员的地址 = 基地址 + 偏移**。第 6 步说明「用结构体指针访问」和「直接拿地址算」是同一件事的两种写法。

## 二、SPL 对照：真实库做的就是把基址转成结构体指针

标准库头文件里（示意，实际定义以 `stm32f10x.h` 为准）大致是这样的结构：

```c
#define PERIPH_BASE       0x40000000u
#define APB2PERIPH_BASE   (PERIPH_BASE + 0x00010000u)
#define GPIOA_BASE        (APB2PERIPH_BASE + 0x00000800u)   /* 0x40010800 */

typedef struct {
    volatile uint32_t CRL;
    volatile uint32_t CRH;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t BRR;
    volatile uint32_t LCKR;
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)
```

于是：

```c
GPIOA->ODR |= (1u << 5);     /* 等价于往 0x4001080C 这个地址写值 */
```

与 PC 示例第 5 步的 `GPIOA_SIM->ODR |= (1u << 5);` 是**同一行代码**，区别只在 `GPIOA` 指向的是真实寄存器地址。

## 三、不用结构体的写法

也有直接把地址定义成「可读写变量」的写法：

```c
#define GPIOA_ODR (*(volatile uint32_t *)(GPIOA_BASE + 0x0Cu))
GPIOA_ODR |= (1u << 5);
```

对比：

| 写法 | 优点 | 缺点 |
| --- | --- | --- |
| 结构体指针 `GPIOA->ODR` | 偏移由结构体统一管，可读性好 | 依赖结构体成员顺序与手册一致 |
| 直接地址宏 `GPIOA_ODR` | 每个寄存器地址一目了然 | 寄存器多了以后宏名字爆炸 |

两种在 SPL 工程里都能见到，看懂任意一种即可，混用时要小心别把同一寄存器写成两个名字。

## 四、为什么每个成员都带 `volatile`

`volatile` 告诉编译器：这块内存可能在程序没写它的时候变（硬件改的），也可能写它本身有副作用。

没有 `volatile` 会怎样：编译器看到 `while (flag == 0);` 这种循环，可能把 `flag` 读一次放进寄存器，之后不再读内存 —— 于是永远等不到硬件置起的标志。这是 K10 的主话题，这里先记住：**映射硬件寄存器的指针，类型里必须有 `volatile`。**

## 五、结构体映射成立的前提

`GPIOA->ODR` 能正确落在 0x4001080C，靠的是两件事同时成立：

1. 结构体成员顺序与手册的寄存器顺序一致
2. 没有插入编译器自作主张的填充字节（对齐）

第 2 条就是 K08（结构体、对齐与内存布局）要处理的问题。所以 K07 之后紧接 K08：先会用结构体指针，再搞清楚它为什么可靠。

## 六、把本知识点带回 PC 的做法

在 PC 上验证「偏移」这件事：

```c
printf("%zu\n", offsetof(GPIO_TypeDef, ODR));   /* 打印 12 */
```

把打印出来的偏移和手册里的地址偏移对一遍，不一致就说明结构体写错了。这比上板之后发现引脚没反应再回头查要省事得多。
