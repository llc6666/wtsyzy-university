# 枚举：给一组整数常量起名字

## 1. 枚举解决什么问题

枚举把一组有关系的整数常量放进同一个声明里，代码里使用名字而不是裸数字：

~~~c
enum State {
    STATE_IDLE,
    STATE_RUNNING,
    STATE_ERROR
};

enum State state = STATE_IDLE;
~~~

默认第一个枚举常量从 0 开始，后续按 1 递增；也可以显式指定值，后续从最近一个显式值继续递增：

~~~c
enum Pin {
    PIN_A = 3,
    PIN_B,       /* 4 */
    PIN_C = 20,
    PIN_D        /* 21 */
};
~~~

枚举常量是编译期整数常量。枚举类型的兼容整数类型由实现决定，不能把它简单等同为固定宽度的 int。

## 2. C 里为什么经常写 typedef enum

C 的标签名和普通类型名处于不同的命名空间。下面的类型声明需要写 enum State：

~~~c
enum State {
    STATE_IDLE,
    STATE_RUNNING
};

enum State s = STATE_IDLE;
~~~

库代码常把它写成：

~~~c
typedef enum {
    DISABLED = 0,
    ENABLED = 1
} EnableState;

EnableState enabled = ENABLED;
~~~

这让 EnableState 直接成为类型名，也方便把配置项写进结构体成员。

## 3. 嵌入式库里的使用方式

标准外设库常见以下结构：

- 用枚举表示 GPIO 模式、输出速度、标志位和成功/失败状态。
- 用结构体保存多个配置项。
- 让结构体成员类型使用对应枚举，再由库函数把枚举值编码到寄存器字段。

名字给读代码的人看，数值给库函数和寄存器编码逻辑使用。不要因为名字中出现 10MHz、50MHz 就推断变量本身存的是频率；具体值和含义要回到对应版本头文件与参考手册。

## 4. enum、define 和 const 的选择

| 工具 | 适合场景 | 主要边界 |
| --- | --- | --- |
| enum | 一组相关的状态、模式或互斥选项 | C 中对任意整数的限制较弱；底层兼容类型由实现决定 |
| define | 条件编译、宏参数、硬件地址和需要预处理的常量 | 文本替换，没有类型和作用域保护 |
| const 对象 | 单个有类型的只读值 | 在 C 中仍需注意存储和常量表达式语境 |

判断顺序：

1. 先问这些名字是否属于同一个概念集合。
2. 再问它们是否需要类型和调试器可见性。
3. 如果值要直接参与寄存器位域编码，保留与头文件和手册一致的显式值。
4. 不要为了看起来整齐把有硬件意义的编码改成自动递增。

## 5. 状态机和名字表

枚举最实用的落点是状态机：

~~~c
switch (state) {
case STATE_IDLE:
    break;
case STATE_RUNNING:
    break;
case STATE_ERROR:
    break;
default:
    /* 处理越界或未定义状态 */
    break;
}
~~~

也可以把枚举值映射到调试字符串，但数组下标必须先确认范围：

~~~c
static const char *state_name[] = {
    "IDLE",
    "RUNNING",
    "ERROR"
};
~~~

如果枚举值不是连续的 0、1、2，不能直接把它当数组下标。可以改用 switch 或显式映射表。

## 6. 常见错误

| 错误 | 后果 | 修复 |
| --- | --- | --- |
| C 文件里写 State s，但没有 typedef | 类型名不存在 | 写 enum State s，或使用 typedef |
| 把枚举成员当变量赋值 | 枚举常量不能被修改 | 另定义状态变量 |
| 中间插入显式值，却继续假设后面按原序号 | 状态值错位 | 显式列出硬件编码，或重新检查后续值 |
| 任意枚举值直接当数组下标 | 越界或取错字符串 | 确认连续范围后再索引 |
| 用名字推断物理量 | 把标签误当单位或实际数值 | 查看头文件、手册和寄存器字段说明 |
