# 非阻塞主循环：到期检查、按键消抖与任务验收

## 适用任务与交付物

要在同一个主循环里完成两件事：按键每次确认按下翻转一次 LED；光敏模块的数字输出控制蜂鸣器。按住按键时，光敏任务仍要得到执行。

本文补充[红绿灯与心跳的入门模拟](C语言与STM32简化实例/嵌入式专题/S05-非阻塞时基与帧调度/README.md)，重点解决采样消抖、错过周期与边界验收。适用于短任务的裸机轮询；高速脉冲、精确定时输出和长期阻塞操作需要硬件定时器、捕获、DMA 或另外的调度设计。

完成后交付三项：一张任务表、一个通过 PC 自测的程序、一份板上观测记录。当前公开示例只提供逻辑模拟，未编译 STM32 固件、未下载、未验证电气或真实响应时间。

## 1. 先把电平与业务状态分开

准备开发板型号、引脚表、模块供电和原理图。先单独记录“松开/按下时 GPIO 读值”和“明/暗时 DO 读值”，再归一化成 `pressed`、`dark`。不要预设所有模块都低电平有效。3.3 V 输入、公共地、上拉/下拉和输出类型按[光敏 DO 接线检查](光敏模块DO输入：先核对电平再读GPIO.md)核对。

| 任务 | 示例周期 | 状态与动作 | 本轮错过周期时 |
| --- | --- | --- | --- |
| 按键采样 | 5ms | 候选状态、候选开始时刻、已确认状态；确认按下时翻转 LED | 不补读旧样本；重启候选稳定窗口 |
| 光敏 DO 采样 | 100ms | 保存最新 `dark`，更新蜂鸣器输出 | 只读一次当前值，记录跳过次数 |
| 毫秒时基 | 1ms | 中断只累计计数 | 必须排查丢 tick，不把计数直接当墙上时间 |

这里的 5ms、20ms 稳定窗口和 100ms 都是实验参数。按实际抖动、最短有效按压和响应目标调整，不视为器件保证。

## 2. 拆掉四种占住主循环的等待

检查每个任务及其调用链：`Delay_ms(...)`、`while (按键未松开)`、`while (还没到时间)`、带超长超时的串口/I2C/OLED 调用。前三种可以直接让后续任务无法及时执行；第四种即使藏在一个普通函数里也有同样影响。

主循环只做“到期了吗？到期就执行一小步，然后返回”。状态存在结构体里，下一轮继续。时基中断只计数，不放消抖、打印、刷屏或等待。

```c
while (1) {
    uint32_t now = tick_snapshot(); /* 每轮取一次；平台层保证一致读取 */
    service_button(now);
    service_light(now);
    /* 其余函数也必须有可测的执行时间上限。 */
}
```

这段是结构示意，平台函数未定义；可编译实现见下方独立示例。共用时基避免各任务维护不同的时间来源，但各任务仍共享 CPU 时间。一个任务耗时过长会延误其他任务。

## 3. 用经过时间判断到期，明确回绕限制

保存上次参考时刻 `last`，判断：

```c
uint32_t elapsed = (uint32_t)(now - last);
if (elapsed >= period) {
    /* 执行一次短任务，再按选定策略推进 last。 */
}
```

`uint32_t` 计数从最大值回到 0。例如 `last=0xfffffff0`、`now=4`，差值转换回 `uint32_t` 后是 20。不要用 `now >= last + period` 直接比较跨回绕的绝对值。上述规则依赖无符号范围转换与模运算，可查 [WG14 N1570 §6.2.5、§6.3.1.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。

边界必须写清：时间单向推进；`period > 0`；从参考时刻到本次检查的真实 tick 差小于 `2^32`。1ms 计数的完整周期约 49.7 天，暂停这么久后再检查，无法仅用两个 32 位值恢复经过了多少圈。计数复位后应重新初始化任务。

旧例程中的 `(int32_t)(now-target)` 涉及超出有符号范围的转换，在 C17 下结果由实现规定；这种截止时刻比较还要求比较距离小于半个计数周期。不能把一次 GCC 示例通过扩展成对所有 C 平台、所有时间跨度的保证。

## 4. 超时后执行一次，还是把欠账全部补完？

按任务语义选策略，并用迟到输入测试。

| 更新参考时刻 | 行为 | 适用与风险 |
| --- | --- | --- |
| `last = now` | 从实际执行时刻重新等一个周期 | 两次执行至少隔一个周期，长期开销可能导致漂移 |
| `last += period` | 每次补一个周期 | 可能在后续循环连续执行追赶；必须限制补跑数量 |
| `last += (elapsed / period) * period` | 保持原相位，一次执行，跳过旧周期 | 最新传感器读数适用；无法恢复过去没有采到的数据 |

示例选第三种。周期 100ms，上次参考时刻 100ms，下次检查到 450ms：100→200→300→400 共跨过 3 个周期，只执行一次当前采样，记录跳过 2 次，把 `last` 推到 400ms；500ms 再执行。不会拿 450ms 的读数伪装成 200ms、300ms 的历史读数。

按键错过采样时重新开始候选稳定窗口，防止把没有观测的时间当作连续稳定。若系统不断错过采样，按键可能无法确认，这应作为过载故障处理。

## 5. 消抖必须有状态，长按只产生一次事件

每次到期采样执行以下规则，示例启动条件是“已知按键松开”：

1. 当前读值与候选值不同：更新候选值，记下当前时刻。
2. 候选值连续被采样为同一值，距候选开始至少 20ms，且与已确认状态不同：更新已确认状态，生成一次边沿事件。
3. 只有“确认松开→确认按下”才翻转 LED。确认松开仅重新允许下一次按下；持续按住不重复触发。
4. 错过采样就重启候选窗口。开机已经按住要采用明确策略：忽略到松开后才允许按下，或稳定确认后触发；不要依靠未初始化的旧状态。

每 5ms 采一次，首次候选采样到第五次一致采样跨度为 20ms。例：10ms 按下、15ms 松开、20ms 按下、25ms 松开、30ms 后保持按下，则 50ms 才确认按下。确认后继续按住，LED 不再翻转。

“每 20ms 读一次”本身没有以上状态判断，采样点仍可能落在抖动中。“相邻样本相同”也无法证明两次采样之间没有变化。示例过滤的是观测到的短暂变化；对机械接点和电磁干扰的可靠性还要测波形、选参数，必要时加电气滤波。

同理，光敏 DO 每 100ms 读一次只能降低软件更新频率，不能自动建立阈值迟滞。如果蜂鸣器在临界光照下反复变化，应记录 DO 波形、检查比较器阈值/迟滞，或另设软件稳定窗口，并报告增加的响应延迟。

## 6. 先跑 PC 自测，再移植 GPIO

独立代码：[nonblocking-button-light-demo.c](C语言与STM32简化实例/嵌入式专题/S05-非阻塞时基与帧调度/nonblocking-button-light-demo.c)。无第三方驱动，只依赖 C 标准库。代码中 `raw_pressed`、`raw_dark` 已归一化，不能直接把未核对的 GPIO 值传入。

在 PowerShell 切换到该代码目录后运行；要求 `gcc` 已在 PATH。可执行文件写入系统临时目录，失败即停止，防止运行旧产物：

```powershell
$nonblockingExe = Join-Path ([System.IO.Path]::GetTempPath()) ('nonblocking-' + [guid]::NewGuid().ToString('N') + '.exe')
gcc -std=c17 -O2 -Wall -Wextra -Wpedantic -Werror .\nonblocking-button-light-demo.c -o $nonblockingExe
if ($LASTEXITCODE -ne 0) { throw '编译失败，停止运行' }
& $nonblockingExe
if ($LASTEXITCODE -ne 0) { throw '自测失败，停止移植' }
```

自测必须通过：

- 普通启动和 1024 个接近计数回绕的起点，均在相对 50ms、260ms 确认两次按下；长按和松开不多翻转。
- 4096 种长度为 12 的采样序列，与独立的“连续相同样本计数”参考逻辑对拍，覆盖 49,152 次观测。
- 20ms 到期检查跨回绕、100ms 周期相位、错过周期只执行一次。
- 主循环到 450ms 才恢复时按键跳过 89 次采样、光敏跳过 3 次；不补造历史采样。
- 11–14ms 的 4ms 按压没有被 5ms 采样捕获，明确展示轮询遗漏边界。

2026-10-03 本机使用 GCC 16.2.0、C17 与上述严格警告参数编译运行通过，输出：

```text
PASS waveform starts=1025 press_events=2050
PASS debounce sequences=4096 observations=49152
PASS wrap, phase, skipped samples, overload, short-pulse boundary
PASS checks=1335492
```

测试只证明这些输入下的 PC 逻辑，不证明接线正确或硬件时基准确。

## 7. STM32 移植检查

若从未使用 SysTick 的裸机工程开始，确认时钟和 `SystemCoreClock` 后，可参考 [CMSIS SysTick 文档](https://arm-software.github.io/CMSIS_6/latest/Core/group__SysTick__gr.html)配置 1ms 中断，并检查 `SysTick_Config(SystemCoreClock / 1000U)` 的返回值，0 成功、1 失败。这一 API 也可能被厂商实现替换，应回读工程所用头文件。

先搜索工程现有 `SysTick_Handler`、`HAL_IncTick`、RTOS tick 和 `Delay` 实现。已有 HAL/RTOS 时基时使用其受支持的接口；不要再定义同名中断或随意改重装值。教学延时函数如果每次重配 SysTick，也不能与这个连续毫秒时基直接混用。

中断共享变量可声明为 `volatile uint32_t`，但 `volatile` 不提供跨平台的原子性、锁或事件队列。平台层 `tick_snapshot()` 要验证对齐、目标处理器和生成的读指令；扩大到 64 位或跨执行上下文修改复合状态时，重新设计一致读取。主循环独占的任务状态不需要由 ISR 改写。

移植顺序：先验证 tick，再单独验证 GPIO 归一化，再接入按键任务，最后接入光敏任务。不要一次同时改时钟、中断、GPIO 和业务状态机。

## 8. 板上验收与故障定位

| 测试 | 操作与记录 | 通过条件 |
| --- | --- | --- |
| tick | 用测试 GPIO 在每 1000 tick 翻转，测多个周期 | 与时钟配置一致；记录测量仪器与误差，不凭 LED 肉眼估算 1ms |
| 单次按压 | 连续操作至少 20 次，记录事件计数 | 每次符合定义的按下恰好一个事件，松开零个按下事件 |
| 长按 | 按住数秒，同时改变光照 | LED 只翻一次；光敏任务持续更新 |
| 临界光照 | 缓慢经过阈值，记录 DO 和蜂鸣器 | 如有抖动，单独处理阈值/稳定窗口，不声称周期采样已消除 |
| 最短按压 | 从较长按压逐步缩短，记录漏检 | 给出实际可接受最短按压范围；过短脉冲需要捕获方案 |
| 最坏负载 | 加入真实显示、串口、通信，测最大采样间隔 | 达到预定响应目标，跳过次数可解释；超标则拆任务/限时/异步化 |

响应时间包含输入采样等待、消抖确认和调度延误。只在已经给出执行时间、检查间隔和稳定信号条件时讨论上界；单独一个“100ms 周期”不能保证 100ms 内响应。例：显示函数阻塞 200ms 时，其他任务也可能延后超过 100ms。

长时间屏蔽中断可能使基于 ISR 累加的 tick 漏计，因此主循环差值正确不等于真实时间准确。发现异常时依次查时基、最长阻塞调用、输入电平、候选/已确认状态和错过周期计数，不先随意改消抖常数。

记录模板：

```text
板卡/芯片/固件版本：
时钟来源、tick 来源与周期：
输入引脚、有效电平、供电与接线核验：
采样周期、稳定窗口、启动按住策略：
最长主循环检查间隔/最长任务耗时/错过次数：
每次按压的原始采样、候选变化、确认事件：
光敏变化时刻与输出变化时刻、测量方法：
已通过项目、失败项目、下一次只改哪一项：
```
