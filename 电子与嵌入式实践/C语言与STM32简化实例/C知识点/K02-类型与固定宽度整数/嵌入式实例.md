```text

   uint32_t 范围：0 .. 4294967295
```

第 3 行是重点：两个 2³¹ 相加，在 32 位里回绕成 **0**。编译没有任何报错。

## 二、SPL 对照

STM32F103 是 32 位机，寄存器基本都是 32 位，所以库头文件里大量使用固定宽度类型：

```c
uint8_t  byte_from_uart;      /* 串口收到的一个字节，必须正好 8 位 */
uint16_t adc_value;           /* ADC 结果 12 位，用 16 位装 */
uint32_t reg_value;           /* 读一个 32 位寄存器 */
volatile uint32_t *reg;       /* 指向寄存器的指针 */
```

调试打印时配套格式宏：

```c
#include <inttypes.h>
printf("ADC = %" PRIu16 "\r\n", adc_value);
printf("REG = 0x%08" PRIx32 "\r\n", reg_value);
```

如果写成 `printf("%d", reg_value)`，在 `uint32_t` 与 `int` 宽度一致时「看起来能用」，一旦换平台或改类型就出错——而这类错误在嵌入式上表现为串口打印出一串乱码，很难联想到是格式符的问题。

## 三、ADC 例子：为什么 12 位要用 16 位装

STM32F103 的 ADC 是 12 位，结果范围 0–4095。常见写法：

```c
uint16_t adc = ADC_GetConversionValue(ADC1);   /* 返回值本身就是 16 位 */
float voltage = (float)adc * 3.3f / 4096.0f;
```

要点：

- 不要用 `uint8_t` 装 12 位数据（装不下，会截断）
- 12 位数据参与乘除前先提升类型，否则中间结果可能溢出
- 浮点在裸机上开销大，很多场合用定点（如放大 1000 倍用整数表示毫伏）

## 四、把本知识点带回 PC 的做法

在 PC 上先验证「这个类型装不装得下」：

```c
printf("%zu\n", sizeof(uint32_t));   /* 期望 4 */
printf("%" PRIu32 "\n", UINT32_MAX); /* 期望 4294967295 */
```

估算任何计数器的上界时，先算「最大值是多少」，再去选类型，而不是先写 `int` 再看结果对不对。
