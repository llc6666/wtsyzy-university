# 算法学习闭环：从单题解出到同类迁移

> 一道题通过样例，只能说明当前实现暂时没有被这些样例击穿；要判断自己是否学会了一类知识，必须继续完成变式、边界、间隔重写和复盘。

## 适用场景

当你出现以下情况时，使用这套流程：

- 看题解时觉得会做，合上题解却写不出来。
- 同一道题能做，换一个问法就不会。
- 样例全部通过，但提交或边界测试仍然出错。
- 题单越做越长，却说不清已经掌握了哪些能力。
- 学习计划列了很多专题，却没有客观的完成标准。

这套流程面向有明确输入、程序或推导结果的算法学习。它不适合单纯背诵定义，也不能替代完整课程。

## 你需要准备什么

| 材料 | 用途 | 最低要求 |
| --- | --- | --- |
| 一道代表题 | 暴露这一类问题的核心动作 | 能拿到完整题面、输入输出和约束 |
| 两道不同表面形式的变式 | 检查迁移能力 | 不能只是把样例数字换掉 |
| 编译器或解释器 | 验证实现 | 能记录版本和实际命令 |
| 测试记录 | 证明边界被检查 | 每条数据注明它要击穿什么错误 |
| 错误记录 | 防止同一类错误重复出现 | 写清输入、错误输出、正确结果和修正规则 |

开始前先建立一张任务卡：

```text
知识类别：
代表题：
核心动作：
输入规模：
目标复杂度：
最终产物：
完成判据：
```

## 先按底层动作分类

不要按题目标题记忆算法。先问“题目要求我反复做什么动作”，再把题目归类。下面只是分类示例，实际题目可能同时涉及多个类别：

| 底层动作 | 常见信号 | 首先检查什么 |
| --- | --- | --- |
| 周期或过程模拟 | 题面逐步描述状态变化 | 能否用除法或取模批量跳过 |
| 不变量与奇偶性 | 一次操作同时影响多个元素 | 哪个量的奇偶或模值不变 |
| 最终状态化简 | 问达到某个关系的最少操作 | 能否直接描述最终状态 |
| 二分与单调性 | 求最小或最大的可行值 | 可行性是否随答案单调 |
| 贪心与证明 | 每一步都要选择一个动作 | 局部选择能否通过交换或反例检验 |
| 预处理 | 多次询问同一结构 | 能否先算中间量再回答 |
| 逆序处理 | 全局更新会覆盖之前的工作 | 倒着处理时是否只需保留后缀信息 |
| 递归与搜索 | 选择、回溯、连通或最短路 | 状态、出口、访问标记在哪里 |

分类的结果不是答案。它只决定你要检查哪种不变量、复杂度或边界。

## 四个学习档位

下面的 T1 至 T4 是记录学习证据的自定义档位，不是平台认证，也不等于正式能力等级。

| 档位 | 说明 | 必须留下的证据 |
| --- | --- | --- |
| T1 读懂 | 能用自己的话复述目标、输入、输出和约束 | 题意卡与至少一个手算样例 |
| T2 想出 | 能写状态、判据、复杂度，并说明为什么成立 | 推导记录和一个反例检查 |
| T3 写出 | 能不看旧实现独立编码并通过自测 | 源码、编译命令、测试输出 |
| T4 顶住 | 能在变式、极端数据或时间限制下保持正确 | 变式结果、压力测试或限时记录 |

档位只描述一题走到哪里。一个知识类别是否完成，要看下一节的五条验收线。

## 五条完成判据

### 1. 主题独立完成

不看题解和旧代码，独立写出以下四项：

1. 状态变量及其含义。
2. 解法或判据。
3. 最坏时间、空间复杂度。
4. 可以运行的实现。

如果只能复述题解，保留在 T1 或 T2，不要标记为“已掌握”。

### 2. 至少两道不同变式

变式要改变题面的表面形式，但仍然训练同一个底层动作。例如：

- 周期事件：从“下一班车”换成“环形位置跳转”。
- 二分：从有序数组找边界换成对答案二分，并重新设计 `check`。
- 不变量：从翻转整数符号换成翻转二进制位，同时检查操作范围是否改变。
- 预处理：从一维连续段换成二维四方向连续段。

只改数字、变量名或输入顺序，不算独立变式。每道变式都要写“它改变了什么、保留了什么”。

### 3. 五类边界测试

至少准备以下五类数据，并逐条说明是否适用：

| 边界类型 | 要检查的风险 | 例子 |
| --- | --- | --- |
| 最小值 | 空输入、单元素、下标或初始化错误 | `n = 1`、只有一个节点 |
| 最大值 | 溢出、内存和时间超限 | 最大规模、最大数值 |
| 相等值 | 严格小于与小于等于混淆、并列处理错误 | 两个答案相同 |
| 逆序或反向 | 错把输入顺序当成有序性、扫描方向错误 | 降序数组、从末尾开始的事件 |
| 答案为零 | 把“无操作”误判为异常 | 初始状态已经满足目标 |

“不适用”可以作为结论，但必须写出原因。结果与错误版本完全一样的数据，不能算有效边界测试，因为它没有区分任何规则。

### 4. 间隔重写

完成代表题后至少间隔一天，关闭旧代码和题解，重新写一遍核心实现。重写前只允许看题面和约束。

重写后逐项比较：

- 状态是否仍然定义正确。
- 循环边界是否改变。
- 类型和复杂度是否仍满足约束。
- 是否遗漏原先暴露过的错误。

如果重写失败，记录失败位置，回到最小示例修正，不要直接复制旧实现。

### 5. 口头复盘三问

每道代表题和变式都要能回答：

1. 为什么这个方法正确？
2. 暴力方法为什么不够快或不够稳？
3. 哪里最容易错？哪组数据能把这个错误打出来？

第三问必须指向具体错误和具体数据。“注意边界”“要认真检查”不构成复盘。

## 一轮的实际执行顺序

### 第 0 步：先写完成线

在打开题解前写下本轮的目标，例如：

```text
目标：掌握“找第一个满足条件的位置”这一类二分。
代表题：一个有序数组的下界定位。
完成线：独立实现 + 两道不同变式 + 五类边界 + 间隔重写 + 三问复盘。
```

目标越具体，越容易判断什么时候停止扩展。

### 第 1 步：读题并写模型

只做四件事：

1. 圈出输入规模和时限。
2. 写出状态变量，不要先写代码。
3. 手算一个普通样例和一个极端样例。
4. 估算暴力复杂度，判断它是否可行。

若连状态都说不清，不要急着抄模板。先把题面中的名词翻译成可变化的数据。

### 第 2 步：写判据与证明骨架

用下面的句式压缩思路：

```text
我维护：
每次操作改变：
始终不变的是：
因此目标答案由：决定。
复杂度为：，因为：。
```

需要公式时，先写出公式依赖的题面条件。例如“每次修改一个位置”和“目标变成等差”是两个不同条件，换掉其中任意一个，公式都可能失效。

### 第 3 步：独立实现

关闭旧代码后完成最小版本。第一版只解决题目，不提前加入无关封装、复杂优化或大量模板。

编译时固定记录：

```text
编译器：
版本：
命令：
退出码：
```

代码能编译，不等于算法正确；代码能通过样例，也不等于边界正确。

### 第 4 步：按目的测试

每条测试记录四列：

| 输入 | 预期结果 | 实际结果 | 它要击穿的错误 |
| --- | --- | --- | --- |
| 具体数据 | 手算或可靠来源 | 程序输出 | 例如“漏掉并列最小编号” |

优先加入“正确版和错误版输出不同”的数据。若测试结果相同，说明它不能验证那条规则。

### 第 5 步：做两道变式

每道变式先写一行对照：

```text
保留的底层能力：
改变的题面条件：
原判据是否仍成立：
如果不成立，哪一步需要重推：
```

变式的意义在于迫使你重新确认前提，而不是让你把模板改几个变量名。

### 第 6 步：隔天重写并复盘

重写结束后，把结果汇总到一张类别卡：

```text
类别：
代表题：
变式 1：通过 / 失败，原因：
变式 2：通过 / 失败，原因：
五类边界：完成 / 有不适用项，说明：
隔天重写：通过 / 失败，原因：
复盘三问：
仍未解决：
下一步：继续本类 / 降低难度 / 暂停扩展
```

## 最小可验证示例

下面的程序只演示一个训练动作：在有序数组中找第一个大于等于目标值的位置。它不是整套学习流程的替代品，作用是示范“实现、边界和预期输出”应如何落盘。

```cpp
#include <cassert>
#include <iostream>
#include <vector>

int first_not_less(const std::vector<int>& values, int target) {
    int left = 0;
    int right = static_cast<int>(values.size());

    while (left < right) {
        const int middle = left + (right - left) / 2;
        if (values[middle] >= target) {
            right = middle;       // middle 可能就是最左答案，不能丢掉
        } else {
            left = middle + 1;    // middle 已经不够大，答案只能在右侧
        }
    }
    return left;                   // 返回 values.size() 表示不存在
}

int main() {
    const std::vector<int> values{2, 5, 5, 12, 19};

    assert(first_not_less(values, 1) == 0);   // 小于全部元素
    assert(first_not_less(values, 5) == 1);   // 重复值取最左位置
    assert(first_not_less(values, 12) == 3);  // 精确命中
    assert(first_not_less(values, 20) == 5);  // 不存在，返回尾后位置

    std::cout << "boundary checks passed\\n";
}
```

编译和运行：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -g "C++学习笔记/代码示例/算法学习闭环-下界定位.cpp" -o lower_bound_demo
./lower_bound_demo
```

预期输出：

```text
boundary checks passed
```

这个示例至少验证了四件事：目标小于全部元素、重复元素取最左位置、精确命中和目标大于全部元素。若把 `right = middle` 错改成 `right = middle - 1`，或者把 `left = middle + 1` 错改成 `left = middle`，边界测试和循环终止性就需要重新检查。

## 交付物清单

一轮合格的算法学习至少留下：

1. 类别卡：说明目标、前提、完成判据。
2. 代表题实现：包含编译命令和运行结果。
3. 两道变式记录：说明题面变化和判据变化。
4. 边界测试表：每条数据有预期结果和测试目的。
5. 错误记录：保留至少一个真实失败或反例。
6. 间隔重写结果：注明是否独立完成。
7. 三问复盘：尤其写出最容易错的地方。

## 验收标准

只有同时满足以下条件，才把一个类别标记为“本轮完成”：

- 能在不看旧实现时写出代表题。
- 至少两道变式不依赖原题的代码结构。
- 五类边界均已测试，或明确解释不适用原因。
- 至少一次间隔重写通过。
- 能回答复盘三问，且第三问包含具体数据。
- 测试、复杂度和类型结论有实际记录。

若只完成代表题，记录为“单题完成”；若变式或重写失败，记录缺口，不用“基本掌握”掩盖未完成项。

## 常见失败与修正

| 失败表现 | 根因 | 修正动作 |
| --- | --- | --- |
| 一直看题解，迟迟不落码 | 学习目标停留在理解 | 先写最小实现，再回看题解补差异 |
| 只刷同一种题 | 记住了表面模板 | 更换题面，保留同一底层动作 |
| 只测官方样例 | 样例没有覆盖关键分支 | 为每条规则单独造能区分对错的数据 |
| 用“样例全过”证明正确 | 缺少证明和反例 | 写成立理由，再主动构造错误规则的反例 |
| 题单不断扩张 | 用新题逃避当前欠账 | 先完成当前类别的五条验收线 |
| 把计划写成成果 | 把意图当证据 | 只把源码、输出、测试和反馈写入成果栏 |
| 复杂度只写一个大 O | 没有对照约束规模 | 把输入上界代入，估算实际运算量与内存 |

## 边界与不适用情况

- 这套流程衡量的是“能否独立完成并复现一个窄范围任务”，不能推出“掌握整个算法领域”。
- 题面、数据范围或操作条件变化后，原公式和证明必须重新核对。
- 五类边界是检查框架，不是每道题都能机械套用；不适用项必须说明原因。
- 代码通过本地测试，不能替代平台评测、代码审查或真实系统测试。
- 复杂度中的“通常可行”受语言、硬件、常数和时限影响，最终以题目约束和实测为准。
