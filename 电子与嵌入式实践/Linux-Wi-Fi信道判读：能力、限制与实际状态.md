# Linux Wi-Fi 信道判读：能力、限制与实际状态

网卡列表里有某个频点，但接口没在用，或接入点界面里选不了。先回答三个问题：**物理网卡列出了什么、此刻哪些条件限制这个用法、接口实际跑在哪个信道**。这三条证据分别来自不同输出。

## 先固定设备和场景

准备一台有权管理的 Linux 或 OpenWrt 设备，或一份脱敏的既有输出。先写清角色（客户端或接入点）、目标频点和频宽，分开记预期值与当前观察值。仅凭「支持 5 GHz」无法得出某个信道、频宽和角色组合可用。网卡、驱动、固件和 Linux 应用到设备的规则都可能影响结果。

## 按顺序读取，不改配置

| 顺序 | 查看什么 | 抄哪些字段 |
| --- | --- | --- |
| 1. 找对网卡 | `iw dev` 列出无线接口；按 `phy#` 归组 | 目标接口、所属物理网卡、接口类型（如 `managed` 或 `AP`） |
| 2. 查此时的频点 | `iw list`；只读属于该物理网卡的 `Wiphy` 段 | 目标频率（MHz）、信道号、当前标志和频宽限制；频点未列出与列出但禁用分别记录 |
| 3. 读规则状态 | `iw reg get`；同时留意全局与单独的设备条目（若有） | 当前显示的监管域、相关频率范围与限制；不要用另一张网卡的结果替代 |
| 4. 看实际运行 | 回到 `iw dev` 的目标接口；客户端可用 `iw dev 接口名 link` 看关联状态与频率 | 此刻的信道或频率、实际宽度（若报告）、客户端是否关联；未显示的字段填「未知」 |

把 `接口名` 换成第一步实际看到的名字。若命令不可用，先记录系统、驱动版本和缺失的字段；可转看设备界面已有信息或用既有输出练习。没有必要为了填表改监管域、功率、信道或服务状态。

## 三个常见误读

| 看到什么 | 能判断什么 | 先别推断什么 |
| --- | --- | --- |
| 目标频点出现，标了 `disabled` | 该网卡当前把该频点标为禁用 | 只凭这一行无法判断是硬件、驱动还是规则导致 |
| 出现 `no IR`，或提示需要雷达检测 | `no IR` 限制主动发起发射（例如发送探测请求或信标）；雷达检测是另一项条件。要启动 AP 时，需按角色、设备状态与当地规则核对 | 这两项不是同一种限制；能看到附近信号也不能证明可在这个频点启动自己的 AP |
| 频点在列表里，且没有看到 `disabled` | 它通过了「没有显式标为禁用」这一项 | 不代表目标频宽或角色可用。宽信道还要看涉及的其他频点和频宽限制；实际是否使用要查接口 |

`iw list` 中的功率上限、管理界面填写的值和天线端的实际辐射功率各有口径。没有对应测量记录，功率栏只抄「来源 + 字段名 + 单位」，不要把上限写成实测值。当地频谱规则及设备的使用条件另行查对应主管部门与设备资料；系统输出只说明软件当时报告的状态。

## 留下一张能复查的记录卡

```text
采集时间／系统与驱动版本：
接口与物理网卡／客户端或 AP：
目标频段、频点、频宽与用途：
网卡列出该频点吗？标志和限宽：
全局／设备规则（若分别显示）：
接口当前实际频点、频宽和关联状态：
能确认的一句／仍未知的一项／下一步查什么：
```

**读表示意（非实测）：** 某机器的目标接口属于 A 网卡，目标频点在 A 的清单中标为禁用，接口实际运行在另一个频点。记录写「A 当前未在目标频点工作，且该频点被 A 标为禁用；限制原因待查。」B 网卡即使列出同一频点，也不能填到 A 的记录中。

交接时让另一位读者指出「接口对应哪张网卡」「目标频点在哪一行」「实际状态来自哪份输出」。最后只补最先缺失的一项。准备分享时，删去真实 SSID、MAC、序列号和内部网络细节。
