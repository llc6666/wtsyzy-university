# I2C 总线排障：开漏、上拉与波形核对

> 目标：把 I2C 通信失败拆成电气、地址、时序和软件状态四层，先用波形确认总线发生了什么，再修改驱动。

## 何时使用

- OLED、传感器或其他 I2C 器件无应答、读到全 `0` 或全 `1` 时。
- 软件模拟 I2C 与硬件 I2C 表现不一致时。
- 总线偶发卡死、速度不稳定或接入多个器件后失败时。

## 输入

1. MCU、从设备型号和数据手册。
2. SDA、SCL、GND、电源和上拉电阻的实际接线。
3. 目标地址格式：7 位地址、读写位和地址扫描结果。
4. 总线速率、时序配置、逻辑分析仪或示波器。

## 机制

I2C 线通常使用开漏或开集电极结构，器件主动拉低总线，逻辑高电平由上拉电阻提供。STM32 的 I2C 引脚需要按具体系列配置为开漏，并由外部上拉形成高电平；上拉值、电容和总线速度共同影响上升时间。[ST 官方 I2C 资料](https://www.st.com/content/ccc/resource/training/technical/product_training/2d/5a/12/09/9e/7e/42/b3/STM32L4_Peripheral_I2C.pdf/files/STM32L4_Peripheral_I2C.pdf/_jcr_content/translations/en.STM32L4_Peripheral_I2C.pdf)

## 操作步骤

### 1. 断电核对电气连接

确认 MCU 与从设备共地，供电电压兼容，SDA 与 SCL 没有接反，线上确实存在上拉。不要把推挽输出直接并到另一器件可能拉低的总线上。上拉电阻不能脱离总线电容和目标速率单独讨论。

### 2. 先测空闲电平

总线空闲时 SDA、SCL 都应回到逻辑高电平。若一直为低，分别断开从设备和主控端，定位是哪一端拉低；检查复位状态、短路、错误电平和从设备是否卡在半帧。

### 3. 抓一帧最小通信

只保留一次地址加一次读或写，抓取起始、地址、应答、数据和停止条件。记录：

| 项目 | 实际值 |
| --- | --- |
| SDA/SCL 空闲电平 | |
| 总线速率 | |
| 地址与读写位 | |
| ACK/NACK 位置 | |
| 数据字节 | |
| 起始与停止是否完整 | |

### 4. 按证据分支

- **没有时钟**：查 GPIO 复用、外设时钟、启动调用和代码是否阻塞在前一步。
- **有时钟但没有 ACK**：查地址格式、供电、复位、器件型号和 SDA/SCL 接线。
- **有 ACK 但数据错误**：查寄存器地址、读写方向、重复起始、时序和数据手册要求。
- **波形上升太慢或边沿变形**：查上拉、总线电容、线长、电平转换器和速率。

### 5. 只改一个因素再复测

每轮只改变地址、速率、上拉、驱动模式或初始化顺序中的一个因素。保存波形和代码提交号，避免“改了很多后突然能用”却无法知道真正原因。

## 交付物

- 实际接线和器件版本表。
- 一帧最小通信的波形或逻辑分析记录。
- 地址、ACK/NACK、速率和上拉信息。
- 一条已证实或已排除的故障假设。

## 验收

- 空闲电平、起始、地址、ACK、数据和停止条件都能在波形中定位。
- 读写地址格式与器件资料一致。
- 同一硬件、同一固件连续复测至少 20 次，结果稳定或失败模式明确。
- 软件模拟 I2C 与硬件 I2C 的差异被记录，不能混用未经验证的时序参数。

## 常见失败与修正

- **看到地址扫描不到就改一堆代码**：先抓波形，区分没有时钟、无应答和地址错误。
- **使用内部上拉就默认足够**：按具体 MCU 和总线条件核对上升时间，必要时使用合适的外部上拉。
- **把 8 位地址直接当 7 位地址**：先确认库函数要求的地址格式。
- **总线卡死后只重启应用**：明确复位从设备、释放 SDA/SCL 和重新初始化外设的策略。

## 边界

不同 STM32 系列的 I2C 外设、GPIO 电气特性和配置界面不同；上拉阻值不能从一个系列或一块开发板直接照搬。高速、长线、多器件或不同电压域场景需要单独做信号完整性评估。
