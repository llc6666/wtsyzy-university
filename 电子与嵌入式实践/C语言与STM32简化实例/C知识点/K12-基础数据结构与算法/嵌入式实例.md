## 二、SPL 对照：中断写、主循环读

串口接收最典型的用法：中断里把收到的字节塞进缓冲，主循环里慢慢处理。

```c
volatile ringbuf_t g_uart_rx;          /* 共享的接收缓冲 */

void USART1_IRQHandler(void)
{
    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET) {
        uint8_t b = USART_ReceiveData(USART1);
        rb_write(&g_uart_rx, b);       /* 只做写入，不做解析 */
        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}

int main(void)
{
    /* 初始化… */
    while (1) {
        uint8_t b;
        while (rb_read(&g_uart_rx, &b)) {
            handle_byte(b);            /* 处理放在主循环 */
        }
    }
}
```

（示意写法，未上板验证。）

三个要点：

1. **`write` 与 `read` 分居两侧**：中断只写、主循环只读。若两边都写或都读，`head`/`tail`/`count` 的一致性就要额外保护
2. **写满时的策略**：示例里是拒绝写入（丢弃新数据）。也可以改成覆盖最旧的，取决于业务
3. **与 K10 的关系**：这里的缓冲结构本身不是 `volatile`（它是结构体，靠函数调用访问），但**中断标志**必须 `volatile`；如果主循环和中断共享一个计数变量，那个变量要按 K10 处理

## 三、为什么容量常取 2 的幂

容量是 2 的幂时，绕回可以用位运算代替取模：

```c
rb->head = (rb->head + 1) & (RB_SIZE - 1);    /* RB_SIZE 为 2 的幂时等价于 % RB_SIZE */
```

在没有硬件除法器的 MCU 上，`%` 是软件实现的除法，代价不小。这是嵌入式里很常见的一处优化。

（代价是：容量必须是 2 的幂，改容量时要同步改掩码。）

## 四、二分查找在嵌入式里的用处

典型场景是**查表**：比如把 ADC 采样值映射到温度，若有一张按采样值排好序的表，就可以二分查找。

```c
/* 表必须有序，这是一条硬前提 */
static const struct { uint16_t adc; int16_t temp; } table[] = {
    { 100, -100 }, { 500, 0 }, { 900, 100 },   /* 示例数据 */
};
```

如果表很小（十几个元素），顺序查找往往更简单可靠；表大了再上二分。**先量清楚数据规模，再决定用什么**，比一上来就套算法重要。

## 五、把本知识点带回 PC 的做法

环形缓冲这种容易写错边界的结构，先在 PC 上把下面几件事跑一遍：

1. 写满后再写（应拒绝或覆盖，按约定）
2. 读空后再读（应返回失败）
3. 连续写入跨越数组末尾（确认绕回正确）
4. 交替读写多次（确认 head/tail/count 始终一致）

这四步在 PC 上几分钟能验证完；在板子上靠串口打印验证同样的逻辑，可能要一晚上。
