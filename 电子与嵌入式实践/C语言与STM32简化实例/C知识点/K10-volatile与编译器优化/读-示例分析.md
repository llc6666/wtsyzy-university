**教程里那句「编译器可能会对程序进行优化，使 *p 只被取一次」，对应的就是 `movl` 从循环内挪到循环外。**

## 三、读汇编要抓的三条指令

| 指令 | 含义 |
| --- | --- |
| `movl 变量(%rip), %eax` | 从内存读一个 32 位值到寄存器 |
| `testl %eax, %eax` | 测试它是不是 0 |
| `je 标号` / `jmp 标号` | 是 0 就跳 / 无条件跳 |

看优化是否发生，就数 `movl 变量` 出现几次、在不在循环体里。这个技巧对排查「优化导致的偶发故障」很有用：不必上板，先看汇编。

## 四、汇编观察与并发正确性分开验证

[volatile-demo.c](volatile-demo.c) 当前使用原子变量完成跨线程通知。普通变量或仅带 `volatile` 的变量被两个线程并发读写，仍会产生数据竞争；偶尔正常退出不能证明代码正确。旧版非原子线程演示已移除。

汇编探针只用于比较编译器生成的访问指令，不把它直接作为可运行的线程同步方案。外部调用可能影响优化，但不提供同步保证。
