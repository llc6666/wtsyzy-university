## linked-list

- 位置：`exercism-c/c-main/exercises/practice/linked-list/` （原始目录路径，随库搬运后失效；题面与参考解副本见本知识点 README 的素材表）
- 接口见 `linked_list.h`（读码分析在 [读-示例分析.md](读-示例分析.md)）
- 题面要点：实现 `list_create / list_count / list_push / list_pop / list_unshift / list_shift / list_delete / list_destroy`
- 这一题同时是 K09（动态内存与所有权）的练习场：每个节点都是 `malloc` 出来的，谁释放、什么时候释放要写清楚

### 验收标准（用例表 + 五类边界）

- 签名（官方 `linked_list.h`）：`list_create / list_count / list_push / list_pop / list_unshift / list_shift / list_delete / list_destroy`
- 用例表：

| 操作序列 | 期望 |
| --- | --- |
| 新建 | `list_count = 0` |
| push 11 | count = 1，pop 得 11 |
| push 11、push 22 | shift 得 11（最旧），count = 1 |
| unshift 11、push 22 | count = 2，pop 得 22，shift 得 11 |
| push 11、22、33 后 delete 22 | 剩 11、33，count = 2 |

- 五类边界：

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 空链表上 `pop` / `shift` | 需明确定义（不崩溃；返回值自行约定并在注释写明） |
| 最小 | 单节点链表 | 删除后 count = 0，头指针回到空状态 |
| 最大 | 连续 push 多个节点 | count 与逐个 pop 的顺序完全对应 |
| 相等 | 链表中有重复元素 | `list_delete` 只删第一个匹配项（头文件注释：deletes **a** node） |
| 非法 | `list_destroy` 之后继续使用 | 未定义；头文件已声明「调用后指针悬空」，不得再访问 |

- 不变量：count 始终等于实际节点数；push/pop 在尾部、unshift/shift 在头部，两者不能混为一谈；`list_destroy` 必须释放全部节点

### 复盘三问（做完填）

1. **为什么对**
2. **暴力做法为什么不行**：用数组实现也能过测试，但 `list_destroy` 的语义和指针操作就练不到了；这一题的练习目标是**指针与所有权**，不是功能
3. **哪里最容易错**：空链表上 `pop`；删除头节点时忘了更新头指针；`list_destroy` 后指针未置空

## list-ops

- 位置：`exercism-c/c-main/exercises/practice/list-ops/` （原始目录路径，随库搬运后失效；题面与参考解副本见本知识点 README 的素材表）
- 题面要点：按给定的函数式操作名实现链表变换
- 练习重点：`list_t` **不是链式节点**，而是 `{ size_t length; list_element_t elements[]; }` 的柔性数组结构（连续内存）。所以「新建列表」本质是算好 `sizeof(list_t) + n * sizeof(list_element_t)` 一次 `malloc` 出来——这是本知识点指针与内存计算的核心练习
- 涉及函数指针：`filter_list(list, bool (*filter)(list_element_t))`、`map_list`、`foldl_list`、`foldr_list`

### 验收标准（用例表 + 五类边界）

- 签名（官方 `list_ops.h`）：`new_list / append_list / filter_list / length_list / map_list / foldl_list / foldr_list / reverse_list / delete_list`
- 用例表：

| 操作 | 期望 |
| --- | --- |
| `new_list(3, {1,2,3})` | length = 3 |
| `append_list({1,2}, {3})` | `{1,2,3}` |
| `filter_list({1,2,3}, 偶数)` | `{2}` |
| `map_list({1,2,3}, 平方)` | `{1,4,9}` |
| `foldl_list({1,2,3}, 0, 加)` | 6 |
| `foldr_list({1,2,3}, 0, 减)` | 与 foldl 结果不同（顺序敏感） |
| `reverse_list({1,2,3})` | `{3,2,1}` |

- 五类边界：

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 空列表（length = 0） | `length_list = 0`；reverse、filter、map 都得到空列表，不崩溃 |
| 最小 | 单元素列表 | fold 返回 initial 与该元素的运算结果 |
| 最大 | 较长列表 | 柔性数组分配尺寸计算正确，不越界写 |
| 相等 | `foldl` 与 `foldr` 用同一个加法 | 结果相同（加法可交换）；换成减法则不同，用来验证顺序 |
| 非法 | `filter` / `map` 传入 NULL 函数指针 | 不得调用；需判空或直接约定由调用方保证 |

- 不变量：输入列表不被修改（这些操作返回新列表）；每个新列表都要有对应的 `delete_list`；`length` 字段与实际元素个数一致

### 复盘三问（做完填）

1. **为什么对**
2. **暴力做法为什么不行**
3. **哪里最容易错**：原地修改 vs 新建链表两种语义混在一起

## circular-buffer

- 位置：`exercism-c/c-main/exercises/practice/circular-buffer/` （原始目录路径，随库搬运后失效；题面与参考解副本见本知识点 README 的素材表）
- 接口：**头文件为空，自己设计**
- 设计前先回答三个问题（写在代码注释里）：
  1. 容量固定还是可变？（嵌入式里固定）
  2. `head == tail` 时如何区分满与空？（常用做法：留一个空位，或额外记一个计数）
  3. 写满是覆盖旧数据还是返回错误？（串口收数常用覆盖，业务数据常用报错）
- 这一题做完后，把结论带到 K12 的串口收发场景
- 参考实现用的是柔性数组结构（`{ head, tail, count, capacity, values[] }`），写入失败通过返回值 + `errno` 表达（`ENOBUFS` 满、`EINVAL` 空指针）

### 验收标准（用例表 + 五类边界）

- 接口（自己设计，可参考官方）：`new_circular_buffer(capacity)`、`write`、`overwrite`、`read`、`delete_buffer`
- 用例表（容量 7 为例，取自题面）：

| 操作序列 | 期望 |
| --- | --- |
| write 1, 2, 3 | read 依次得 1, 2, 3（最旧先出） |
| 写满 7 个后 write | 失败（题面：报错，写被阻塞），已有数据不被破坏 |
| 满时 `overwrite` A、B | 覆盖最旧的两个，之后最旧的是原来的第三个 |
| 读出两个后再 overwrite | 覆盖的是当前最旧的元素 |

- 五类边界：

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 空缓冲 `read` | 返回失败，不返回脏数据 |
| 最小 | capacity = 1 | 写一个后即满；`overwrite` 覆盖唯一元素 |
| 最大 | 写满 capacity 个 | 再 write 失败；count 不超过 capacity |
| 相等 | 连续写入相同值 | 能按原顺序全部读出，不被判为「空」 |
| 非法 | 传入 NULL 缓冲指针 | 返回失败，不崩溃 |

- 不变量：`count <= capacity`；`head`/`tail` 绕回用取模实现；`read` 得到的永远是**最旧的未读元素**；满与空不能靠 `head == tail` 单独区分（要么留一个空位，要么额外记 count）

### 复盘三问（做完填）

1. **为什么对**
2. **暴力做法为什么不行**
3. **哪里最容易错**：`write` 到满缓冲的边界；`read` 空缓冲的返回值怎么表示错误
