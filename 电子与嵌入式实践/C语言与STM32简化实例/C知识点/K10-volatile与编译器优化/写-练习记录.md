## 练习一：标志等待

### 任务

写一个 `wait_for_flag()`，在一个标志被置起前一直等待。分别写成两个版本：

```c
volatile int flag_a;
int          flag_b;

void wait_a(void) { while (flag_a == 0) { } }
void wait_b(void) { while (flag_b == 0) { } }
```

生成汇编并检查 `wait_b` 是否被优化成「读一次 + 死循环」、`wait_a` 是否每轮都读。

### 验收标准（用例表 + 五类边界）

| 检查项 | 期望 |
| --- | --- |
| `wait_a` 汇编里 `movl flag_a` 出现次数 | 出现在循环体内，至少 1 次 |
| `wait_b` 汇编里读 `flag_b` 的位置 | 记录具体编译器和优化等级下的结果；不强求固定指令或标号 |
| 循环体里加一个 `printf` 后重编译 | 比较生成代码，外部调用可能影响优化，但不构成同步保证 |

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 标志初始为 0 | 两版都进入等待 |
| 最小 | 标志初始为 1 | 立即返回，不进循环 |
| 最大 | 用 `-O3` 再试 | 结论不变（volatile 版本仍每轮读） |
| 相等 | `-O0` 与 `-O2` 对比 | `-O0` 时两版汇编几乎一样——说明这类问题只在开优化后才出现 |
| 非法 | 标志是 `volatile` 但循环里调用外部函数 | 仍每轮读（更保守，不会出错） |

- 不变量：`volatile` 版本的读操作**永远**在循环内，与优化等级无关

### 复盘三问

1. **为什么对**
2. **为什么不能用普通变量**：汇编就是答案
3. **哪里最容易错**：把 `volatile` 加在指针本身（`int * volatile p`）而不是指向的类型（`volatile int *p`）——前者表示指针变量本身易变，后者才是数据易变

## 练习二：寄存器映射

### 任务

用一个 `volatile uint32_t *` 指向一块内存（模拟寄存器），编写「读状态寄存器直到某位就绪」的函数：

```c
#define READY_BIT (1u << 5)

uint32_t wait_ready(volatile uint32_t *status)
{
    while ((*status & READY_BIT) == 0) { }
    return *status;
}
```

要求：

1. 生成汇编，确认循环内每次都读 `*status`
2. 去掉 `volatile` 再编译一次，对比汇编差异
3. 可运行的跨线程版本必须改用原子变量与原子读写；不要让另一个线程写入此处的普通或 volatile 对象

### 验收标准（用例表 + 五类边界）

| 检查项 | 期望 |
| --- | --- |
| volatile 版本汇编 | 循环内有读 `*status` 的指令 |
| 非 volatile 版本汇编 | 读操作被提到循环外（或整个循环被优化掉） |
| 可运行版本 | 使用原子标志模拟延时通知，函数正常返回；汇编探针与线程实验分开 |

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 状态寄存器全 0 | 一直等待（有超时保护时不崩） |
| 最小 | 只有 READY 位 | 立即返回 |
| 最大 | 其余位全 1、READY 为 0 | 仍然等待（说明只判断了目标位） |
| 相等 | 连续两次读到的值相同 | 不影响判定 |
| 非法 | 传入 NULL 指针 | 需判空，不得解引用 |

- 不变量：返回值等于退出循环时读到的状态值；不得修改 `status` 指向的内容

### 复盘三问

1. **为什么对**
2. **为什么要 volatile**：硬件会在程序不知情时改这个寄存器
3. **哪里最容易错**：`volatile` 写在了错误的位置；把 `READY_BIT` 写成 `1 << 5`（有符号）
