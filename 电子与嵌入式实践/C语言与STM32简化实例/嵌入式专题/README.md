# 嵌入式专题

`C知识点/` 讲的是 C 语言本身，每个知识点末尾带一段「嵌入式落点」。这里是反过来：**从一个具体的单片机场景出发，看它需要哪些 C 知识。**

六个专题按「先跑起来 → 能读输入 → 能收能发 → 能显示输出 → 能控制时间 → 能接传感器」的顺序排：

| 专题 | 场景 | 用到的 C 知识点 |
| --- | --- | --- |
| [S01 单片机程序骨架](S01-单片机程序骨架/README.md) | 启动 → 初始化 → 主循环 → 中断置标志 | K01 编译、K04 循环、K10 volatile |
| [S02 GPIO 与按键](S02-GPIO与按键/README.md) | 配置引脚、读按键、翻转 LED、消抖 | K03 位运算、K04 状态机、K07 指针、K08 结构体 |
| [S03 串口收发与命令解析](S03-串口收发与命令解析/README.md) | 中断收字节、环形缓冲、主循环解析 | K05 字符数组、K10 volatile、K12 环形缓冲 |
| [S04 OLED 显示与显存缓冲](S04-OLED显示与显存缓冲/README.md) | 显存数组、字模转换、页列寻址、整帧刷新 | K03 位运算、K05 二维数组、K12 查表 |
| [S05 非阻塞时基与帧调度](S05-非阻塞时基与帧调度/README.md) | SysTick 毫秒时基、时刻表调度、回绕 | K02 有符号差值、K04 状态机、K10 volatile |
| [S06 传感器阈值与滞回控制](S06-传感器阈值与滞回控制/README.md) | DO/AO 区别、单阈值抖动、滞回、持续去抖 | K02、K04 状态记忆、K12 滤波 |

每个专题都有一个**能在电脑上编译运行的模拟程序**：用普通变量当寄存器、用函数模拟中断服务函数。这样在没有开发板的时候也能把逻辑跑通，上板时只剩硬件一层要查。

**S04–S06 的工程原型**是 `本地工程目录` 下的真实练习工程（OLED 示例工程 的显存与帧调度、本地传感器工程原型 的光敏直通），SPL 对照段抄自这些工程的实际代码，Keil 编译产物可查；上板情况以本人记录为准。

## C 知识点到单片机的映射表

| 编号 | C 知识点 | 单片机里的落点 |
| --- | --- | --- |
| K01 | 编译四步 | 交叉编译（本机编译、板子运行）、`.elf` → `.hex/.bin`、启动文件 |
| K02 | 固定宽度类型 | `uint8_t` 串口字节、`uint16_t` ADC 值、`uint32_t` 寄存器、`PRIu32` 打印 |
| K03 | 位运算与掩码 | `ODR` 置位清零、`CRL` 配置字段、`BSRR/BRR` 原子操作、`IDR` 读电平 |
| K04 | 控制流与循环 | `while(1)` 主循环、`switch` 状态机、按键消抖、软件延时 |
| K05 | 字符数组 | 串口命令解析、定长接收缓冲、`\0` 边界、协议包 |
| K06 | 函数与传参 | 驱动函数参数约定、数组必带长度、`const` 只读数据放 Flash |
| K07 | 指针与地址 | 寄存器地址映射、`GPIO_TypeDef`、指针步长、`offsetof` 核对偏移 |
| K08 | 结构体与对齐 | 寄存器块结构体、为什么全用 32 位成员、`packed` 的代价 |
| K09 | 动态内存 | 裸机少用堆、静态分配、内存池、中断里不能 `malloc` |
| K10 | `volatile` | 中断标志、硬件寄存器、优化导致的偶发故障 |
| K11 | 头文件与多文件 | 模块化驱动（一外设一对 `.c/.h`）、`stm32f10x.h`、条件编译 |
| K12 | 数据结构与算法 | 环形缓冲（串口收发）、查表二分、采样值处理 |

## 与嵌入式知识库的分工

- **本目录**：把 C 语言落到单片机场景的可运行模拟，练习场性质
- `嵌入式/02-STM32`：正式的 STM32 知识点笔记，以课程与数据手册为准
- S04 的板卡资料（SSD1306/CH1116、I2C 地址）以 `本地板卡资料` 为准；S06 的传感器接线以 `嵌入式/02-STM32/04-板卡与外设/带DO的光敏电阻传感器` 为准
- 两者可以互相参照，但**事实以数据手册与参考手册为准**，本目录的 SPL 片段都标了「未上板验证」或「取自工程原型」

## 关于「未验证」的说明

S01–S03 的 SPL 代码是示意写法，没有在开发板上跑过；S04–S06 的 SPL 对照取自 `本地工程目录` 的真实工程（Keil 编译通过），但 PC 模拟验证的仍是**逻辑**（显存位运算、时基调度、滞回决策），不等于硬件行为正确。上板前仍要核对：引脚号、时钟使能、寄存器地址、外设编号。
