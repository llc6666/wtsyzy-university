# std::endl：换行与刷新输出缓冲区

## 一句话结论

`std::endl` 会向输出流写入换行符，并立刻刷新该流的缓冲区。普通换行通常只需要 `"\n"`；没有明确的刷新需求时，优先用 `"\n"`。

## 它解决什么问题

输出流通常先把字符放进缓冲区，再在合适的时机交给终端、文件或其他设备。缓冲可以减少频繁的底层 I/O 操作。

`std::endl` 做两件事：

1. 输出一个换行符。
2. 调用 `flush()`，要求缓冲区立即提交给底层设备。

因此它适合“此刻必须立刻看见输出”的场景，例如交互式提示、关键诊断信息或程序崩溃前的日志。

## 最小示例

```cpp
#include <iostream>

int main() {
    std::cout << "第一行\n";      // 换行，通常不强制立刻刷新
    std::cout << "第二行" << std::endl; // 换行，并立刻刷新 cout
}
```

## 为什么默认用 `"\n"`

循环中反复使用 `std::endl` 会反复刷新流。刷新可能触发额外 I/O，性能通常比只写入换行符更差。

```cpp
for (int i = 0; i < 100000; ++i) {
    std::cout << i << '\n';  // 一般写法
}
```

除非你确实需要“立刻提交”，否则不应把 `std::endl` 当作普通换行的习惯性替代。

## 常见误解

### `std::endl` 只是换行吗？

不是。它还会刷新流。这正是它与 `"\n"` 的关键差别。

### 用了 `"\n"`，内容会永远留在缓冲区吗？

不会。流会在若干时机刷新，例如程序正常结束、缓冲区满、显式调用 `flush()`，或受流绑定和设备行为影响。区别在于 `"\n"` 不承诺立刻刷新。

### 交互式程序该怎么写？

当程序输出提示后立刻等待用户输入，可以显式刷新：

```cpp
std::cout << "请输入年龄：" << std::flush;
int age{};
std::cin >> age;
```

此处 `std::flush` 表达意图更准确：需要的是刷新，不是换行。

## 使用边界

- 普通文本输出：用 `"\n"`。
- 需要立即显示且需要换行：用 `std::endl`。
- 只需要立即显示、不需要换行：用 `std::flush`。
- 文件写入中的关键检查点：可考虑刷新，但先判断是否真的需要即时落盘。
