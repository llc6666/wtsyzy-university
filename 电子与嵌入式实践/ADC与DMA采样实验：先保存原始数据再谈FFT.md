# ADC 与 DMA 采样实验：先保存原始数据再谈 FFT

> 目标：建立一条可复查的采样链路：模拟输入 → ADC 转换 → DMA 缓冲 → 原始数据保存 → 统计或频谱分析。先证明采样数据可信，再讨论滤波和 FFT。

## 何时使用

- 需要采集传感器、电压或音频类模拟信号时。
- 想在 STM32 上做 FFT，却还没有确认采样率、缓存长度和数据格式时。
- 发现频谱峰值不稳定，怀疑是采样或缓存配置错误时。

## 输入

1. MCU 型号、ADC 通道和模拟输入范围。
2. 已知的测试输入：稳定直流电压或频率明确的信号源。
3. 采样率 `Fs`、采样点数 `N`、数据位宽和 DMA 模式。
4. 保存原始数据的方式，例如串口、调试器内存读取或文件导出。
5. 若使用 CMSIS-DSP，准备对应版本、头文件、库和链接配置。

## 先算清两个参数

- 采样时间窗：`T = N / Fs`。
- 频率栅格间隔：`Δf = Fs / N`。

这两个量决定一次实验观察了多长时间、频率结果能分到多细。增加 `N` 会增加缓冲区、处理时间和内存占用；提高 `Fs` 会扩大可观察频率范围，但可能提高数据搬运和处理压力。

## 操作步骤

### 1. 做直流基线

给 ADC 一个稳定、在允许范围内的输入，先不用 FFT。连续采满一个缓冲区，保存原始样本，计算最小值、最大值、平均值和峰峰值。若直流输入仍出现大幅跳动，先解决供电、接地、输入阻抗或采样时间问题。

### 2. 配置并核对 DMA

在配置工具中确认 ADC 触发源、采样时间、数据对齐、DMA 传输宽度、缓冲区长度和循环或单次模式。用“配置文件 + 生成代码 + 参考手册”三方核对，避免只看图形界面。[STM32 ADC 官方入门资料](https://wiki.st.com/stm32mcu/wiki/Getting_started_with_ADC)

### 3. 保存一整块原始数据

用 DMA 完成回调或明确的就绪标志通知主循环处理。不要在中断里打印整块数据；这会改变实时性并可能造成丢样。记录缓冲区前后各几个样本、计数器和就绪次数。

### 4. 用已知频率输入验证频率轴

给输入一个频率已知的正弦或方波，先用离线脚本或电脑工具检查，再接入 MCU 的频谱处理。若峰值频率偏移，依次检查实际 `Fs`、定时器触发、`N`、窗口和频率轴换算，不要先修改 FFT 函数。

### 5. 再接入 RFFT 和幅值计算

CMSIS-DSP 的实数 FFT 使用 `arm_rfft_fast_init_f32` 初始化并用 `arm_rfft_fast_f32` 处理；初始化函数要求 FFT 长度为支持的长度。实数输入的频谱存在共轭对称，通常只分析有效的一半；输出格式和缓冲区要求以当前库文档为准。[CMSIS-DSP RFFT 文档](https://arm-software.github.io/CMSIS-DSP/latest/group__RealFFT.html)

频谱输出是复数交错数据时，幅值需要按实部、虚部计算。CMSIS-DSP 的 `arm_cmplx_mag_f32` 输入为实部、虚部交错数组，输出为每个复数的幅值。[幅值函数文档](https://arm-software.github.io/CMSIS-DSP/latest/group__cmplx__mag.html)

## 交付物

- ADC 与 DMA 配置表。
- 一份直流输入原始数据和统计结果。
- 一份已知频率输入的采样数据、频率轴和峰值记录。
- FFT 前后缓冲区格式、库版本和处理耗时记录。

## 验收

- 直流输入的最小值、最大值、平均值和峰峰值可重复。
- DMA 缓冲区长度、采样率和代码中的数组大小完全一致。
- 已知频率输入的峰值落在预期频率栅格附近，误差有数值记录。
- 关闭 FFT 后原始采样仍能正常保存，说明采样链路与频谱处理已分层。

## 常见失败与修正

- **只看到一个频谱峰就宣布成功**：先检查直流基线、原始数据和实际采样率。
- **在 DMA 中断里大量打印**：中断只置标志，主循环或后台任务处理数据。
- **把 ADC 数值直接当电压**：补上参考电压、分辨率、分压和校准关系。
- **FFT 长度随便写**：先查当前库支持的长度和输出布局，再分配缓冲区。

## 边界

本页不规定任何具体 STM32 型号的 ADC 通道、触发源或 DMA 通道；这些资源随系列和封装变化。FFT 的峰值也不等于信号真实幅值，窗口、采样时钟、量化、噪声和标定都会影响结果。
