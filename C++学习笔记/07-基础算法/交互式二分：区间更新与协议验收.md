# 交互式二分：区间更新与协议验收

## 适用场景

题目让程序通过多轮问答猜出隐藏整数，回复表示询问值与隐藏值的关系，并限制询问次数。此时要同时保证两件事：候选区间严格缩小，进程严格遵守交互协议。

本页只讨论“在闭区间 `[1, N]` 中精确查找一个整数”的通用模型。完整示例使用本地模拟器，不连接真实评测器，也不包含任何比赛题面、提交记录或个人成绩。

## 1. 先固定回复的方向

下面约定询问值为 `mid`，隐藏值为 `X`：

| 回复 | 已知事实 | 新区间 |
| --- | --- | --- |
| `<` | `mid < X` | `[mid + 1, r]` |
| `>` | `mid > X` | `[l, mid - 1]` |
| `=` | `mid == X` | 找到 `mid` |

`<` 描述的是询问值和隐藏值的关系，不是“答案小于询问值”。写代码前先把这张表填一遍，避免把两侧方向反过来。

例如 `[1, 7]` 询问 4，得到 `<`，4 已经确定不是答案，新候选只能是 `[5, 7]`。把 `mid` 留在区间内会让区间少排除一个值，可能浪费询问次数。

## 2. 闭区间精确查找模板

```text
l = 1, r = N
当 l <= r：
    mid = l + (r - l) / 2
    询问 mid
    如果回复 <：l = mid + 1
    如果回复 >：r = mid - 1
    如果回复 =：提交 mid 并结束
```

这里 `[l, r]` 的含义是“仍有可能成为答案的全部整数”。因此：

- 精确查找中，`mid` 被证明错误后必须排除，使用 `mid + 1` 或 `mid - 1`。
- 循环使用 `l <= r`，这样单元素区间 `[x, x]` 也会被询问。
- `l == r` 时不能只退出循环而不提交；如果协议允许直接确定，也必须明确写出最终答案。
- `mid = l + (r-l)/2` 避免 `l+r` 在大整数范围内溢出。

这和“二分答案”不是同一个模板。若 `check(mid)` 表示“mid 可行”，`mid` 可能仍是答案，最小可行值的区间更新可以保留 `mid`。更新式取决于本轮信息，不取决于都叫“二分”。

## 3. 询问次数要先算上界

每次询问应当把候选集合分成两侧，并排除当前值。用 q 次询问最多区分 `2^q - 1` 个候选值，因此闭区间 `[1,N]` 的保守上界是：

```text
q = ceil(log2(N + 1))
```

对 `N=1`，上界为 1；对 `N=7`，上界为 3；对 `N=8`，上界为 4。实现中可以用整数循环计算上界，避免浮点 `log` 的舍入误差。

## 4. 交互协议是算法的一部分

即使区间逻辑正确，协议错误也会让程序失效。按题面提供的符号和格式实现，至少逐项确认：

1. 询问行与最终答案行是否包含规定的前缀、空格和换行。
2. 每次询问后是否刷新输出；C++ 标准规定 `std::endl` 先写入换行，再调用 `flush`。[C++ 标准草案：`endl` 与 `flush`](https://eel.is/c++draft/ostream.manip)
3. 读取回复失败时是否立即停止。
4. 若评测器用 `-1` 表示协议错误、询问超限或交互结束，是否把它作为完整字符串读取并立即退出。用 `char` 只能读到 `'-'`，无法判断完整的 `-1`。
5. 发送最终答案后是否停止，不再继续询问。

可按下面的伪代码组织 I/O，具体前缀以题面为准：

```cpp
std::string reply;
std::cout << "? " << mid << std::endl;
if (!(std::cin >> reply)) {
    return 0; // 输入关闭，停止读写
}
if (reply == "-1") {
    return 0; // 评测器要求停止
}
if (reply == "<") {
    l = mid + 1;
} else if (reply == ">") {
    r = mid - 1;
} else if (reply == "=") {
    std::cout << "! " << mid << std::endl;
    return 0;
}
```

没有真实交互器时，不能把“本地程序结束”写成线上通过。至少要有一个模拟器，检查输出格式、候选范围、询问次数、最终答案、超限后的停止和输入关闭。

## 5. 用离线模拟器验收区间逻辑

公开示例把隐藏值封装在 `Oracle` 中，算法只能调用 `ask(mid)` 得到 `<`、`>` 或 `=`，不能直接读取隐藏值。`--self-test` 枚举 `N=1..1024` 的全部隐藏值，共 524,800 组，并检查：

- 返回值就是隐藏值；
- 询问次数不超过整数计算出的上界；
- 每次询问都在当前候选区间内；
- `N=1`、左右端点和中间值都覆盖。

在仓库根目录用 PowerShell 编译：

```powershell
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -Werror '.\C++学习笔记\代码示例\交互式二分搜索.cpp' -o "$env:TEMP\interactive-binary-search.exe"
if ($LASTEXITCODE -ne 0) { throw '编译失败，停止运行' }
& "$env:TEMP\interactive-binary-search.exe" --self-test
'7 7' | & "$env:TEMP\interactive-binary-search.exe"
'6 4' | & "$env:TEMP\interactive-binary-search.exe"
'1 1' | & "$env:TEMP\interactive-binary-search.exe"
```

本轮 GCC 16.2.0、C++17 编译运行结果：

```text
PASS cases=524800 max_queries=11
7
4
1
```

这证明的是离线精确查找函数和询问上界，不证明任何具体线上评测器的格式兼容性。若要发布实际交互程序，必须另外保留逐行协议记录或本地交互裁判输出。

## 常见失败与修正

| 失败 | 反例或症状 | 修正 |
| --- | --- | --- |
| `l=mid`、`r=mid` | 区间不严格缩小，端点可能重复询问 | 精确查找使用 `mid+1`、`mid-1` |
| `while(l<r)` | `N=1` 时一次都不问 | 明确闭区间终止条件，通常用 `l<=r` |
| 只读一个字符 | `-1` 被读成 `'-'`，程序继续输出 | 用字符串读取并先处理停止信号 |
| 只测宽松格式 | 本地能跑，严格解析器拒绝 | 单独检查空格、换行和刷新 |
| 看到 TLE 就改成三分点 | 询问位置改变但没有证明上界 | 先证明每轮排除的候选数和最大询问次数 |
| 把本地模拟当线上结果 | 模拟器与真实交互器协议不同 | 分别记录模拟覆盖范围和线上证据 |

## 交付物与边界

至少留下三项产物：区间含义表、询问协议检查表、离线模拟器输出。遮住代码后，能解释为什么精确查找排除 `mid`，以及为什么回复必须作为字符串读取，再开始写真实交互程序。

本页不覆盖自适应答案、非整数搜索、噪声回复、多个隐藏值或具体评测平台规则。遇到这些条件，要重新定义状态、错误处理和询问上界。
