# C++ 学习闭环：从知识点到独立解题

## 这页解决什么问题

很多学习记录把“看懂讲解”“想出算法”“代码能编译”“测试通过”和“能独立完成新题”混在一起。结果是笔记越来越多，真正能迁移的能力却无法判断。

本页把学习拆成一条可检查的链：

```text
真实问题 → 归类与拆题 → 机制/判据推导 → 最小实现
→ 样例与边界验证 → 独立重写与变式 → 回填笔记和状态
```

每一步都要留下证据。只阅读讲解不能替代独立落码；本地运行通过也不能写成在线评测通过。

## 一、先区分五类材料

| 材料 | 主要问题 | 适合放置的内容 |
| --- | --- | --- |
| 基础知识页 | 一个语法、类型、容器或接口为什么这样工作 | 机制、最小示例、误区和边界 |
| 算法方法页 | 一类题如何识别和建模 | 题面信号、不变量、单调性、复杂度和反例 |
| 单题题解 | 这道题如何从题面走到答案 | 题面对应的推导、实现和测试 |
| 训练记录 | 这次练习实际发生了什么 | 错误版本、测试输入、输出和下一步 |
| 状态台账 | 当前能力和证据到哪一步 | 独立程度、验证等级和欠账 |

目录可以按以下方式分工：基础语法与 STL 放知识目录，跨题判据放算法目录，题面/题解/训练过程分开保存，学习路线和质量规则放方法目录。

新建页面前先搜索同主题。已有页面能承载结论时补充原页，只有核心问题不同才新建页面。

## 二、开始前固定写五行

面对一道题或一个新概念，先写：

1. 输入是什么，数量和范围是多少？
2. 输出是什么，是否有无解值或多个合法答案？
3. 一次操作改变哪些位置、方向和数量？
4. 目标状态是什么，哪些量可能保持不变？
5. 朴素做法的最坏复杂度和中间数值范围是多少？

五行中有一行写不清，就先停在读题阶段。直接写代码容易把操作次数、目标条件、下标边界和数据范围读错。

## 三、从题面推导算法

### 1. 先翻译状态

不要从代码模板开始。先写“谁在什么时候变成什么”。例如“每次给两个位置各加一，最后三数相等”和“每次给一个位置加一，最后三数成等差”虽然都涉及三个数，动作和目标不同，不能共用公式。

### 2. 先找不变量

常见入口包括：

- 总和守恒：一个位置减少的量必须转移到另一个位置。
- 奇偶性守恒：一次同时改变两个位置时，受影响数量的奇偶性不变。
- 单调性：候选答案增大后，判定是否从不可行变成可行。
- 方向性：从左到右处理后，已经确定的位置以后不再改变。

不变量通常只能先证明哪些情况不可能。可行的情况还要给出构造或具体算法。

### 3. 把模型压缩到必要变量

- 最终状态问题：计算最终值和缺口，不逐次模拟加一。
- 周期事件：用向上取整或取余找到下一次事件。
- 成对操作：统计奇偶和最小代价，不搜索所有操作顺序。
- 二分答案：只保留 `check(x)`，并写清判定的单调方向。
- 网格问题：预处理各方向连续长度，避免每格重复搜索。

### 4. 同时写下界和可达性

一个公式至少要配两句话：

- 下界：任何合法答案都必须满足什么限制？
- 构造：达到这个下界后，剩余操作为什么一定能完成？

只有结论、没有这两部分的页面只能做速查，不能作为完整方法。

### 5. 先估复杂度，再定类型

写完伪代码后补上：

```text
时间：最坏 O(      )
空间：最坏 O(      )
可能溢出的量：总和 / 乘积 / 平方 / 前缀和 / 计数
所需类型：int / long long / double / size_t
```

看到累计和、`n × x`、平方距离或大范围计数时，先检查中间结果，不要等输出异常才换类型。浮点二分还要确保 `mid` 和 `check` 的参数类型一致。

### 6. 写边界清单

至少选择与题目相关的测试：

1. 最小规模、单元素或空状态。
2. 全部相等、全部相同字符或全部被阻断。
3. 答案为零、无解、恰好踩点或恰好达到边界。
4. 逆序、重复值、并列最小值或最后一个元素触发条件。
5. 最大规模和最大数值，重点检查时间、内存、越界和溢出。

样例通过只能说明样例没有触发已知错误，不能替代边界和复杂度证据。

## 四、代码验收顺序

每道题按以下顺序执行：

1. 手算一个样例和两个自造边界。
2. 写出能表达判据的最小实现。
3. 使用题目要求的标准编译，并打开 `-Wall -Wextra`；每个警告都要解释或修正。
4. 逐组记录样例的实际输出。
5. 执行适用的边界测试。
6. 能写小规模暴力、枚举或闭式参照时，做随机对拍；否则至少做压力测试。
7. 用最大或近最大输入测试时间、内存和是否卡死。
8. 间隔一段时间后只看题面和判据，独立重写，不看旧代码。

错误复盘按五层归类：输入、模型、边界、实现、验证。修复时要记录错误位于哪一层，以及什么测试本应提前发现它。

## 五、两套状态尺子

### T 档位：思考链走到哪一步

| 档位 | 含义 | 最低证据 |
| --- | --- | --- |
| T1 | 能复述题意、输入输出和约束 | 不看答案口述题目 |
| T2 | 能说出判据、算法和成立理由 | 手推样例与边界 |
| T3 | 能独立写出代码并完成自测 | 独立落码、编译、样例和边界 |
| T4 | 能在新变式或压力条件下稳定处理 | 反例、变式、复杂度或限时证据 |

### L 级别：手上证据有多硬

| 级别 | 含义 |
| --- | --- |
| L1 | 有在线评测通过记录或明确确认的 AC |
| L2 | 本地样例、边界、对拍或压力测试充分通过 |
| L3 | 教学验收和自动化测试通过，但独立证据仍不完整 |
| L4 | 有源码或历史编译产物，正确性未系统验证 |
| L5 | 未完成、未编译或只写了一半 |
| L6 | 只有讲解、题面或提示下推演，没有独立代码 |

T 和 L 量的是两件事。`T3 + L2` 表示独立写出并经过充分本地验证，仍然不等于在线 AC。代码存在也不能单独证明会做，旧编译产物更不能证明当前源码仍然正确。

## 六、什么时候算一个算法大类完成

一道样例题做通，只能说明进入该类。至少完成以下五项，才可以把大类标为“已完成”：

1. 能从新题面识别该类信号。
2. 能不看笔记复述核心判据和成立理由。
3. 样例题之外，独立完成至少两道同类变式。
4. 覆盖至少五类适用边界，并记录实际输出或推导结果。
5. 完成三问复盘：错在题意、模型、实现还是验证？下次如何提前发现？

变式没有完成时，写“样例题闭环”或具体 T/L 档位，不写“该类掌握”。

## 七、回填笔记的最小模板

### 基础知识页

```text
一句话结论
它解决什么问题
关键机制
最小可验证示例
错误写法与后果
适用边界
标准版本、头文件和来源
关联笔记
```

### 算法方法页

```text
题面信号
状态与操作
不变量/单调性/贪心选择
判据或伪代码
为什么正确：下界 + 构造
复杂度与数据类型
反例与边界
对应题解和训练记录
```

### 训练记录

只记录真实发生的事：日期、题目、源码、错误版本、编译命令、测试输入、实际输出、当前档位和下一步。不要把计划写成完成，也不要把讲解写成独立能力。

## 八、每次整理 C++ 知识库的清单

- 搜索同主题，决定补原页还是新建页。
- 读完来源和现有页面，再写结论。
- 把题面、算法、代码、测试和状态放回正确位置。
- 用具体动作和例子替换“熟练掌握”“全面理解”等空话。
- 更新 C++ 总索引和相关专题入口。
- 检查链接、文件名和反向入口。
- 记录新增、修改、排除项和未完成事项。
