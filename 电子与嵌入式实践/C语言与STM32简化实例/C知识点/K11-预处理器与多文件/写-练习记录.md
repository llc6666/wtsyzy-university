## 练习一：把一个程序拆成三个文件

### 任务

任选一个之前写过的程序（例如 K05 的字符串处理、K06 的数组求和），按下面的形状拆分：

```text
mylib.h     声明 + 类型 + 宏（带 include guard）
mylib.c     实现（内部辅助函数用 static）
main.c      只 include mylib.h，调用其中的函数
```

要求用两条命令分别编译再链接：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -c mylib.c -o mylib.o
gcc -std=c17 -Wall -Wextra -Wpedantic -c main.c  -o main.o
gcc mylib.o main.o -o app.exe
```

### 验收标准（用例表 + 五类边界）

| 检查项 | 期望 |
| --- | --- |
| 单独编译 `mylib.c` | 通过，无警告 |
| 单独编译 `main.c` | 通过（说明头文件自足，没有依赖隐含的 include 顺序） |
| 链接 | 通过，程序行为与拆分前一致 |
| 只改 `mylib.c` 后重新编译 | 可以只重编它一个文件 |

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 空实现（只有声明） | 能编译；调用时会链接失败（提示 undefined reference） |
| 最小 | 只有一个函数 | 拆分成功 |
| 最大 | 五到十个函数 | 头文件里的声明与 `.c` 里的定义**逐个对应** |
| 相等 | 两个 `.c` 里各有一个同名 `static` 函数 | 编译链接都通过，互不干扰（对比：若不加 `static` 会报重复定义） |
| 非法 | 在头文件里写变量定义并被两个 `.c` 包含 | 链接时报重复定义——这正是要避免的写法 |

- 不变量：头文件里的每条声明都能在 `.c` 里找到定义；`.c` 里每个非 `static` 的全局标识符都应在头文件里声明

### 复盘三问

1. **为什么对**
2. **暴力做法为什么不行**：全部塞进一个 `.c` 也能跑，但改一处要全量重编，且没有模块边界
3. **哪里最容易错**：头文件里放了变量定义；忘记 include guard；声明与定义签名不一致

## 练习二：可见性实验

### 任务

用四个小文件验证下面的结论（每个结论都要**实际编译一次**）：

| 实验 | 做法 | 期望结果 |
| --- | --- | --- |
| A | 两个 `.c` 里各定义一个同名全局变量 | 链接报重复定义 |
| B | 其中一个加 `static` | 链接通过，两个变量互不影响 |
| C | 头文件 `extern` 声明 + 一个 `.c` 定义 | 另一个 `.c` 能读到它的值 |
| D | 头文件 `extern` 声明，但 `.c` 里定义为 `static` | 能编译链接运行，但读到的值是 **0**（陷阱） |

### 验收标准（用例表 + 五类边界）

| 检查项 | 期望 |
| --- | --- |
| A | 链接失败 |
| B | 链接通过 |
| C | 打印出的值等于 `.c` 里定义时给的初值 |
| D | 打印出的值是 0，而不是初值（本次实测应能看到这个现象） |

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 变量初值为 0 | C 与 D 的输出相同（无法区分，所以要换一个非零初值再做一次） |
| 最小 | 只一个变量 | 结论清楚 |
| 最大 | 多个变量混用 static/extern | 逐个核对 |
| 相等 | 两个文件里的同名 static 变量给不同初值 | 各自文件里读到各自的初值 |
| 非法 | `extern` 声明了一个从未定义的变量 | 链接时报 undefined reference |

- 不变量：D 组实验是本次练习的重点——它证明「能编译能运行」不等于「行为正确」

### 复盘三问

1. **为什么对**
2. **为什么要区分链接属性**：避免符号冲突、隐藏实现
3. **哪里最容易错**：把「文件作用域的 static」和「函数内的 static」当成同一件事
