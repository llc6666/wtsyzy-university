# K08 嵌入式实例

形式：**PC 可编译最小例**（已跑通，输出实测）+ **SPL 对照片段**（未上板，未验证）。

## 一、PC 侧：已验证

文件：[struct-layout-demo.c](struct-layout-demo.c)

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic struct-layout-demo.c -o struct-layout-demo.exe
```

实测输出（gcc 16.2.0，2026-10-01）：

```text
1) bad_order  大小=12，成员大小之和=6（差的就是填充字节）
   good_order 大小=8（把大的放前面更省空间）
2) 各成员偏移：
   bad_order:  a@0 b@4 c@8
   good_order: b@0 a@4 c@5
3) 全 32 位成员的寄存器组：大小=16，偏移 CRL@0 CRH@4 IDR@8 ODR@12
4) 位域：sizeof=4 字节，tx_done=1 rx_done=0
5) 按值传参后：x=1（没变）
   按指针传参后：x=11（变了）
6) 结构体可以直接赋值（数组不行）：q.x=11 q.y=2
```

第 1 行是本知识点最直观的证据：同样的三个成员，换个顺序省了 4 个字节。

## 二、SPL 对照：库为什么把寄存器全定义成 32 位

标准库头文件里 GPIO 的结构体大致是（以 `stm32f10x.h` 为准）：

```c
typedef struct {
    volatile uint32_t CRL;
    volatile uint32_t CRH;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t BRR;
    volatile uint32_t LCKR;
} GPIO_TypeDef;
```

全是 `uint32_t`，于是：

- 不存在填充，成员偏移严格等于手册里的地址偏移
- `GPIOA->ODR` 就是「基址 + 12 字节」，和 PC 示例第 3 步的输出一致

**这就是库把寄存器都写成 32 位的原因之一**——不是因为每个寄存器都需要 32 位，而是为了让结构体布局与硬件地址完全对齐。真实寄存器里有些位保留不用，库照样用 `uint32_t` 占位。

## 三、`packed` 是什么，代价是什么

如果想让结构体紧凑排列（不要填充），GCC 提供了扩展：

```c
struct __attribute__((packed)) msg {
    uint8_t  type;
    uint32_t value;
};
```

去掉填充后 `value` 不再对齐。代价有两个：

1. **访问变慢**：CPU 可能要分两次读再拼接（在 Cortex-M3 上甚至可能触发对齐fault）
2. **取地址出问题**：对 `packed` 结构体里的成员取地址，得到的是非对齐地址，传给要求对齐的指针会出错

结论：**寄存器映射不要用 `packed`**（靠全 32 位成员就能对齐）；`packed` 只在解析紧凑的通信协议包时使用，且最好用逐字节拷贝代替直接访问。

## 四、协议包：用逐字节组装代替位域

发一个 `[类型(1字节)][长度(1字节)][数据]` 的包，推荐写法：

```c
uint8_t buf[64];
buf[0] = type;
buf[1] = len;
memcpy(&buf[2], data, len);      /* 明确按字节放，不依赖结构体布局 */
```

而不是：

```c
struct __attribute__((packed)) pkt { uint8_t type; uint8_t len; uint8_t data[]; };
```

后者在某些平台能工作，但依赖编译器的字节序与对齐行为，换工具链就可能出错。

## 五、把本知识点带回 PC 的做法

**每次写完要映射硬件的结构体，都在 PC 上打印一遍偏移**：

```c
printf("%zu %zu %zu\n", offsetof(GPIO_TypeDef, CRL),
                        offsetof(GPIO_TypeDef, IDR),
                        offsetof(GPIO_TypeDef, ODR));
```

把输出与参考手册的地址表对一遍。这一步只要几分钟，能省掉上板之后「引脚没反应」的半天排查。
