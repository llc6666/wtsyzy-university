# K03 位运算与掩码

## 一句话结论

**掩码决定「动哪几位」，运算符决定「怎么动」。** 所有寄存器操作都是这两件事的组合，没有第三种花样。

## 为什么它在 K07 指针之前

SPL 里最先撞见的就是这种语句：

```c
GPIOA->ODR |= (1 << 5);
```

看懂它不需要懂指针算术，只需要懂掩码。所以位运算排在指针前面。

## 五种操作与对应写法

| 操作 | 写法 | 掩码含义 |
| --- | --- | --- |
| 置位（某位设 1） | `reg \|= PIN(5);` | 该位为 1，或运算强制变 1 |
| 清零（某位设 0） | `reg &= ~PIN(5);` | `~` 后该位为 0，与运算强制变 0 |
| 翻转 | `reg ^= PIN(0);` | 异或：不同为 1，相同为 0 |
| 测试（某位是否为 1） | `(reg & PIN(0)) != 0` | **结果是 0 或「非 0」，不是 0 或 1** |
| 改多位字段 | `reg = (reg & ~MASK) \| (val << shift);` | 先清目标字段，再写新值 |
| 读多位字段 | `(reg >> shift) & MASK` | 右移到最低位，再挡掉高位 |

其中 `PIN(n)` 统一写成宏：

```c
#define PIN(n) (1u << (n))
```

写 `1u` 而不是 `1`：`1` 是 `int`，左移 31 位会移进符号位，属于未定义行为。

## 实测输出（PC 侧已跑通）

文件：[gpio-mask-demo.c](gpio-mask-demo.c)，命令与完整输出见 [嵌入式实例.md](嵌入式实例.md)。节选：

```text
起始      00000000 00000000 00000000 00000000  (0x00000000)
置位 PA5  00000000 00000000 00000000 00100000  (0x00000020)
清零 PA5  00000000 00000000 00000000 00000001  (0x00000001)
低4位改A 00000000 00000000 00000000 00001010  (0x0000000A)
```

注意最后一条「重复置位」：对已经是 1 的位再 `|=` 一次，值不变 —— 这叫**幂等**，是 `|=` 比直接赋值安全的原因：它不会动到你不想动的位。

## 易错清单（本节）

1. `1 << 31`：`1` 是 `int`，溢出未定义 → 写 `1u`
2. `~mask` 在 `int` 上算 → 显式用无符号
3. **把 `reg & PIN` 当 0/1 用**（真实代码里就有人这么写错，见读码分析）→ 写 `!= 0`
4. 改字段只写不清 → 先 `& ~MASK`
5. 混写 `&` 与 `<<` 不加括号 → 一律括号
