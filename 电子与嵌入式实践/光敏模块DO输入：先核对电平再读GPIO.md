# 光敏模块 DO 输入：先核对电平再读 GPIO

## 适用场景

需要用带比较器的光敏模块控制 LED 等开关量，却发现程序能编译、灯也会亮，遮光后行为仍没有变化。这时先检查“外部信号有没有进入 MCU”，再考虑阈值和控制逻辑。

本文针对标有 `VCC/GND/DO` 的数字输出模块，以 STM32F1 标准外设库为代码示例。不同模块的比较器接法、上拉电压和明暗极性可能不同。本文没有对应实物的电平、接线和烧录记录，以下步骤是**待自行执行的实验方案**，不宣称已完成硬件验证。

## 准备输入

- 模块的型号、丝印或电路图，确认引脚确为电源、地、数字输出 `DO`；若还带 `AO`，须明确本轮只使用哪一路。
- MCU 完整型号、板卡供电和拟接收的 GPIO 引脚；示例暂用 STM32F1 的 `PB13`，实际引脚以板卡占用情况和芯片资料为准。
- 能确认电压的万用表，以及遮光、照光和调节电位器的条件。
- 可重新构建的 STM32F1 标准外设库工程，保存修改前版本和构建日志。本文代码不能脱离该库单独用主机编译器构建。

## 第一步：画信号链，选 DO 或 AO

```text
模块 DO → 数字输入引脚 → 读取输入电平 → 按实测极性判断 → 输出动作
模块 AO → ADC-capable 引脚 → ADC 数值 → 软件阈值/映射 → 输出动作
```

带比较器的 `DO` 只给出“阈值哪一侧”的高低状态，不能从一个 0/1 值恢复连续照度。若目标是连续变化或由程序设置多个阈值，应检查模块是否提供 `AO`，再单独规划 ADC；不要把 `AO` 接法套到 `DO` 上。光敏电阻与可调阈值的方向由具体电路决定，不预设“遮光一定高电平”。

## 第二步：无电核对接线与电平

1. 断电确认模块丝印和 MCU 引脚，画出 `VCC/GND/DO → 电源/地/输入引脚` 三线表；输入端与 LED 等执行器输出端分开。
2. 核对模块允许的供电范围。若资料确认支持 3.3 V，可先以 3.3 V 供电并共地，减少电压域变量。
3. 若模块用 5 V 供电，先查输出上拉接向、目标 GPIO 是否允许该电压、所选输入模式与板卡外围电路；未确认前**不要直接接入 GPIO**。某些引脚具备特定条件下的 5 V 容限，不能据此推断整块板或所有接法安全。
4. 在输入未接 MCU 前，按器件说明书和测量条件确认模块 `DO` 两个状态的电压。比较器若为开集电极输出，高电平依赖模块或 MCU 的上拉路径；“模块供电电压”等于“DO 高电平”也不能凭空假定。

留下接线表和电压测量值。任何一项无法核对，停止在这里，先找板卡原理图和模块资料。

## 第三步：把外部信号脚配置为输入

以下示例的前提是：模块和 MCU 均在已核对的 3.3 V 电压域、共地，`DO` 确实接 `PB13`，模块输出结构允许使用 MCU 内部上拉。若板上已有上拉或模块输出结构不同，应按电路重新选择输入模式。代码仅展示读取路径，**未在本文独立编译、烧录或实测**。

```c
#include "stm32f10x.h"
#include "stm32f10x_rcc.h"
#include "stm32f10x_gpio.h"

void LightInput_Init(void)
{
    GPIO_InitTypeDef input;
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
    GPIO_StructInit(&input);
    input.GPIO_Pin = GPIO_Pin_13;
    input.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_Init(GPIOB, &input);
}

uint8_t LightInput_Level(void)
{
    return GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_13);
}
```

在主循环中先记录 `LightInput_Level()` 的原始 0/1，不立即把 `0` 固定解释成“亮”。等遮光、照光各做至少三次并记录结果后，再写 `if` 将实际电平映射到业务动作。若原代码将传感器脚配置为推挽输出，或用 `GPIO_ReadOutputDataBit()` 判断外部光照，必须先修正信号方向：后者读的是输出锁存状态，不能作为外部输入证据。输入脚和 LED 输出脚分别初始化，不合并成“一组全输出”。

## 第四步：按观测记录，再下结论

| 测试轮次 | 条件 | DO 实测电压 | 输入函数读数 | LED/执行器结果 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1–3 | 遮光 | 待填 | 待填 | 待填 | 电位器保持不动 |
| 4–6 | 照光 | 待填 | 待填 | 待填 | 供电与接线不变 |
| 7–9 | 调整阈值后重复 | 待填 | 待填 | 待填 | 记录调节方向 |

先建立只输出原始读数的最小程序，再添加控制输出。如果模块指示灯变化而 MCU 读数不变，依次检查共地、接线、输入模式、上拉和所选引脚。若阈值附近频繁跳变，再考虑连续多次采样确认；不要用软件消抖掩盖供电和接线问题。

## 交付物与验收

交付物：模块及 MCU 型号、接线与电压表、代码提交号或文件版本、构建日志、九轮读数记录，以及明暗极性的实测结论。

只有同时满足以下条件，才可以写“本硬件上的 DO 控制已复现”：

- 输入脚确实连接外部 `DO`，其模式与信号电压已核对，输出脚角色独立。
- 工程在对应工具链中重新构建；所有警告已定位与处理，不能把“生成固件”直接当作功能验证。
- 遮光与照光的原始电平可重复区分，阈值调节方向和控制动作有表格证据。
- 已记录失效情况，例如两种条件读数相同、阈值附近抖动或模块供电变化。
