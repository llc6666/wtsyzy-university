# K03 嵌入式实例

形式：**PC 可编译最小例**（已跑通，输出实测）+ **SPL 对照片段**（未上板，未验证，以 `stm32f10x.h` 实际定义为准）。

## 一、PC 侧：用普通变量模拟一个 32 位寄存器

文件：[gpio-mask-demo.c](gpio-mask-demo.c)

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic gpio-mask-demo.c -o gpio-mask-demo.exe
```

实测输出（gcc 16.2.0，2026-09-30）：

```text
起始      00000000 00000000 00000000 00000000  (0x00000000)
置位 PA5  00000000 00000000 00000000 00100000  (0x00000020)
置位 PA0  00000000 00000000 00000000 00100001  (0x00000021)
清零 PA5  00000000 00000000 00000000 00000001  (0x00000001)
翻转 PA0  00000000 00000000 00000000 00000000  (0x00000000)
测试 PA0：raw=0, 归一化为 0/1: 0
低4位改A 00000000 00000000 00000000 00001010  (0x0000000A)
读字段   pin1 的模式字段 = 0x4
重复置位 00000000 00000000 00000000 00001010  (0x0000000A)
```

最后一行是**幂等性**的证据：对已经是 1 的第 3 位再 `|=` 两次，值不变。这正是 `|=` 比直接赋值安全的地方——它只动你指定的位。

## 二、SPL 对照：同一套运算，换一个名字

| PC 示例里的写法 | SPL 里的写法 | 说明 |
| --- | --- | --- |
| `gpioa_odr \|= PIN(5);` | `GPIOA->ODR \|= GPIO_Pin_5;` | 置位：PA5 输出高 |
| `gpioa_odr &= ~PIN(5);` | `GPIOA->ODR &= ~GPIO_Pin_5;` | 清零：PA5 输出低 |
| `gpioa_odr ^= PIN(0);` | `GPIOA->ODR ^= GPIO_Pin_0;` | 翻转 |
| `(gpioa_odr & PIN(0)) != 0` | `(GPIOA->IDR & GPIO_Pin_0) != 0` | 读输入引脚电平 |
| `PIN(n)` | `GPIO_Pin_5` = `((uint16_t)0x0020)` | 都是「第 n 位为 1」的掩码 |

`GPIO_Pin_5` 就是 K03 读码分析里讲的**命名掩码**，只是名字换成了引脚。多个引脚组合也一样：

```c
GPIOA->ODR |= (GPIO_Pin_5 | GPIO_Pin_6);   /* 同时置位 PA5 与 PA6 */
```

## 三、配置寄存器：改字段的标准动作

`CRL`（端口配置低寄存器）里每个引脚占 4 位，改某引脚的模式必须**先清后写**（PC 示例第 6 步就是这个动作）：

```c
/* 把 PA5 配置成推挽输出、50MHz（示例值，具体编码查参考手册） */
GPIOA->CRL &= ~(0x0Fu << (4u * 5));   /* 先清掉 PA5 对应的 4 位 */
GPIOA->CRL |=  (0x03u << (4u * 5));   /* 再写入新值 */
```

写成一行：

```c
GPIOA->CRL = (GPIOA->CRL & ~(0x0Fu << (4u * 5))) | (0x03u << (4u * 5));
```

如果少了「先清」那一步，新值会和旧值按位或，得到的既不是旧值也不是新值——这是配置寄存器最常见的错法。

## 四、为什么还有 BSRR / BRR

`ODR |= PIN` 在 CPU 看来是三步：**读 ODR → 改 → 写回 ODR**。如果这三步中间来了中断，中断里也改 ODR，返回后主流程写回的是它读到的旧值，中断的改动就被覆盖掉了。

`BSRR`（置位/复位寄存器）把这件事变成一步写入：

```c
GPIOA->BSRR = GPIO_Pin_5;          /* 置位 PA5，写 1 生效，写 0 无动作 */
GPIOA->BRR  = GPIO_Pin_5;          /* 清零 PA5 */
```

写 0 的位不产生动作，所以**不需要读-改-写**，也就不会被中断打断。这就是它存在的理由。

对照 PC 示例：普通变量上的 `|=` 没人跟你抢，所以看不出差别；换成硬件寄存器，差别就是偶发的丢失改动。

## 五、把本知识点带回 PC 的做法

在 PC 上验证「先清后写」与「只写不清」的差别：

```c
uint32_t reg = 0x0000000Fu;
reg =  (reg & ~0x0Fu) | 0x03u;   /* 正确：结果是 0x3 */
reg2 = reg | 0x03u;              /* 错误示范：0xF | 0x3 仍是 0xF，看不出写入生效 */
```

把这两行打印出来看一次，比记结论牢。
