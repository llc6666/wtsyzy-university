# S03 嵌入式实例

## 一、PC 侧：已验证

文件：[uart-ringbuf-demo.c](uart-ringbuf-demo.c)，输出见 [README](README.md)。

验证的是：缓冲绕回是否正确、满时是否拒绝写入、攒行与 `\0` 是否安全、命令解析是否正确，以及突发时的丢弃行为。PC 程序按顺序模拟中断写入和主循环读取，不能替代真实中断抢占下的原子性与临界区验证。

## 二、SPL 对照

```c
/* queue_push_from_isr 是待实现的中断安全队列接口。
 * PC 示例的 count++/count-- 由两端共同修改，不能直接并发使用。
 */

void USART1_IRQHandler(void)
{
    if (USART_GetITStatus(USART1, USART_IT_RXNE) != RESET) {
        uint8_t b = USART_ReceiveData(USART1);   /* 读数据本身就清了标志 */
        queue_push_from_isr(b);               /* 同步实现需单独验证 */
    }
}

/* 发送：查询方式，等待发送寄存器空 */
void uart_send_byte(uint8_t b)
{
    while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET) { }
    USART_SendData(USART1, b);
}
```

（示意写法，未上板验证；标识符以库头文件为准。）

注意串口的一个特殊性：**读 `DR` 寄存器这个动作本身会清除 RXNE 标志**，所以接收中断里通常不需要再调 `ClearITPendingBit`；而发送完成标志 `TC` 需要显式清。这一点与 GPIO 外部中断（必须手动清）不同，容易混淆。

## 三、波特率与误差

波特率由时钟分频得到，实际值与目标值之间有误差：

```text
误差 = (实际波特率 − 目标波特率) / 目标波特率
```

STM32F103 的 USART 挂在 APB2/APB1 上，时钟频率取决于系统时钟配置。常见坑：

- 以为 `SystemInit()` 后是 72MHz，实际没配 PLL 时只有 8MHz → 波特率差 9 倍 → 收到乱码
- 误差超过约 2~3% 时可能出现误码（双方都有误差时更严格）

**收到乱码先查时钟，再查波特率，最后才怀疑接线。**

## 四、协议层的三个问题

串口只负责传字节，消息边界与可靠性要上层解决：

| 问题 | 常见做法 |
| --- | --- |
| 消息边界（粘包/拆包） | 固定长度 / 分隔符（如 `\n`）/ 包头包尾 |
| 数据中出现与边界相同的字节 | 转义、或用「长度 + 校验和」代替包尾 |
| 传输出错 | 校验和或 CRC；关键命令加确认与重传 |

本专题用的是最简单的「以 `\n` 为分隔符 + 文本命令」，适合调试与人工输入。二进制协议通常用「包头 + 长度 + 数据 + 校验」。

## 五、printf 重定向

调试时常用 `printf` 走串口：

```c
int fputc(int ch, FILE *f)
{
    uart_send_byte((uint8_t)ch);
    return ch;
}
```

（示意写法，未上板验证；具体做法与工具链相关，有的需要关闭半主机模式。）

要注意两点：

1. `printf` 很慢，在中断里绝对不要用
2. 格式化输出会占不少 Flash，量产版本通常用宏关掉

## 六、把本专题带回 PC 的做法

**协议解析先在 PC 上用字节流跑通**，包括这几种情况：

1. 正常一帧
2. 一帧分多次到达（拆包）
3. 两帧连在一起到达（粘包）
4. 数据里出现与分隔符相同的字节
5. 校验和错误的一帧

这五种情况在 PC 上用几行数组就能覆盖；在板子上靠串口助手手动发，很难系统地试全。
