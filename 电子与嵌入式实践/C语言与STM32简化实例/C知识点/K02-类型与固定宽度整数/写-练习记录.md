## grains

- 位置（原始目录）：`exercism-c/c-main/exercises/practice/grains/`；题面与参考解见 [素材库](../../99-素材库/exercism-c/K02-类型与固定宽度整数/)
- 签名：`uint64_t square(uint8_t index)`、`uint64_t total(void)`
- 题面要点：棋盘 64 格，每格翻倍；求某格数量与总和

### 验收标准（用例表 + 五类边界）

| 输入 | 期望 |
| --- | --- |
| `square(1)` | 1 |
| `square(2)` | 2 |
| `square(3)` | 4 |
| `square(16)` | 32768 |
| `square(32)` | 2147483648 |
| `square(64)` | 9223372036854775808 |
| `total()` | 18446744073709551615 |

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | `square(0)` | 0（不是 1） |
| 最小 | `square(1)` | 1 |
| 最大 | `square(64)` | 2⁶³，必须用 64 位 |
| 相等 | `square(1) + square(1)` 与 `square(2)` | 相等，验证翻倍关系 |
| 非法 | `square(65)`、`square(255)` | 返回 0，不越界计算 |

- 不变量：所有返回值都是 `uint64_t`；`total()` 等于 1 到 64 格之和；不得用浮点计算（精度不够）

### 复盘三问（做完填）

1. **为什么对**
2. **暴力做法为什么不行**：循环乘 2 能做，但要确认用的是 64 位移位还是乘法，以及第 64 格是否会溢出
3. **哪里最容易错**：`(uint64_t)1 << (index - 1)` 写成 `1 << (index - 1)`；`square(0)` 的边界

## gigasecond

- 签名：`void gigasecond(time_t start, char *buffer, size_t size)`
- 题面要点：给定时刻加十亿秒，按 `"%Y-%m-%d %H:%M:%S"` 输出
- 需要 `<time.h>`：`gmtime` 把 `time_t` 转成结构体时间，`strftime` 按格式写进缓冲区

### 验收标准（用例表 + 五类边界）

| 输入 | 期望输出 |
| --- | --- |
| 2015-01-24 22:00:00 | `2046-10-02 23:46:40` |
| 1970-01-01 00:00:00 | `2001-09-09 01:46:40` |

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | `start = 0`（1970 纪元起点） | 正常输出，不崩溃 |
| 最小 | 1970 之前的时间（`time_t` 为负） | 不依赖 `time_t` 是无符号类型 |
| 最大 | 接近 `time_t` 上限的时刻 | 加法不溢出 |
| 相等 | 加 0 秒 | 等于原时刻 |
| 非法 | `buffer` 太小（`size` 不足） | 不得越界写入；按 `size` 截断 |

- 不变量：结果写进调用方缓冲区，函数不分配内存；输出以 `\0` 结尾；不修改输入

### 复盘三问（做完填）

1. **为什么对**
2. **暴力做法为什么不行**
3. **哪里最容易错**：`gmtime` 返回的是**静态缓冲区指针**，多次调用会被覆盖；`time_t` 的宽度假设
