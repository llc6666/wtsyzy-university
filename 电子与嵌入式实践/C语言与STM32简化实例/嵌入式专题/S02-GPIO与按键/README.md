# S02 GPIO 与按键

## 一句话结论

**GPIO 编程就是三件事：把引脚配置成输入或输出、读某一位、改某几位。** 按键的难点不在读电平，而在滤掉抖动——那要靠状态机，不靠延时。

## 实测（PC 模拟）

文件：[gpio-key-demo.c](gpio-key-demo.c)

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic gpio-key-demo.c -o gpio-key-demo.exe
```

```text
配置后 CRL = 0x00300000（PA5 对应的 4 位被写成 0x3）

采样序列（1=松开 0=按下）：11010000100111

逐次处理：
  [ 2] 电平 0 -> 进入待确认（可能是抖动）
  [ 3] 电平 1 -> 是抖动，回到空闲
  [ 4] 电平 0 -> 进入待确认（可能是抖动）
  [ 5] 电平 0 -> 确认按下：LED 亮（第 1 次）
  [ 8] 电平 1 -> 已松手，回到空闲
  [ 9] 电平 0 -> 进入待确认（可能是抖动）
  [10] 电平 0 -> 确认按下：LED 灭（第 2 次）
  [11] 电平 1 -> 已松手，回到空闲

结果：采样中出现了 6 次电平跳变，但只确认了 2 次真实按下
```

**6 次跳变只确认 2 次真实按下**——这就是消抖的价值。

## 一、配置一个引脚：先清后写

`CRL`（端口配置低寄存器）里每个引脚占 4 位。要把 PA5 配成推挽输出：

```c
const uint32_t shift = 4u * 5u;                          /* 引脚号 × 4 */
gpioa.CRL = (gpioa.CRL & ~(0x0Fu << shift)) | (0x03u << shift);
```

两步都不能少：

- `& ~(0x0F << shift)`：把 PA5 那 4 位清成 0
- `| (0x03 << shift)`：写入新的模式值

少第一步，新值会和旧值按位或，得到既不是旧值也不是新值的结果（K03 里重点讲过）。

## 二、读电平与翻转：只动目标位

```c
uint8_t level = (gpioa.IDR & PIN_KEY) ? 1u : 0u;   /* 读：判非零，不是判等于 1 */
gpioa.ODR ^= PIN_LED;                              /* 翻转：异或只影响这一位 */
```

`^=` 翻转的好处是不需要先知道当前状态，也不会动别的引脚。

## 三、消抖：状态机比延时好

采样 → 状态迁移表：

| 当前状态 | 读到 | 动作 |
| --- | --- | --- |
| 空闲 | 按下 | 进入「待确认」 |
| 待确认 | 仍按下 | **确认为真实按下**，执行动作，进入「等松手」 |
| 待确认 | 松开了 | 判定是抖动，回到空闲 |
| 等松手 | 松开了 | 回到空闲 |

为什么不用「延时 10ms 再读」：延时会把 CPU 占死（K04 讲过）。状态机的做法是把采样周期固定下来（比如定时器每 1ms 采一次），主循环只做查表与迁移。
