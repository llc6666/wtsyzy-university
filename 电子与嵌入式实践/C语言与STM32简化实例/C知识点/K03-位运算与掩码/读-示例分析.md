## 二、《单身狗》示例：一份能跑通但逻辑错的代码

来源：`hairrrrr-C-CrashCourse/C-CrashCourse-master/Coding/Advanced_C/02 Exercises/02/03 单身狗问题/SingleDog.c`

题目：数组中只有两个数各出现一次、其余都出现两次，找出这两个数。思路是对的：

1. 全部异或一遍 → 得到 `rst = dog1 ^ dog2`
2. `rst` 中为 1 的某一位，说明两个单身狗在这位上不同
3. 按这一位把数组分成两组，组内分别异或 → 各得一个单身狗

### 问题出在第 2 步

（原示例代码未随公开版复制；此处保留分析结论。）

`rst & (1 << leftPos)` 的结果只有两种可能：`0`，或者 **`1 << leftPos` 这个值本身**（即 2、4、8、16……）。

也就是说，除了 `leftPos == 0` 的情况，它**永远不等于 1**。于是：

- 如果 `rst` 的最低位恰好是 1 → 循环在第 0 轮 break，碰巧对了
- 否则 → 循环跑满 32 次，`leftPos == 32`。如果后续无保护地继续执行 `1u << leftPos`，就会越过位宽并产生未定义行为；验证程序显式停止在这里，避免用未定义行为证明错误

同样的写法在后面的分组里又出现一次，所以两处都要改。

两处改动：`1u`（无符号，避免移位进符号位）+ `!= 0`（判「有没有这一位」，而不是判「等于 1」）。

**这就是本知识点易错清单第 3 条的由来**：位测试的结果是 0 或非 0，不是 0 或 1。

对比上面那份错误代码：这里正是 `!= 0`。同一个判断，一个写法对、一个写法错，差别就在这一处。

`allergen_t` 是枚举，`ALLERGEN_EGGS = 0`、`ALLERGEN_PEANUTS = 1`…… 枚举值当位序用，这也是常见手法。

注意它仍写的是 `1 << allergen`（`int`），因为 allergen 最大为 7、score 是 `unsigned int`，这里不会溢出；但对 32 位寄存器的位操作，一律推荐 `1u`。

## 读码小结

1. 看到 `x & mask == 1` 这种写法，先怀疑
2. 判断「某位是否为 1」用 `!= 0`
3. 移位构造掩码时，底数用无符号
4. 「在我试的数据上是对的」不等于「是对的」——A 组就骗过了原写法
