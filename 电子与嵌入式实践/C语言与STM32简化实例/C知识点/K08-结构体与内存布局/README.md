# K08 结构体、对齐与内存布局

## 一句话结论

**结构体成员之间可能有编译器插入的填充字节**；成员顺序一变，结构体大小就变。把结构体映射到硬件寄存器时，这条是硬约束。

## 实测：顺序不同，大小不同

```text
1) bad_order  大小=12，成员大小之和=6（差的就是填充字节）
   good_order 大小=8（把大的放前面更省空间）
2) 各成员偏移：
   bad_order:  a@0 b@4 c@8
   good_order: b@0 a@4 c@5
```

两个结构体成员完全一样，只是顺序不同：一个 12 字节，一个 8 字节。

原因：CPU 访问内存时按对齐要求读（4 字节成员通常要放在 4 的倍数地址上），编译器就在中间补空字节。

## 为什么寄存器映射要求「无填充」

```text
3) 全 32 位成员的寄存器组：大小=16，偏移 CRL@0 CRH@4 IDR@8 ODR@12
   每个成员都比前一个大 4，没有填充
```

全是 `uint32_t` 时成员自然对齐，不需要填充，于是 `结构体基址 + 偏移` 正好等于手册里的寄存器地址。这就是 K07 里 `GPIOA->ODR` 能正确工作的前提，也是本知识点存在的理由。

一旦混进 `uint8_t` 成员，就可能出现填充，`->ODR` 就会指向错误的地址。

## 位域能用，但谨慎

```text
4) 位域：sizeof=4 字节，tx_done=1 rx_done=0
```

位域能把几个标志塞进一个整数，但**位的排列顺序由编译器决定**。做通信协议解析（字节流有确定位序）时不要依赖位域；做普通标志位（不关心具体哪一位）时可以省空间。

## 结构体按值传参会整体拷贝

```text
5) 按值传参后：x=1（没变，传的是副本）
   按指针传参后：x=11（变了）
6) 结构体可以直接赋值（数组不行）：q.x=11 q.y=2
```

结构体能整体赋值、能作为返回值，这是它比数组方便的地方；代价是拷贝开销，大结构体要传指针。

## 初始化、赋值与传参

~~~c
struct Box {
    int x;
    int y;
};

struct Box a = {1, 2};
struct Box b = {0};
b = a;
~~~

使用结构体时按以下顺序处理：

1. 定义变量时明确初始化；局部结构体不要在未初始化状态下读取成员。
2. 成员较多时使用指定初始化器或专门的初始化函数，避免顺序填错。
3. 整体赋值会复制结构体对象，包括其中的数组成员；裸数组自身不能用整体赋值。
4. 按值传参会复制一份对象；大对象或需要修改调用者对象时，传结构体指针，并写清楚是否允许为空。
5. 返回结构体的值与返回局部结构体地址是两回事；后者会形成悬空指针。

## 嵌套与自引用

结构体可以包含另一个结构体，也可以包含指向自身的指针：

~~~c
struct Point {
    int x;
    int y;
};

struct Box {
    struct Point pos;
    int width;
};

struct Node {
    int value;
    struct Node *next;
};
~~~

自引用必须使用指针。若把 struct Node next 直接作为成员，编译器无法确定 Node 的最终大小。链表、树和环形缓冲区都依赖这种“对象保存下一对象地址”的布局；使用时仍要单独写明所有权、终止条件和生命周期。

## 复习与自查卡

遇到一段结构体代码，先填写以下六项：

1. 成员列表、成员类型和初始化方式。
2. 每个成员的访问形式，是点号还是结构体指针箭头。
3. sizeof 与 offsetof 的结果来源，是否依赖特定 ABI。
4. 传参时是复制对象还是传递地址，修改责任归谁。
5. 如果用于协议或寄存器，字节序、访问宽度、保留位和成员偏移来自哪份资料。
6. 来源记录、源码阅读、工程构建和硬件现象分别处于哪一层，不能把它们合并成一个结论。

## 易错清单（本节）

1. 以为 `sizeof(结构体)` 等于成员大小之和
2. 成员顺序随意排，导致结构体变大
3. 把带填充的结构体直接映射到寄存器
4. 用位域解析有确定位序的协议
5. 大结构体按值传参，拷贝开销大
