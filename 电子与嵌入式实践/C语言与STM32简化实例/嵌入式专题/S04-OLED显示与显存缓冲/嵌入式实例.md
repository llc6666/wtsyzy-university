# S04 嵌入式实例

## 一、PC 侧：已验证

文件：[oled-gram-demo.c](oled-gram-demo.c)，输出见 [README](README.md)。

验证的是：字模转换、页列寻址（含跨页）、三种颜色位运算、越界丢弃、单像素刷新的字节数。

## 二、工程原型对照（OLED 示例工程）

以下片段取自真实工程 `本地 OLED 工程原型\Hardware\OLED.c`（Keil 编译通过，`Objects/Project.axf` 存在；上板情况以本人记录为准）。PC 模拟与它逐行对应：

```c
/* 显存：页 x 列，与本 demo 的 oled_gram[2][32] 同构 */
static uint8_t OLED_GRAM[OLED_HEIGHT / 8][OLED_WIDTH];   /* [8][128] */

static void OLED_SetPixelInternal(int16_t x, int16_t y, uint8_t Color)
{
    uint8_t Mask;

    if (x < 0 || x >= OLED_WIDTH || y < 0 || y >= OLED_HEIGHT) {
        return;                                    /* 越界丢弃，demo 第 2 步 */
    }

    Mask = (uint8_t)(1U << (y & 0x07));             /* 页内行号 */
    if (Color == OLED_COLOR_WHITE) {
        OLED_GRAM[y >> 3][x] |= Mask;               /* demo：|= */
    } else if (Color == OLED_COLOR_XOR) {
        OLED_GRAM[y >> 3][x] ^= Mask;               /* demo：^= */
    } else {
        OLED_GRAM[y >> 3][x] &= (uint8_t)~Mask;     /* demo：&= ~ */
    }
}
```

页定位命令——`0xB0|Page`、`0x10|列高4位`、`列低4位` 三条，demo 里统计的「每页 3 字节命令」就是它们：

```c
static void OLED_SetCursor(uint8_t Page, uint8_t Column)
{
    OLED_WriteCommand(0xB0 | Page);
    OLED_WriteCommand(0x10 | ((Column >> 4) & 0x0F));
    OLED_WriteCommand(Column & 0x0F);
}
```

整页连发（demo 第 4 步「改一个像素也整页重发」的出处）：

```c
static void OLED_UpdateRegion(void)
{
    uint8_t Page;
    for (Page = 0; Page < OLED_HEIGHT / 8; Page++) {
        OLED_SetCursor(Page, 0);
        OLED_WriteDataBuffer(OLED_GRAM[Page], OLED_WIDTH);
    }
}
```

攒帧用法（工程 `User/main.c`，动画期关闭自动刷新、每帧只刷一次）：

```c
OLED_Init();
OLED_SetAutoUpdate(0);          /* 画入显存不发送 */
while (1) {
    /* ……把整帧画进 GRAM…… */
    OLED_Update();              /* 一次发完 */
}
```

## 三、软件 I2C：GPIO 模拟时序

该工程的 I2C 是 GPIO 位操作模拟的（PB8=SCL、PB9=SDA），发字节靠「取最高位 → 拉时钟」循环：

```c
static void OLED_I2C_SendByte(uint8_t Byte)
{
    uint8_t i;
    for (i = 0; i < 8; i++) {
        OLED_W_SDA((Byte & 0x80) != 0);   /* MSB 先行 */
        OLED_W_SCL(1);
        OLED_W_SCL(0);
        Byte <<= 1;
    }
    /* 不读 ACK，补一个时钟走完应答周期 */
    OLED_W_SDA(1); OLED_W_SCL(1); OLED_W_SCL(0);
}
```

I2C 地址 `0x78` 是**8 位写地址**（7 位地址 `0x3C` 左移一位补 0）。资料里有的写 `0x3C`、有的写 `0x78`，是同一个器件的两种记法——上板前先确认手头资料用哪种。

## 四、真实字模的格式

工程 `OLED_Font.h` 存的是**转换结果**（宽 8、高 16 的两段式）：

```text
const uint8_t OLED_F8x16[][16] = {
    0x00,0x00,0x00,0xF8,0x00,0x00,0x00,0x00,   ← 前 8 字节：上半页 8 列
    0x00,0x00,0x00,0x33,0x30,0x00,0x00,0x00,   ← 后 8 字节：下半页 8 列
    //! 1
    ...
```

对照本 demo：`bitmap_to_columns` 产出的 `columns[8]` 相当于它的「前 8 字节」，高 16 的字符就是再来一份下半页。查表项按 ASCII 码偏移索引（`' '`=0x20 起）。

## 五、上板前要核对的

| 项 | 核对什么 |
| --- | --- |
| 控制器型号 | 板卡是 SSD1306 还是 CH1116（1.3 寸常见），初始化命令序列不同 |
| I2C 地址 | 0x78（8 位）= 0x3C（7 位），与资料记法对齐 |
| 引脚 | SCL/SDA 接哪个 GPIO，工程是否一致 |
| 页高 | 64 行 = 8 页；0.91 寸 128x32 只有 4 页 |
| 供电 | 多数模块 3.3V，接 5V 前看板卡说明 |

（板卡资料见 `本地板卡资料`，已区分模块手册与控制器裸芯片参数。）

## 六、把本专题带回 PC 的做法

显存类驱动的通用 PC 验证法：**数组当显存，printf 当屏幕**。能覆盖：字模转换对不对、跨页对不对、擦除会不会误伤邻居、闪烁翻两次是否复位。上板后真正要试的只剩：命令序列、时序、地址这些硬件层。
