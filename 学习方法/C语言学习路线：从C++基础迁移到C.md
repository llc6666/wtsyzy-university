# C 语言学习路线：从 C++ 基础迁移到 C

## 一句话结论

已有 C++ 基础的人学习 C，重点不在重新背条件和循环，而在重新理解编译过程、数组传参、字符串、指针、动态内存和多文件组织。算法建模与复杂度可以复用，资源管理和标准库接口必须重新学习。

## 适用场景

这条路线适合已经能读写基础 C++ 程序，却想补足以下能力的人：

- 能独立编译和运行 `.c` 文件。
- 能解释数组、地址、指针和函数参数之间的关系。
- 能用字符数组处理简单字符串。
- 能用 `malloc` 和 `free` 管理一段动态内存。
- 能把一个小型 C++ 算法程序改写成 C 程序。

它不把嵌入式外设、操作系统接口或大型工程作为初学阶段前置。先把语言本身的对象、内存和编译边界做实，再扩大范围。

## 你需要准备什么

- 一个支持 C17 的 GCC 或 Clang 编译器。
- 一个纯文本编辑器和命令行。
- 一份记录表，至少记录：源文件、编译命令、警告、测试输入、实际输出和未解决问题。
- 能读懂 C++ 中的条件、循环、数组、函数、结构体和基础算法。

## 先做一次可复现编译

建立 `main.c`，写入下面的程序：

```c
#include <stdio.h>

int main(void) {
    int values[] = {3, 1, 4};
    int max_value = values[0];

    for (int i = 1; i < 3; ++i) {
        if (values[i] > max_value) {
            max_value = values[i];
        }
    }

    printf("max = %d\n", max_value);
    return 0;
}
```

用严格警告编译：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -g main.c -o main
```

运行：

```bash
./main
```

Windows 环境下可运行 `main.exe`。预期输出：

```text
max = 4
```

这一步的验收不是“屏幕上出现 4”这么简单，还要能说清楚：源文件由编译器转换为可执行文件，`values` 是数组对象，函数入口是 `main(void)`，循环访问的下标范围是 `1` 到 `2`。

## C++ 内容如何迁移

| 已有知识 | 在 C 中的处理 | 迁移时必须重新检查 |
| --- | --- | --- |
| 条件、循环、基础数组 | 大部分表达式结构可复用 | 类型、下标和数组长度 |
| 函数和返回值 | 保留函数调用结构 | 函数声明、作用域和参数类型 |
| `std::string` | 改用字符数组和 `\0` | 容量、有效长度和越界 |
| `std::vector` | 先用固定数组，再学动态数组 | 元素数量、容量和释放责任 |
| `struct` | 保留数据组织方式 | 没有构造函数、析构函数和成员函数 |
| 值传递、指针参数 | 作为重点重新推导 | 函数拿到的是副本还是地址 |
| `new/delete` | 改为 `malloc/free` | 谁申请、谁使用、谁释放 |
| `iostream` | 改用 `stdio.h`、`printf`、`scanf` | 格式符和输入返回值 |
| STL 容器 | 暂缓 | 先理解数组、指针和手写数据结构 |
| 二分、贪心、模拟 | 复用模型和复杂度 | 用 C 重新实现并测试边界 |

表格中的“可以复用”只表示思路相近，不表示两种语言的代码可以直接混写。

## 按阶段执行

### 阶段 1：程序结构、类型和输入输出

学习 `main(void)`、整数和浮点类型、表达式、数组、`sizeof`、`printf`、`scanf` 以及编译警告。

练习顺序：求和 → 最大值 → 频数统计 → 数组逆序 → 二维数组遍历。

留下的产物：至少 5 个可独立编译的 `.c` 文件，以及一张记录每个程序测试输入和输出的表。

验收条件：每个程序都测试一个最小边界和一个极值；能够指出每个变量保存的是值、数组元素还是地址；能够解释一个编译器警告对应的代码行。

### 阶段 2：函数与数组传参

学习函数声明与定义、值传递、指针参数、数组参数、数组长度、`const` 和作用域。

按下面顺序完成函数：

1. 交换两个整数。
2. 返回数组最大值。
3. 原地逆序数组。
4. 统计数组中某个值的出现次数。

每个函数都写出“是否修改调用者对象”的说明。验收时，故意传入长度为 `0` 的数组场景，确认函数是否有明确的处理约定，不能让空状态靠运气运行。

### 阶段 3：字符数组、字符串与指针

学习字符数组、字符串结尾的 `\0`、指针加减、数组下标和指针表达式的关系。

练习：手写字符串长度、复制、比较、反转、删除空格和回文判断。每次记录三项：数组容量、有效字符数量、结尾零字符的位置。

验收条件：能说明为什么字符串容量至少要为有效字符数加上结尾零字符；能用一个越界输入复现错误风险，并把输入长度限制写进代码。

### 阶段 4：结构体与动态内存

学习结构体数组、`malloc`、`calloc`、`realloc`、`free`、空指针、悬空指针和链表。

每次动态内存练习都写一张所有权表：

| 阶段 | 必须回答的问题 |
| --- | --- |
| 申请 | 哪个函数申请了这块内存，申请了多少字节 |
| 使用 | 哪些函数可以读写，当前有效元素数量是多少 |
| 失败 | 申请失败时如何停止，是否会继续解引用空指针 |
| 释放 | 哪个函数负责释放，释放后是否还会再次使用 |

验收条件：能写出结构体数组和简单链表的创建、遍历、插入、删除；能检查重复释放、释放后使用和忘记释放。

### 阶段 5：预处理与多文件

学习头文件、函数声明、宏、条件编译、`static`、多个 `.c` 文件的编译与链接。

把一个小程序拆成三个部分：输入模块、数据处理模块和 `main`。分别编译源文件，再完成链接：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -c input.c
gcc -std=c17 -Wall -Wextra -Wpedantic -c logic.c
gcc -std=c17 -Wall -Wextra -Wpedantic -c main.c
gcc input.o logic.o main.o -o app
```

验收条件：能区分声明、定义和链接；修改一个函数声明后，能找到受影响的源文件；头文件不会因为重复包含产生重复定义。

### 阶段 6：用 C 重写基础算法

从熟悉的模拟、二分或贪心问题开始，每题固定执行：

```text
独立建模 → 写 C 版本 → 编译警告检查 → 边界测试 → 说明复杂度 → 隔天重写
```

第一轮先使用普通数组和手写基础排序，目的是确认数据结构和边界；理解之后再学习 `qsort` 等库函数。库函数可以减少代码量，不能替代算法模型和正确性检查。

每题留下：题意抽象、数据结构、核心循环、不变量或正确性依据、复杂度、测试用例、实际输出和未解决问题。

## 每篇 C 笔记的最低结构

一篇正式笔记至少要包含：

1. 一句话结论。
2. 一个最小、可独立编译的示例。
3. 变量、地址、对象和生命周期的关系。
4. 一个“可以编译但逻辑不正确”的反例。
5. 编译命令、编译器版本和测试输入。
6. 与已有 C++ 知识的迁移关系。

缺少编译结果或边界测试时，只能标记为“待验证”，不能写成已经掌握。

## 统一验收清单

- [ ] `.c` 文件能用明确的标准选项编译。
- [ ] 编译警告已阅读并做出处理决定。
- [ ] 测试覆盖空输入、最小长度、最大长度或极值中的适用项。
- [ ] 数组下标、字符串结尾和动态内存范围有明确证明。
- [ ] 函数参数的副本、地址和 `const` 语义能口头解释。
- [ ] 动态内存有申请失败和释放责任说明。
- [ ] 多文件程序分别编译并完成链接。
- [ ] 至少有一道 C++ 基础题被独立改写为 C。
- [ ] 隔天不看旧代码，能重写一个小程序并重新测试。

## 常见误区

| 误区 | 修正动作 |
| --- | --- |
| 认为 C++ 代码删掉类就变成 C | 逐项重写字符串、容器、内存和输入输出 |
| 把数组参数当成带长度的对象 | 显式传入长度，并检查调用约定 |
| 把字符数组容量当成字符串长度 | 单独记录有效字符数和 `\0` |
| `malloc` 成功后忘记释放 | 在所有权表中指定释放位置 |
| 只看程序输出，不看警告 | 将 `-Wall -Wextra -Wpedantic` 作为固定编译选项 |
| 先学大量库函数和宏 | 先用最小语言特性完成可验证程序 |

## 什么时候暂停路线

- 如果还不能解释 C++ 中值传递和指针参数的区别，先回到函数与数组传参。
- 如果数组越界无法定位，暂缓动态内存和链表。
- 如果只会照抄编译命令，却无法解释警告和链接错误，先补程序结构与编译流程。
- 如果没有实际编译和边界输入记录，不把路线进度写成语言掌握结论。

## 来源与复核要求

- [GNU C Language Manual](https://www.gnu.org/software/c-intro-and-ref/manual/c-intro-and-ref.html)：C 语言基础、数组、指针和程序结构。
- [GCC C 方言选项](https://gcc.gnu.org/onlinedocs/gcc/C-Dialect-Options.html)：核对 `-std=c17`、`-std=c23` 和 GNU 扩展。
- [GCC C 标准支持状态](https://gcc.gnu.org/projects/c-status.html)：核对不同标准的编译器支持情况。
- [ISO/IEC JTC1/SC22/WG14](https://open-std.org/jtc1/sc22/wg14/)：C 语言标准化工作组官方入口。

编译器支持、标准版本和库函数细节可能变化，遇到版本相关问题时以当前官方文档和实际编译结果为准。

## 当前状态

这是一份可执行的学习路线，不代表学习者已经掌握 C 语言。每个阶段都应以源文件、编译输出、测试记录和错误修正作为证据。
