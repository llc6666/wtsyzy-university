# K12 读：两份参考解的边界处理

## 一、`binary-search`：三种边界一次处理完

来源：`99-素材库/exercism-c/K12-基础数据结构与算法/binary-search_参考解.c`（exercism/c，MIT）

（原示例代码未随公开版复制；此处保留分析结论。）

三点值得学：

1. **开头就处理空数组与空指针**：`length == 0` 时 `arr + length - 1` 会算到数组前面去，属于未定义行为，所以必须先挡掉
2. 用的是**指针**而不是下标：`low`、`high` 都是 `const int *`，中点用指针算术取。这与 K07 的指针算术是同一套
3. 区间是**两端都闭** `[low, high]`，所以循环条件是 `low <= high`

对照本库示例用的是「前闭后开 + 下标」。两种都可以，**但不能中途换**：两端都闭时收缩写成 `high = mid - 1`；前闭后开时写成 `high = mid`。混起来就会漏元素或死循环。

返回值是 `const int *`（指向找到的元素），找不到返回 `NULL`。这个设计让调用方既能知道「找没找到」，也能拿到元素本身。

## 二、`spiral-matrix`：分配与 size 为 0 的处理

两个观察：

1. 用 `calloc` 而不是 `malloc`：**分配的同时清零**，矩阵初值就是全 0，省掉一次 `memset`
2. `size == 0` 返回一个有效但为空的结构，而不是 NULL。这让调用方不用区分「分配失败」与「大小为 0」——**但代价是调用方不能只靠判 NULL** 来判断是否有内容，得看 `size`

## 读码小结

1. 看算法实现，先看它对空输入的处理
2. 看区间类算法，先确定区间是闭还是开，再看收缩写法是否配套
3. 看返回指针的函数，确认「找不到」与「分配失败」是否区分得开
