# 进制小数：位权、转换与十六进制浮点表示

## 要解决的问题

给定一个带小数点的二、八或十六进制数，算出其数值；再把十进制有限小数转换成这些进制，并用 C++ 验证十六进制浮点字面量。

准备纸笔、支持 C++17 的编译器和[完整示例](../../代码示例/进制小数与十六进制浮点.cpp)。本页的转换练习只处理非负数。先分开转换整数部分和小数部分，再拼接，避免把小数点两侧的位权混在一起。

## 1. 先算每个位置代表多少

在 b 进制中，小数点右侧第 1、2、3 位的位权分别为 `b⁻¹、b⁻²、b⁻³`。该位数字乘以位权，最后相加。这与整数部分的位权展开使用同一个规则。[大学课程的二进制小数说明](https://www.cs.uni.edu/~schafer/cohort26/FCCS/lessons/week1/topic1c/t1c_r1_binaryfractions.html)

以 `0.101₂` 为例：

```text
第一位：1 × 2⁻¹ = 1/2
第二位：0 × 2⁻² = 0
第三位：1 × 2⁻³ = 1/8
合计：1/2 + 1/8 = 0.625
```

对照计算：

| 写法 | 按位权展开 | 十进制结果 |
| --- | --- | --- |
| `0.101₂` | `1/2 + 0/4 + 1/8` | `0.625` |
| `0.5₈` | `5/8` | `0.625` |
| `0.A₁₆` | `10/16` | `0.625` |

十六进制的 `A` 表示数字 10。`0.A₁₆` 是数学写法，不能直接当作 C++ 代码粘贴。

验收动作：不看表格，独立算出 `0.011₂`、`0.3₈`、`0.6₁₆`。三者都应得到 `0.375`。

## 2. 十进制小数转目标进制

对满足 `0 ≤ f < 1` 的小数部分，重复执行：

1. 把剩余小数乘以目标进制 b。
2. 取整数部分，作为下一位数字。
3. 把小数部分留给下一轮。
4. 余数变成 0 时停止；到达位数上限而余数仍非 0，标记“未结束”，不能假装精确。

例如把 `0.625` 转成二进制：

| 轮次 | 乘以 2 | 本位数字 | 剩余小数 |
| --- | --- | --- | --- |
| 1 | `0.625 × 2 = 1.25` | 1 | `0.25` |
| 2 | `0.25 × 2 = 0.5` | 0 | `0.5` |
| 3 | `0.5 × 2 = 1.0` | 1 | 0 |

依次读出 `101`，结果是 `0.101₂`。不要把生成顺序倒过来。整数的“除基取余再逆序”与小数的“乘基取整按顺序”需要分开记。

为了避免把机器浮点误差混入这项练习，完整示例使用精确分数 `5/8`，每轮计算：

```text
scaled = numerator × base
digit = scaled / denominator
numerator = scaled % denominator
```

这里的分子始终表示“当前剩余小数的分子”，分母不变。示例限制分母不超过十亿、进制在 2 到 16 之间，用 `uint64_t` 计算乘积；这个范围内中间乘积小于 160 亿，不会溢出。它没有宣称支持任意精度分数。

## 3. 二进制与八、十六进制互转

因为 `8 = 2³`、`16 = 2⁴`，八进制的一位对应三位二进制，十六进制的一位对应四位二进制。

从小数点向两边分组：整数侧向左分，小数侧向右分。整数侧不足一组在最左边补零；小数侧不足一组在最右边补零。补在错误一侧会改变数值。

```text
10.625₁₀ = 1010.101₂

转八进制：001 010 . 101    → 12.5₈
转十六进制：1010 . 1010    → A.A₁₆
```

验收动作：把 `11.375₁₀` 先转二进制，再按三位和四位分组。应得到 `1011.011₂ = 13.3₈ = B.6₁₆`；最后用位权展开还原十进制。

## 4. 十进制有限小数不一定能有限表示

约分后的分数 `p/q` 在 b 进制中有限表示，当且仅当存在某个 m，使 `q` 整除 `bᵐ`。理由是有限的 m 位小数可写成整数除以 `bᵐ`；反过来，只要分母能扩成 `bᵐ` 就能直接写成 m 位小数。

因此 `1/8` 可以在二进制中终止；`1/10` 的分母含因子 5，任何 `2ᵐ` 都不能被 10 整除，它的二进制展开不会终止：

```text
0.1₁₀ = 0.0001100110011001...₂
```

这是由分母条件推导出的结论。示例末尾的 `...` 只表示达到输出上限时仍有余数；程序没有实现循环节检测，也没有做四舍五入。截断位串、机器中的浮点近似值、原来的精确分数需要分别标记。

## 5. 用 C++17 验证十六进制浮点字面量

C++17 支持十六进制浮点字面量：`0x` 开头，`p` 或 `P` 后接二的幂指数。`p` 指数是语法必需项，指数按十进制写；它表示乘以 `2^指数`，不会乘以十六的幂。标准的浮点字面量语法列出十进制和十六进制形式，不提供二进制、八进制浮点字面量。[C++ 标准草案：浮点字面量](https://eel.is/c++draft/lex.fcon)

```cpp
double x = 0xA.Ap0;    // (10 + 10/16) × 2^0 = 10.625
double y = 0x1.54p3;   // (1 + 5/16 + 4/256) × 2^3 = 10.625
```

两种写法表示同一个数。`std::hexfloat` 控制输出格式，`std::defaultfloat` 恢复普通浮点格式；它们不会修改变量里的数值。

在仓库根目录使用 PowerShell 编译和运行，产物放到系统临时目录：

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic -Werror '.\C++学习笔记\代码示例\进制小数与十六进制浮点.cpp' -o "$env:TEMP\base-fractions.exe"
if ($LASTEXITCODE -ne 0) { throw '编译失败，停止运行' }
& "$env:TEMP\base-fractions.exe"
```

其中 `g++` 需要已加入 PATH。不要在编译失败后继续运行旧的同名可执行文件。

本轮在 GCC 16.2.0 下编译并运行，输出为：

```text
5/8 base 2: 0.101
5/8 base 8: 0.5
5/8 base 16: 0.A
1/10 base 2 (16 digits): 0.0001100110011001...
decimal: 10.625
hexfloat: 0x1.54p+3
decimal again: 10.625
PASS checks=9
```

十六进制输出的具体规范化形式可能随实现而不同。验收核心是数值正确、格式恢复后数值不变、示例内部检查通过，不要只比对某一行字符串的外观。

## 最后留下的产物与边界

留下三项：一张位权展开表、一组双向转换结果、一份带编译命令和运行输出的记录。

常见失败检查：小数生成数字是否被倒序；分组补零是否放错位置；是否把 `p3` 读成乘以 `16³`；是否把截断串写成精确等式。
