# 链表的删除：前驱与边界

## 一句话结论

单向链表删除节点必须靠"前驱"（上一个节点）：让前驱的 `next` 跳过目标指向目标的 `next`，再 `delete` 目标。删头节点没有前驱，直接更新头指针。遍历找目标时用两个指针同步前进（一个当前、一个前驱）。

## 它解决什么问题

链表节点靠 `next` 纸条串联，每个节点的"上家"无法回溯。删除中间节点时，必须让它的上家重新接线，否则链条断裂，后面的节点全部丢失。遍历时提前记住前驱，是单向链表的标配手法。

## 工作机制

删除分两种情况：

**删头节点**：头没有前驱，直接让大门（head）指向第二个节点：

```cpp
Node* t = head->next;   // 记住第二个
delete head;            // 删旧头
head = t;               // 大门换人
```

**删中间节点**：找到目标的同时记住前驱，让前驱跳过目标：

```cpp
Node *p = head, *q = nullptr;   // p 当前，q 前驱
while (p != nullptr && x != p->data) {
    q = p;                      // 前驱记住当前
    p = p->next;                // 当前走下一步
}
if (p != nullptr) {             // 真的找到了才删
    q->next = p->next;          // 前驱跳过目标
    delete p;                   // 删目标
}
```

## 最小示例

```cpp
void List::del(int x) {
    // 链表：20 → 30 → 10，删 30
    Node *p = head, *q = nullptr;
    if (x == head->data) {          // 删头
        Node* t = head->next;
        delete head;
        head = t;
    } else {                        // 删中间
        while (p != nullptr && x != p->data) {
            q = p;
            p = p->next;
        }
        if (p != nullptr) {
            q->next = p->next;      // 20 → 10
            delete p;               // 30 被移除
        }
    }
}
```

## 常见错误与边界

1. **while 循环缺尽头保护（踩过的坑）**：循环条件只写 `x != p->data`，删不存在的值时，p 一路走到 NULL 还在读 `p->data`，解引用空指针崩溃。必须同时检查 `p != nullptr`。
2. **删头忘记更新 head**：只 delete 旧头不换大门，head 变成悬空指针。
3. **空链表调用 del**：`x == head->data` 直接解引用 NULL。函数开头应先检查 `head == nullptr` 直接返回。
4. **循环后不判断是否找到**：循环结束可能是"走完了"而不是"找到了"，直接跳链删除会误删或崩。
5. **让循环保证安全**：若循环条件保证 p 不会为 NULL，循环后的判断天然安全，比事后补救更稳。

## 使用规则

- 删除中间节点：改的是**前驱**的 next，不是目标自己的。
- 遍历找目标时，两个指针同步前进，一前一后。
- 循环条件永远带上"没走到尽头"的检查。
- 循环结束后先判断"是否真的找到"，找到才删。
- 函数开头先处理空链表边界。
- 删除后析构函数释放剩余节点时，不会再碰到已删节点（跳链已修正）。
