# stack 与 queue：LIFO、FIFO 与场景选择

## 一句话结论

`stack`遵循后进先出（LIFO），`queue`遵循先进先出（FIFO）。判断使用哪一个，先看“下一步应该处理最近加入的元素，还是最早加入的元素”。

## 使用场景与准备

当你需要确定处理顺序、看不懂容器的第二个模板参数，或想在 `queue` 上写下标和双端操作时，先用本页选接口。准备一组待处理元素、允许的加入/删除位置，以及项目采用的 C++ 版本。

本页基础示例按 C++17 写法保留；C++23 扩展另列，不作为基础示例的前提。来源未提供运行验证记录；本轮仅整理，未执行测试。下文的顺序与输出是读者自查目标。

## 先区分接口与存储

`stack`、`queue` 是容器适配器：内部容器负责存放元素，适配器只开放规定的操作。`deque` 是序列容器，直接提供两端操作、下标和迭代器；它也是前两者的默认底层容器。

| 需要的动作 | 选用类型 | 下一元素从哪里读 | 删除接口 |
| --- | --- | --- | --- |
| 最近加入的先处理 | `std::stack` | `top()` | `pop()`，删栈顶 |
| 最早加入的先处理 | `std::queue` | `front()` | `pop()`，删队首 |
| 两端加入/删除，或需要下标 | `std::deque` | `front()`、`back()`、`[i]`、`at(i)` | `pop_front()`、`pop_back()` |
| 每次按最大/最小值处理 | `std::priority_queue` | `top()` | `pop()`，删当前堆顶 |

先写出取出规则，再选类型。需要大小顺序时，普通 `queue` 的 FIFO 规则无法满足要求。

## 工作机制

### stack：后进先出

像一摞盘子：最后放上的盘子最先拿走。

```text
push 10，push 20，push 30
取出顺序：30 -> 20 -> 10
```

### queue：先进先出

像排队：先到的人先处理。

```text
push 10，push 20，push 30
取出顺序：10 -> 20 -> 30
```

## 接口对比

| 目的 | `stack` | `queue` |
| --- | --- | --- |
| 放入元素 | `push` | `push` |
| 查看下一元素 | `top` | `front` |
| 删除下一元素 | `pop` | `pop` |
| 查看末端元素 | 无 | `back` |
| 访问中间元素 | 不提供 | 不提供 |

两者的 `pop()`都只负责删除，不返回元素。都应先读取，再删除。

### 底层容器怎样选

| 类型与头文件 | 默认底层容器 | 底层必须提供的核心操作 | 常用替代 |
| --- | --- | --- | --- |
| `std::stack<T>`，`<stack>` | `std::deque<T>` | `back`、`push_back`、`pop_back` | `vector<T>`、`list<T>` |
| `std::queue<T>`，`<queue>` | `std::deque<T>` | `front`、`back`、`push_back`、`pop_front` | `list<T>` |
| `std::deque<T>`，`<deque>` | 自身是容器 | 不适用 | 按任务重新选容器 |

这张表列出关键接口，完整实例化还需满足标准对序列容器等的要求。第二个模板参数是底层容器类型，其 `value_type` 必须与 `T` 匹配。

例如，`std::stack<int, std::vector<int>>` 使用 `vector` 保存整数，需包含 `<stack>` 与 `<vector>`。`std::queue<int, std::list<int>>` 需包含 `<queue>` 与 `<list>`。`vector` 没有 `pop_front()`，因此不满足普通队列所需的底层接口；某些声明暂未触发诊断，也不代表完整队列操作可用。

`empty()`、`size()` 和同类型对象的 `swap()` 三者都有。`stack` 与 `queue` 没有公开的下标、迭代器或 `clear()`；需要这些操作时应重新审视类型选择。

## 最小示例

```cpp
#include <initializer_list>
#include <iostream>
#include <queue>
#include <stack>

int main() {
    std::stack<int> st;
    std::queue<int> qu;

    for (int x : {10, 20, 30}) {
        st.push(x);
        qu.push(x);
    }

    while (!st.empty()) {
        std::cout << st.top() << ' '; // 30 20 10
        st.pop();
    }
    std::cout << '\n';

    while (!qu.empty()) {
        std::cout << qu.front() << ' '; // 10 20 30
        qu.pop();
    }
    std::cout << '\n';
}
```

上述原有示例的预期输出为两行，行末空格不影响这里的顺序对照：

```text
30 20 10
10 20 30
```

读取与删除之间先复制所需的值。若用引用保存 `top()` 或 `front()` 的结果，删除该元素后不能继续通过这条引用访问它。

## deque：双端与随机访问的边界

当题目同时需要队首删除和队尾删除，或还需按下标读取时，直接使用 `deque` 能表达这些动作。来源中的双端示例可以按下面的表逐步记录，表内均按首到尾表示：

| 动作 | 元素序列 | 可观察结果 |
| --- | --- | --- |
| 创建空 `d` | `[]` | `empty()` 为真 |
| `d.push_front(10)` | `[10]` | 首尾都是 10 |
| `d.push_back(20)` | `[10, 20]` | `front()` 为 10，`back()` 为 20，`d[1]` 为 20 |

使用时保留下面几条边界：

- 访问 `[i]` 前保证 `i < size()`；下标接口不做常规越界检查。`at(i)` 越界会抛出 `std::out_of_range`。
- `front()`、`back()`、`pop_front()`、`pop_back()` 都要求非空。删空后先判空，再决定下一次操作。
- 单个元素的首尾插入/删除是常数时间；中间插入/删除一般为线性时间，不能把“两端高效”推广到所有位置。
- 支持随机访问不等于保证连续存储。`deque` 没有 `data()`、`reserve()` 或 `capacity()`，不能把它当成可直接传出整段连续内存的 `vector`。
- 结构修改后先重新获取迭代器。特别是两端插入会使迭代器失效，但对原有元素引用的影响不同；不要把迭代器与引用合成一个“位置有效”结论。需要跨修改保存它们时，另查对应操作的失效规则。

## 版本边界：看到新接口先查标准模式

| 写法或操作 | 版本范围 | 旧标准下怎样组织 |
| --- | --- | --- |
| 默认构造、用已有底层容器构造、逐个 `push` | 本页 C++17 基础写法 | 直接使用基础流程 |
| `stack(first, last)`、`queue(first, last)` | C++23 | 先构造匹配的底层容器，再交给适配器，或逐个加入 |
| `stack/queue(std::from_range, range)`、`push_range` | C++23 | 按原范围顺序逐个 `push` |
| `deque` 的 `append_range`、`prepend_range`、`insert_range`、`assign_range` | C++23 | 使用已有区间/数量接口，先明确要追加、插入还是替换 |

迭代器对构造的提案为 WG21 P1425R4；范围接口属于 P1206R7。当前工作草案含有比 C++17 更新的接口，查到声明后仍需确认目标标准和标准库实现支持。只打开 C++23 语言选项不能自动补齐旧标准库。

## 什么时候用哪一个

| 问题结构 | 适合的结构 | 原因 |
| --- | --- | --- |
| 括号匹配 | `stack` | 最近打开的括号必须最先匹配 |
| 撤销操作 | `stack` | 最近一次操作最先撤销 |
| 迭代 DFS | `stack` | 先沿最近加入的分支深入 |
| BFS 分层搜索 | `queue` | 先发现的节点先扩展 |
| 消息按到达顺序处理 | `queue` | 保持到达顺序 |
| 滑动窗口逐个淘汰旧数据 | `queue`或`deque` | 从一端加入、另一端移除 |

DFS和BFS的结构选择来自它们的访问顺序。算法题中也可以手写数组模拟，但先确认顺序，再选择容器。

## 与知识库中手写队列的关系

知识库已有的手写链式队列需要自己维护节点、`head`和`tail`。`std::queue`把这些细节封装起来，只暴露先进先出所需的接口。

二者的抽象规则相同，代码责任不同：

- 手写队列适合学习指针、节点和边界。
- `std::queue`适合解题时直接使用稳定的 FIFO 接口。

## 常见错误与边界

### 把 `queue`当成“按大小取最优”

`queue`只按进入顺序处理。需要每次取最大或最小元素时，应考虑 `priority_queue`。

### 空容器读取元素

```cpp
std::queue<int> qu;
// qu.front(); // 错误：必须先判断 qu.empty()
```

### 把 `stack`和`queue`的读取接口写混

```cpp
st.top();   // stack
qu.front(); // queue
```

## 读者自查与交付物

向 `stack` 与 `queue` 都依次加入 `1, 2, 3`。连续读取并删除时，stack 应输出 `3 2 1`，queue 应输出 `1 2 3`。若输出方向相同，说明读写接口或容器选择写错了。

按下列顺序填写一张操作卡：

1. 写下一步取最新、最早、最大/最小，还是要自由访问两端。
2. 选类型，写清所需头文件、元素类型和底层容器。
3. 按来源示例逐行记加入位置、读取值、删除位置和剩余元素。
4. 把判空写在每次可能访问或删除元素的分支前；最后一个元素删除后也要考虑。
5. 若用到扩展接口，记录要求的标准版本和实现支持来源。

```text
任务与取出规则：
选用类型与头文件：
元素类型 / 底层容器：
标准版本与扩展需求：
加入位置 / 读取接口 / 删除位置：
判空位置与结束条件：
逐步状态表：
来源是否有运行记录：
本人是否执行：未执行 / 已执行，记录位置：
```

完成标准：卡片中的每次读取都能指向当时仍存在的元素；删除方向符合任务顺序；不依赖该类型未提供的接口。卡片和预期输出只帮助读者自查，不构成本轮运行记录，也不证明包含 BFS、DFS 等完整算法的正确性。

## 使用规则

1. 最近加入的元素优先处理，用 `stack`。
2. 最早加入的元素优先处理，用 `queue`。
3. 需要按大小取元素，用 `priority_queue`，不要用普通 `queue`。
4. 使用 `top()`或`front()`前先判空。
5. 先保存元素，再调用 `pop()`。
