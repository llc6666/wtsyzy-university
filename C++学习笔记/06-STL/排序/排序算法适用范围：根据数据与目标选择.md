# 排序算法适用范围：根据数据与目标选择

## 一句话结论

排序算法的选择取决于四件事：数据规模、数据是否接近有序、是否要求稳定、是否只需要部分结果或特殊值域。普通完整排序优先使用 `std::sort`。

## 快速选择表

| 场景 | 推荐方案 | 原因 |
| --- | --- | --- |
| 普通数组、`vector` 完整排序 | `std::sort` | 通用、成熟、平均效率高 |
| 相等关键字必须保持原顺序 | `std::stable_sort` | 保证稳定性 |
| 只需要第 `k` 小或第 `k` 大 | `std::nth_element` | 不必完整排序 |
| 只要前 `k` 个，并且前 `k` 个有序 | `std::partial_sort` | 只整理需要的前缀 |
| 数据量很小 | 插入排序、冒泡排序 | 实现简单，常数开销低 |
| 数据接近有序 | 插入排序 | 移动次数较少，最好情况可达 `O(n)` |
| 整数值域很小 | 计数排序 | 直接统计频次，避免比较 |
| 整数位数固定、数据量大 | 基数排序 | 按位处理，适合整数键 |
| 数据分布适合分桶 | 桶排序 | 利用数据分布减少比较 |
| 需要理解分治思想 | 归并排序、快速排序 | 体现典型递归分治 |
| 需要动态维护最大值或最小值 | `priority_queue` | 这属于维护极值，不是一次性完整排序 |

## 1. `std::sort`：默认选择

```cpp
#include <algorithm>
#include <vector>

std::vector<int> a;
a.push_back(4);                         // 加入待排序元素
a.push_back(1);                         // 加入待排序元素
a.push_back(3);                         // 加入待排序元素

std::sort(a.begin(), a.end());          // 对整个区间进行升序排序
```

适用：

- 数据需要完整有序。
- 使用原始数组或 `vector`。
- 不要求相等元素保持原始顺序。
- 没有计数排序等特殊值域条件。

`std::sort` 要求随机访问迭代器，常见的原始数组和 `vector` 满足这一要求；它通常不保证稳定性。

## 2. `std::stable_sort`：要求稳定

```cpp
#include <algorithm>
#include <vector>

struct Record {
    int score;                             // 排序关键字：成绩
};

std::vector<Record> records;               // 保存待排序记录

std::stable_sort(records.begin(), records.end(), // 稳定排序整个记录区间
    [](const Record& x, const Record& y) {       // 比较两条记录
        return x.score < y.score;                // 按成绩升序排列
    });
```

例如学生先按姓名排列，再按成绩排序。如果成绩相同，希望姓名原来的顺序继续保留，就需要稳定排序。

稳定排序可能需要更多额外空间，只有在确实需要保留相等元素顺序时使用。

## 3. `std::nth_element`：只找第 k 个位置

如果只需要中位数、前 `k` 小中的边界元素，不需要完整排序：

```cpp
#include <algorithm>
#include <vector>

std::nth_element(a.begin(),         // 区间起点
                 a.begin() + k,     // 排序后应位于第 k 位的位置
                 a.end());          // 区间终点，不包含

int value = a[k];                   // 读取第 k 小元素
```

执行后，`a[k]` 位于完整排序后应有的位置；左侧元素不大于它，右侧元素不小于它，但左右两边内部不保证有序。

## 4. `std::partial_sort`：只整理前 k 个

如果需要前 `k` 个元素，并且这 `k` 个元素还要有序：

```cpp
#include <algorithm>
#include <vector>

std::partial_sort(a.begin(),        // 排序区间起点
                  a.begin() + k,    // 前 k 个元素需要有序
                  a.end());         // 原始区间终点
```

执行后，`a[0]` 到 `a[k - 1]` 是最小的 `k` 个元素，并且已经升序排列；后面的元素不保证有序。

## 5. 插入排序：小规模或接近有序

插入排序每次把一个元素插入左侧有序区间：

```cpp
void insertion_sort(int a[], int n) {
    for (int i = 1; i < n; ++i) {      // 从第二个元素开始处理
        int value = a[i];             // 保存当前待插入元素
        int j = i - 1;                // 从有序区间的末尾开始比较

        while (j >= 0 && a[j] > value) { // 将较大元素向右移动
            a[j + 1] = a[j];           // 为当前元素腾出位置
            --j;                       // 继续向左寻找插入位置
        }

        a[j + 1] = value;              // 插入当前元素
    }
}
```

接近有序时效果较好；数据规模较大且无特殊条件时，不应优先手写它。

## 6. 计数排序：值域较小

例如所有数据都在 `[0, 100]` 内，可以用 `count[101]` 统计出现次数。此时复杂度与元素个数和数值范围有关，常写作 `O(n + r)`。

适用条件：

- 通常是整数。
- 值域范围 `r` 较小。
- 可以接受开辟与值域相关的额外空间。

如果数据是 `0` 到 `10^9`，但只有几十个元素，计数数组会严重浪费空间。

## 7. 桶排序：数据分布适合分组

桶排序先把数据放入不同范围的桶，再分别处理桶内元素。

适用条件：

- 能合理划分值域。
- 数据分布相对均匀。
- 桶内排序的成本可控。

如果所有数据都集中在同一个桶，桶排序的优势会消失。

## 8. 归并、快速、堆排序的使用位置

| 算法 | 适合学习什么 | 实际选择 |
| --- | --- | --- |
| 归并排序 | 分治、递归、合并 | 需要稳定排序或外部排序思路时考虑 |
| 快速排序 | 分区、递归、边界 | 理解原理；实际完整排序优先 `std::sort` |
| 堆排序 | 堆结构、反复取极值 | 需要动态取极值时优先 `priority_queue` |

## 按数据规模判断数量级

下面是竞赛中的经验边界，不是编译器或评测机的硬性规则。实际还要看时间限制、语言、常数、输入输出和比较器的复杂度。

| 数据规模 `n` | 通常应考虑的复杂度 | 典型选择 |
| ---: | --- | --- |
| `n <= 100` | `O(n^2)` 通常足够 | 冒泡、选择、插入、`std::sort` 都可以 |
| `n <= 1 000` | `O(n^2)` 多数情况下可接受 | 插入排序或 `std::sort` |
| `n <= 10 000` | `O(n^2)` 开始危险 | 优先 `std::sort` 或 `O(n log n)` 算法 |
| `n <= 100 000` | 通常需要 `O(n log n)` 或 `O(n)` | `std::sort`、归并、计数排序 |
| `n <= 1 000 000` | 优先 `O(n)` 或 `O(n log n)`，并关注内存和输入 | `std::sort`、计数排序、基数排序 |
| `n > 1 000 000` | 必须结合题目结构仔细设计 | 线性算法、特殊排序或避免排序 |

### `O(n^2)` 为什么很快失控

如果 `n = 10 000`：

```text
n^2 = 100 000 000
```

嵌套循环可能执行约一亿次比较，已经可能接近或超过时间限制。若 `n = 100 000`：

```text
n^2 = 10 000 000 000
```

这通常无法接受。

### `O(n log n)` 的数量级

当 `n = 100 000` 时，`n log2(n)` 约为 1,700,000；这与 `n^2` 的 10,000,000,000 相比差距很大。因此 `n` 达到几万或十万时，完整排序通常应使用 `std::sort` 或其他 `O(n log n)` 方法。

## 各类排序的大致范围

### 冒泡、选择排序

时间复杂度通常是 `O(n^2)`：

- `n <= 1000`：一般可以作为练习或简单题方案。
- `n` 达到 `5000`：需要谨慎。
- `n >= 10000`：通常不应使用。

冒泡排序的提前结束只能改善已经有序的数据，不能改变最坏复杂度。

### 插入排序

- 数据规模很小时可以使用。
- 数据接近有序时可能表现很好。
- 数据无序且规模达到几万时，不应依赖插入排序。

### `std::sort`、归并排序、堆排序

通常为 `O(n log n)`，是中大规模完整排序的主要选择。题目给出 `n <= 10^5`、`n <= 2 * 10^5` 或 `n <= 10^6` 时，通常先考虑这些方法，再检查内存和比较器成本。

### 计数排序、基数排序、桶排序

当数据存在额外结构时，可以突破一般比较排序的限制：

- 计数排序：值域 `r` 较小，复杂度约为 `O(n + r)`。
- 基数排序：整数位数或字符位数可控。
- 桶排序：数据分布适合分桶。

如果 `r` 远大于 `n`，计数排序可能比 `std::sort` 更浪费空间。

## 二维数组中的数量级

如果有 `R` 行、`C` 列，按某一列重新排列整行时：

- 比较行号的次数约为 `O(R log R)`。
- 如果每次交换整行，移动数据的成本还与 `C` 有关。
- 使用索引间接排序通常只移动 `R` 个行号，最后输出时再访问 `C` 个元素。
- 若把全部 `R * C` 个元素展平排序，复杂度应按总元素数 `N = R * C` 估算。

例如：

```text
R = 100000，C = 5，按一列排序 -> 主要看 R log R
R = 1000，C = 1000，全部元素排序 -> 主要看 (R*C) log(R*C)
```

## 最后检查

1. 先确认题目中的 `n` 指元素数量、行数，还是 `R * C`。
2. 先估算最深层循环会执行多少次。
3. `n` 达到 `10^4` 后，不要默认使用 `O(n^2)` 排序。
4. `n` 达到 `10^5` 时，完整排序优先考虑 `O(n log n)`。
5. 计数排序要同时检查 `n` 和值域 `r`，不能只看元素数量。
6. 时间复杂度只是第一层判断，输入输出、内存和比较器内部循环也会消耗时间。

## 决策顺序

遇到排序题时按以下顺序判断：

1. 是否需要完整排序？如果需要，先考虑 `std::sort`。
2. 相等元素的原始顺序是否重要？重要则考虑 `std::stable_sort`。
3. 是否只需要第 `k` 个或前 `k` 个？分别考虑 `nth_element` 或 `partial_sort`。
4. 数据是否为小范围整数？是则考虑计数排序。
5. 数据是否接近有序且规模很小？是则考虑插入排序。
6. 题目是否要求手写某种算法？如果有，按题目要求实现，不要擅自替换。

## 常见误区

1. 只需要最大值，却把全部数据排序；可考虑遍历、`max` 或 `priority_queue`。
2. 只需要第 `k` 小，却误用完整 `sort`；可考虑 `nth_element`。
3. 看到 `O(n + r)` 就使用计数排序，却没有检查值域 `r` 是否过大。
4. 认为快速排序永远是 `O(n log n)`；分区极不平衡时可能退化。
5. 需要稳定性却使用 `std::sort`，相等元素的原始顺序不能依赖它。
6. 把“排序算法的理论复杂度”和“具体标准库实现”混为一谈；标准库接口与实现细节应分开记录。
