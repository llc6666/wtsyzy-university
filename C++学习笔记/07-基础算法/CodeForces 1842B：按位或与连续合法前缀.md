# CodeForces 1842B：按位或与连续合法前缀

## 一句话结论

三堆书分别从上到下扫描。某堆一旦遇到第一本包含目标 `x` 之外的二进制位的书，就不能再从这堆取得任何后续书；但仍然必须继续读入这些数据。当前书 `a` 可以加入的判断是：

```cpp
canTake && ((a | x) == x)
```

最后检查累计知识 `knowledge` 是否等于 `x`。

## 题目结构

- `n`：每堆书的数量。
- `x`：需要达到的目标知识位集合。
- `a`：当前读到的书携带的知识位。
- `knowledge`：已经取得的知识，初始为 `0`。
- `canTake`：当前这一堆是否还可以继续取书。

每本书的知识用整数的二进制位表示，获得一本书的知识就是按位或：

```cpp
knowledge |= a;
```

## 核心机制：为什么是 `(a | x) == x`

按位或只能把二进制位从 `0` 变成 `1`，不能把已经出现的位清掉。

因此，当前书 `a` 只有在它没有带来 `x` 之外的新位时才安全：

```cpp
(a | x) == x
```

例如：

```text
x = 1010
a = 0010
a | x = 1010    可以取得

x = 1010
a = 0101
a | x = 1111    不可以取得，出现了 x 没有的位
```

一旦累计结果出现 `x` 之外的位，后面无法通过按位或消除它，所以这本书以及这堆书后面的书都不能再取得。

## 为什么必须是连续前缀

每堆书只能从顶部开始取，不能跳过当前书去取后面的书。

所以每一堆能够取得的书一定是：

```text
前 0 本、前 1 本、前 2 本、……、直到第一本不合法的书之前
```

代码中的 `canTake` 就是在记录这个边界。第一次遇到不合法的书后，将它设为 `false`，后续书即使本身合法，也不能加入答案。

## 这份代码中的真正错误

### 错误一：`s` 没有分配空间

原代码：

```cpp
vector<vector<int>> s;
```

这只是创建了一个空的二维数组，行数为 `0`。随后直接访问：

```cpp
cin >> s[j][k];
```

属于越界访问，结果是未定义行为，可能崩溃，也可能输出看似正常但不可靠。

如果确实要保存数据，应先分配：

```cpp
vector<vector<int>> s(3, vector<int>(n));
```

本题其实不需要保存全部书，读到当前书后立即处理即可，额外空间可以降为 `O(1)`。

### 错误二：条件表达式写错，且受到运算符优先级影响

原代码：

```cpp
if (s[j][k] | x == x && top == true)
```

它并不等价于：

```cpp
if (((s[j][k] | x) == x) && top == true)
```

按 C++ 运算符优先级，原表达式实际接近于：

```cpp
s[j][k] | ((x == x) && (top == true))
```

其中 `x == x` 永远为真。于是当 `top` 为真时，表达式会把 `s[j][k] | 1` 当作条件，失去了“当前书是否超出目标位集合”的判断。

正确写法：

```cpp
if (top && ((s[j][k] | x) == x))
```

建议给复合条件加完整括号，并把 `top == true` 简化为 `top`，这样更容易确认“到底是谁和谁在运算”。

## 哪些部分原本是对的

- `top` 在每一堆开始时重新设为 `true`，边界范围正确。
- 遇到不合法的书后继续读入后面的书，这样不会破坏下一组输入；只是不能再把这些书加入 `knowledge`。
- `y = s[j][k] | y` 的数学含义正确，推荐写成更清晰的复合赋值：

```cpp
y |= s[j][k];
```

- 不需要排序。题目的关键约束来自“按堆从上到下取”和“按位或不可撤销”，不是价格排序。

## 最小正确实现

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    cin >> t;

    while (t--) {
        int n, x;
        cin >> n >> x;

        int knowledge = 0; // 当前已经获得的知识位

        for (int j = 0; j < 3; ++j) {
            bool canTake = true; // 当前这堆还没有遇到不能取得的书

            for (int k = 0; k < n; ++k) {
                int book;
                cin >> book; // 即使不能再取，也必须继续读完输入

                if (canTake && ((book | x) == x)) {
                    knowledge |= book;
                } else {
                    canTake = false;
                }
            }
        }

        cout << (knowledge == x ? "YES\n" : "NO\n");
    }

    return 0;
}
```

## 正确性骨架

1. 被加入的每本书都满足 `(book | x) == x`，所以它不会引入目标 `x` 之外的位。
2. 一旦当前书不满足条件，按位或无法消除它带来的多余位，因此该书不能取得。
3. 由于不能跳过书，当前堆后面的书也不能取得；`canTake = false` 正好表示这个边界。
4. 三堆都扫描完后，`knowledge == x` 表示已经收集到目标所需的全部位。

## 边界检查

### 目标为零

```text
n = 1, x = 0
三堆都是 0
```

初始 `knowledge` 已经是 `0`，答案为 `YES`。这也说明“可以一本都不取”。

### 第一本文书不合法，后面合法

```text
x = 0011
当前堆：0100, 0001
```

第一本 `0100` 已经带来目标之外的位，第二本即使是 `0001`，也不能跳过第一本取得。

### 目标位来自不同的堆

只要每堆取得的部分都是合法前缀，最终可以通过多堆的按位或合并出 `x`。不要求某一堆单独包含全部目标位。

## 复杂度

- 时间复杂度：`O(3n)`，即 `O(n)`。
- 额外空间复杂度：`O(1)`。
- 题目保证所有测试用例的 `n` 总和不超过 `10^5`，可以直接线性扫描。

## 可复用规则

1. 看到“二进制位集合 + 按位或”，先问：多余的位能不能被消除？如果不能，通常存在不可逆边界。
2. 看到“栈顶到底部、不能跳过”，可选对象通常是连续前缀，而不是任意子序列。
3. 遇到输入流中的无效元素，逻辑上停止处理，输入上仍要继续读取。
4. `|`、`==`、`&&` 混合出现时，必须加括号，先明确运算分组，再判断算法含义。
5. 看到空的 `vector` 后直接使用下标，要先检查行数和列数是否已经分配。
