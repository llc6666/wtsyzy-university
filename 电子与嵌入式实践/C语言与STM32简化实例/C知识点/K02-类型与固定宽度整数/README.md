# K02 类型、位宽与固定宽度整数

## 一句话结论

**`int` 有多宽，C 标准不保证**；要和硬件打交道就必须用 `stdint.h` 里的 `uint8_t / uint16_t / uint32_t`，它们是按位宽定义的，换平台不变。

## 为什么嵌入式必须先定这一条

寄存器是 8/16/32 位的，通信协议里的字段也是按位定义的。写 `int` 意味着「宽度随编译器变」，在 PC 上是 32 位，换个平台可能就是 16 位，读取一个 32 位寄存器就会出错。

## 本机实测的宽度

```text
1) 宽度：char=1 short=2 int=4 long=4 long long=8 指针=8
   int 范围：-2147483648 .. 2147483647
   uint32_t 范围：0 .. 4294967295
```

注意 `long` 在 Windows 的 GCC 上是 4 字节，在 Linux 64 位上是 8 字节——**同一个类型，换个系统宽度就变**，这正是要用固定宽度类型的理由。

## 四个必记的坑（都有实测输出）

| 现象 | 实测 | 说明 |
| --- | --- | --- |
| 溢出 | 第 64 格麦粒 = `9223372036854775808` | 装不进 `int`，必须用 `uint64_t` |
| 回绕 | `2147483648 + 2147483648 = 0`（`uint32_t`） | 无符号溢出是**有定义**的回绕，不报错但结果错 |
| 无符号减法 | `(uint32_t)0 - 1 = 4294967295` | 不是 -1，倒序循环会因此失效 |
| 隐式转换 | `-1 < 1u` 结果是**假** | -1 被转成很大的无符号数 |

## 格式符必须配套

```c
#include <inttypes.h>
printf("%" PRIu64 "\n", v);      /* uint64_t */
printf("0x%" PRIx32 "\n", r);    /* uint32_t 的十六进制 */
```

用 `%d` 打印 `uint32_t`、用 `%lu` 打印 `uint64_t` 都是未定义行为——在 32 位与 64 位平台上表现还不一样。

## 易错清单（本节）

1. 用 `int` 存超过 21 亿的数 → 溢出，未定义行为
2. `uint32_t` 累加溢出 → 静默回绕，不报错
3. 无符号做倒序循环写成 `i >= 0` → 永远成立
4. 有符号与无符号直接比较 → 隐式转换，结果反直觉
5. 格式符与类型不匹配 → 未定义行为
