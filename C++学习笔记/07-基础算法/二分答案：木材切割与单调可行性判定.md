# 二分答案：木材切割与单调可行性判定

## 适用场景

当题目要求“在一个数值范围内找最大的答案”，并且可以写出一个 `check(x)` 判断“答案取 `x` 是否可行”时，可以考虑二分答案。

本文用木材切割模型说明这种结构：给定若干木材长度和最低需求量，选择一个切割高度 `H`，每根木材只取出高于 `H` 的部分，要求取出的总长度至少达到需求量，并让 `H` 尽可能高。

## 先证明判定是单调的

把切割高度从 `H` 提高到 `H + 1`，每根木材能取出的部分只会减少或不变。因此：

- 较低的高度可能可行；
- 较高的高度可能不可行；
- 可行性只能从 `true` 变成 `false`，不能出现 `true → false → true`。

所以答案形状是：

```text
可行、可行、可行、不可行、不可行
```

目标是找到最后一个 `true`，而非找到任意一个可行高度。

## `check(H)` 应该只做一件事

对每根木材计算：

```text
贡献 = max(0, 木材长度 - H)
```

把所有贡献相加，若总量达到需求量就返回 `true`。累计量必须使用 `long long`：即使单根木材仍能放进 `int`，多根木材的总和也可能超过 `int` 范围。

累计值已经达到需求量时可以立即返回，避免继续扫描无关数据。这个优化不会改变结果，因为 `check(H)` 只关心“是否至少达到需求量”。

## 二分区间和中点

取：

```text
low = 0
high = 所有木材中的最大长度
```

`0` 表示把整根木材都取走，是保守的可行下界；最大木材长度是安全的上界。使用向上取整的中点：

```cpp
mid = low + (high - low + 1) / 2;
```

- `check(mid)` 为真：`mid` 可以保留，答案还可能更大，所以 `low = mid`。
- `check(mid)` 为假：`mid` 以及更高的高度都不满足，所以 `high = mid - 1`。

每一轮都必须让区间缩小。若在“最后一个真”的模板中使用向下取整中点并写 `low = mid`，就可能在 `low + 1 == high` 时卡住。

## 可独立编译的代码

配套代码：[二分答案-木材切割.cpp](../代码示例/二分答案-木材切割.cpp)。代码只保留算法模型，不复制题面或外部题解。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

bool enough(const std::vector<long long>& trees,
            long long required,
            long long cut_height) {
    long long collected = 0;
    for (const long long tree : trees) {
        if (tree > cut_height) {
            collected += tree - cut_height;
            if (collected >= required) {
                return true;
            }
        }
    }
    return false;
}

int main() {
    int n;
    long long required;
    if (!(std::cin >> n >> required) || n <= 0) {
        return 0;
    }

    std::vector<long long> trees(n);
    for (long long& tree : trees) {
        std::cin >> tree;
    }

    long long low = 0;
    long long high = *std::max_element(trees.begin(), trees.end());
    while (low < high) {
        const long long mid = low + (high - low + 1) / 2;
        if (enough(trees, required, mid)) {
            low = mid;
        } else {
            high = mid - 1;
        }
    }

    std::cout << low << '\n';
}
```

至少测试以下四类情况：

| 场景 | 输入 | 预期输出 | 检查点 |
| --- | --- | ---: | --- |
| 常规样例 | `4 7`，木材 `20 15 10 17` | `15` | 高度提高到 16 后不足 7 |
| 不同长度 | `5 20`，木材 `4 42 40 26 46` | `36` | 结果是最后一个可行高度 |
| 长度相同 | `3 1`，木材 `5 5 5` | `4` | 高度 5 取不到木材，高度 4 可行 |
| 需要全部木材 | `3 6`，木材 `1 2 3` | `0` | 下界答案不应被排除 |

## 常见错误

| 错误 | 后果 | 修正 |
| --- | --- | --- |
| 把 `H` 的可行性当成无序判断 | 二分没有依据 | 先证明 `check(H)` 的单调方向 |
| 求和使用 `int` | 大数据时溢出，判定结果错误 | 总量和需求量使用 `long long` |
| 上界写成数组长度 `n` | 木材长度大于 `n` 时漏掉答案 | 上界取最大木材长度 |
| `low = mid` 却使用向下取整中点 | 两个候选值时可能死循环 | 向上取整，或改用另一套区间模板 |
| 只测试题目样例 | 边界错误不容易暴露 | 测试全相等、答案为 0、接近上界和刚好满足 |
| 把“至少达到”写成“恰好达到” | 错误排除合法答案 | 判定使用 `collected >= required` |

## 复杂度

设木材数量为 `n`，最大长度为 `V`。每次判定扫描一次木材，二分进行 `O(log V)` 次，因此总时间复杂度为 `O(n log V)`，额外空间复杂度为 `O(n)`。如果输入只能顺序读取，也可以在读取时记录最大值并设计单次判定所需的数据保存策略，但不能为了省空间破坏重复判定所需的数据。

## 什么时候不适用

- `check(x)` 的结果不是单调的。
- 目标不是数值范围内的边界，而是要求保留具体方案且判定无法独立计算。
- 判定一次的代价本身过高，`O(log V)` 次重复判定仍无法满足限制。
