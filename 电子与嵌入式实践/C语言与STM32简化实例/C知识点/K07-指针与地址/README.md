# K07 指针与地址

## 一句话结论

**指针里存的是地址，指针的类型决定两件事：一次读多少字节、怎么解释这些字节。** 除此之外没有别的玄机。

## 三件事必须分开

| 写法 | 含义 |
| --- | --- |
| `int *p` | `p` 是一个指针变量，它自己占一块内存（放地址） |
| `&x` | 取 `x` 的地址 |
| `*p` | 按 `p` 里存的地址去访问那块内存（解引用） |

容易混的是声明里的 `*` 和使用里的 `*`：声明时 `*` 表示「这是个指针类型」，使用时 `*` 表示「解引用」。同一个符号，两种意思。

## 指针算术的步长

`p + 1` 前进的字节数 = `sizeof(指向的类型)`，不是 1 字节。实测（见 [嵌入式实例.md](嵌入式实例.md)）：

```text
q=...FE10  q+1=...FE14  相差 4 字节（sizeof(int)=4）
同一个地址当 uint8_t* 看：+1 前进 1 字节
```

同一块内存，换一种指针类型去看，步长就变了。这一点在嵌入式里天天用：把寄存器块看成 `uint32_t *` 是 4 字节一跳，看成 `uint8_t *` 就是 1 字节一跳。

## 数组名与下标

`arr[i]` 就是 `*(arr + i)`，下标只是语法糖。实测里连 `2[arr]` 都能得到 `arr[2]` —— 这句话的意思不是鼓励这么写，而是提醒你：**下标运算的本质是指针加偏移再加解引用**。

## 结构体成员的偏移 = 寄存器的排布方式

实测输出：

```text
CRL 偏移  0 字节 -> ...7020
CRH 偏移  4 字节 -> ...7024
IDR 偏移  8 字节 -> ...7028
ODR 偏移 12 字节 -> ...702C
```

STM32 的库把一组寄存器包成结构体，靠的就是这个偏移：`GPIOA` 是基地址，`GPIOA->ODR` 就是「基地址 + 12 字节」那块内存。**结构体不是给寄存器加了什么包装，只是给一串固定偏移起了名字。**

## 易错清单（本节）

1. 返回局部变量的地址 → 函数返回后那块内存不属于你
2. 以为 `p + 1` 只前进 1 字节 → 步长是类型大小
3. 手算结构体偏移 → 用 `offsetof` 核对
4. `free` 后继续用那个指针 → 悬空指针
5. 忘了 `const` 的位置：`const int *`（数据只读）与 `int * const`（指针只读）不是一回事
