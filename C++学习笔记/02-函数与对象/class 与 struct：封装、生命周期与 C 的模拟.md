# class 与 struct：封装、生命周期与 C 的模拟

## 这页解决什么问题

做嵌入式时常会在 C 和 C++ 之间切换。C 的结构体擅长打包数据，C++ 的 class 还能把操作、权限和生命周期规则放进同一个类型。本页只保留能直接帮助读代码和做接口设计的部分，避免把桌面 C++ 的完整继承体系照搬到小型裸机项目。

## class 和 struct 的分界

C++ 中 class 和 struct 都可以拥有数据成员、成员函数、构造函数、析构函数和继承。默认访问权限不同：

| 写法 | 默认访问权限 | 适合先表达什么 |
| --- | --- | --- |
| class | private | 先保护状态，再开放少量操作 |
| struct | public | 公开的数据记录或配置对象 |

C 语言中的 struct 只有数据成员，没有 C++ 的成员函数、访问权限和继承。看到同名的 struct，要先确认文件按 C 还是 C++ 编译。

## 成员函数和 this

~~~cpp
struct Counter {
    int count;
    void tick() { ++count; }
};

Counter c{0};
c.tick();
~~~

调用成员函数时，函数需要知道正在操作哪个对象。C++ 用隐含的对象上下文表达这件事，成员函数中可以用 this 指向当前对象。对应到 C，可以把对象指针作为普通函数的第一个参数：

~~~c
typedef struct {
    int count;
} Counter;

void counter_tick(Counter *self) {
    ++self->count;
}
~~~

读一段成员函数代码时，先问“它修改的是哪个对象、对象是否已经存在、调用者是否拥有它”，再去看函数体。

## 封装和接口

private、protected、public 是编译期访问控制。封装的实际动作是：

1. 把必须保持一致的状态放在 private。
2. 只通过 public 函数修改状态。
3. 在接口中写清楚输入范围、失败状态和对象生命周期。
4. 把内部表示换掉时，只要 public 契约不变，调用方就不必跟着修改。

C 没有同等强度的访问控制，可以用不暴露在头文件中的 static 函数、前置声明和不透明指针隐藏实现，但这依赖文件边界和约定。

## 构造、析构与 RAII

构造函数在对象建立时执行，析构函数在对象生命周期结束时执行。它们适合把“对象必须满足的初始条件”和“对象负责归还的资源”放到同一个类型里。

| 对象来源 | 常见销毁时机 | 读代码时检查 |
| --- | --- | --- |
| 自动对象 | 离开作用域 | 成员是否在构造后可用 |
| 动态对象 | 对应的 delete | 谁拥有对象，谁负责释放 |
| 静态或全局对象 | 程序结束或运行环境规定的时机 | 是否依赖初始化顺序 |

RAII 的核心是资源和对象生命周期绑定。原始 new 与 delete 必须配对，new[] 与 delete[] 必须配对；malloc/free 只管理原始字节，不会替代构造和析构。新代码优先把资源交给标准库的 RAII 类型管理，裸机中是否使用动态分配则要结合启动流程、内存预算和运行时约束决定。

## 继承和虚函数：先看需求，再承担代价

继承用于表达“是一种”，虚函数允许通过基类接口调用派生类实现。带虚函数的实现通常需要额外的间接访问和对象布局信息，但 C++ 标准不规定 vtable 的具体形式、位置或固定字节数，不能把某个编译器的对象大小写成通用规则。

在小型裸机系统中，先比较三种方案：

| 需求 | 先考虑 |
| --- | --- |
| 只是保存配置字段 | struct |
| 需要保护状态和保持不变式 | class + 窄接口 |
| 需要少量可替换操作 | C 函数指针表或 C++ 明确的回调接口 |
| 需要复杂运行时多态 | 先记录内存、启动、调试和实时性预算，再决定是否使用继承 |

不要因为“面向对象”四个字自动引入继承。接口数量、资源责任和运行时成本都应先写进设计卡。

## C 的近似实现：结构体加函数指针

~~~c
typedef struct Counter Counter;
struct Counter {
    int count;
    void (*tick)(Counter *self);
};

static void counter_tick(Counter *self) {
    ++self->count;
}

void counter_init(Counter *self) {
    self->count = 0;
    self->tick = counter_tick;
}
~~~

| C++ 概念 | C 中的显式写法 |
| --- | --- |
| 成员函数 | 普通函数，首参数传对象指针 |
| this | self 指针 |
| 构造函数 | init 函数 |
| 析构函数 | deinit 函数和明确的释放责任 |
| private | 文件内 static、前置声明或不透明指针 |
| 虚函数 | 函数指针表或回调成员 |

这种写法不会自动产生 C++ 的生命周期管理，所有权、初始化顺序和释放动作都必须由接口文档写清楚。

## 实操检查卡

读 class 或 struct 代码时，依次填写：

1. 状态字段有哪些，哪些必须保持不变式。
2. 哪些操作应该公开，哪些实现细节应该隐藏。
3. 对象来自栈、静态区还是堆，销毁时机是什么。
4. 是否持有资源，资源由哪个对象释放，是否存在复制或移动后的双重释放风险。
5. 是否使用继承或虚函数，实际需要的替换点是什么，目标工具链成本如何记录。
6. 如果改写成 C，self、init、deinit、回调表和所有权分别落在哪里。
