# 第四册：先读网络现状，再决定要不要改配置

**目标：**在自己可管理的 Linux 主机或 OpenWrt 设备上，从接口到目标服务记录一条排错链。手边没有设备，可以先用下方示意输出练读。不要用未知网络或公共服务作练习目标。

## 1. 把网卡、桥和 IP 配置分开

IPv4 前缀长度告诉你多少位是网络前缀。例如 `192.0.2.130/25` 的网络地址是 `192.0.2.128`、普通主机地址范围是 `.129` 到 `.254`、广播地址是 `192.0.2.255`。以下地址均为文档示例，不能直接部署。OpenWrt 的逻辑接口可以把地址绑在桥上，桥成员物理口没有单独 IP 并不异常。接口名称和交换机架构随设备和固件而异，先用输出识别。

| 顺序 | 命令或动作 | 看什么 |
| --- | --- | --- |
| 1. 接口 | `ip link show`、`ip addr show` | 名称、状态、桥成员、实际地址与前缀；链路标志正常仍不能证明远端可达 |
| 2. 选路 | `ip route show`；完整 iproute2 可用 `ip route get 192.0.2.1` 练读选路格式 | 出口 `dev`、源地址 `src`、有无 `via`；没有默认路由仍可能有到特定网段的路由 |
| 3. 邻居 | `ip neigh show` | 直连目标或下一跳的邻居状态。旧缓存或缺记录不能独自判定对方离线 |
| 4. 解析 | 对**同一个授权目标**比较已知地址和主机名；按环境用 `nslookup` 或 `getent hosts` | 解析返回的地址是否符合预期；域名能解析也不代表服务可用 |
| 5. 服务 | 在有权限的服务端看监听；客户端按应用协议连接指定地址与端口 | 分开记录地址、协议、端口及报错；ping 结果不能替代服务是否可用 |

部分精简镜像没有完整 `ip` 选项或 DNS 工具；先查 `command -v` 和本机帮助。若需要有限次数地看 ICMP 连通，只探测自己管理或被授权的目标。超时记录为“未收到响应”，不直接认定网线、DNS 或防火墙损坏。

## 2. 练读这组示意输出

```text
2: lan1: <BROADCAST,MULTICAST,UP,LOWER_UP> master br-lab state UP
3: br-lab: <BROADCAST,MULTICAST,UP,LOWER_UP> state UP
    inet 192.0.2.130/25 scope global br-lab

192.0.2.128/25 dev br-lab scope link src 192.0.2.130
192.0.2.131 dev br-lab src 192.0.2.130
```

前半段示意 `ip addr show` 的结果；后两行分别示意 `ip route show` 的直连路由和针对 `.131` 查询 `ip route get` 时选出的路径。这里没有 `via`，预期直接通过该桥发往同一子网。下一步看 `.131` 的邻居记录和目标监听，别为此去修改默认网关。如果地址和前缀本身不匹配，应先读双方设置，排除重复地址和桥接错误。

## 3. 需要改网络时，先写回滚条件

把**运行态**与**持久配置**分开：`ip` 显示的是当前内核状态，设备上的管理服务可以重建它；OpenWrt 持久设置通常通过所用管理界面或 UCI 保存并应用。在自己的隔离练习设备上，先确认目标逻辑接口、原地址与前缀、管理口和恢复入口。改一次只变一个字段，比较前后选路与实际服务；重连不成功时按预先记录的备用入口恢复。只剩一条 SSH 通道、备份无法取回，或不清楚接口属于谁时，停在只读阶段。

**排查单：**`故障时间 | 本机接口与地址 | 到目标的选路 | 邻居状态 | 解析结果 | 具体服务及报错 | 下一步`。能凭其中一条观察排除一个解释，并写出还没证实的那一层，就完成本册。

参考：[ip-route 手册](https://man7.org/linux/man-pages/man8/ip-route.8.html)、[ip-neighbour 手册](https://man7.org/linux/man-pages/man8/ip-neighbour.8.html)。Windows 端可对照 [Wi-Fi 分层排查](../../电子与嵌入式实践/Wi-Fi已连接却用不了：从无线链路查到应用.md)。回到[快通目录](README.md)。
