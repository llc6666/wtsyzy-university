# S01 单片机程序骨架

## 一句话结论

**裸机程序只有四段：启动初始化 → 进入 `while(1)` → 中断置标志 → 主循环处理标志。** PC 程序跑完就退出，MCU 程序必须一直运行，这个差别决定了整个代码结构。

## 四段分别做什么

| 阶段 | 谁写的 | 干什么 |
| --- | --- | --- |
| 启动 | 启动文件（汇编，厂商给） | 设栈顶、把 `.data` 从 Flash 拷到 RAM、把 `.bss` 清零，然后跳到 `main` |
| 初始化 | 用户代码 | 配时钟、使能外设时钟、初始化 GPIO/UART/定时器 |
| 主循环 | 用户代码 | `while(1)`，查标志、做业务、没事就空转或休眠 |
| 中断 | 用户写的 ISR | 只做最少的活：存数据、置标志、清中断标志 |

## 三条铁律

### 一、中断里只做最少的事

```
ISR：读一个字节 / 存一个数据 / 置一个标志 / 清中断标志
主循环：解析、计算、打印、控制
```

原因：中断会打断主流程，ISR 越长，主流程被拖得越久，还可能错过下一个中断。这条与 K09 说的「中断里不 `malloc`」是同一个原则。

### 二、标志必须 `volatile`，且先清后处理

```c
if (g_tick_flag) {
    g_tick_flag = 0;      /* 先清 */
    handle_tick();        /* 再处理 */
}
```

先清的好处：处理期间如果又来了一次中断，标志会被重新置起，下一轮主循环还能看到，不会漏掉事件。反过来（先处理后清）会漏掉处理期间发生的那次。

### 三、主循环里不要写死等

```c
while (flag == 0) { }        /* 死等：期间什么都做不了 */
```

真实工程里主循环应该不断巡检各个标志，没事件就进入低功耗休眠。死等会阻塞其他任务，是裸机程序最常见的设计错误之一。
