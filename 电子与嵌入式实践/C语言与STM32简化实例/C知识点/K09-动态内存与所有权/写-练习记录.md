## binary-search-tree

- 位置（原始目录）：`exercism-c/c-main/exercises/practice/binary-search-tree/`；题面与参考解见 [素材库](../../99-素材库/exercism-c/K09-动态内存与所有权/)
- 题面要点：左子树 ≤ 当前节点 < 右子树；插入后要保持这个性质；要能查到某个值
- 接口以头文件为准，通常包含创建/插入/查找/遍历/销毁

### 验收标准（用例表 + 五类边界）

| 操作 | 期望 |
| --- | --- |
| 依次插入 4、2、6 | 根为 4，左 2，右 6 |
| 再插入 3 | 落在 2 的右子树 |
| 再插入 1、5、7 | 形成满三叉结构（见题面字符图） |
| 查找 5 | 找到 |
| 查找 99 | 找不到 |

| 类型 | 用例 | 期望 |
| --- | --- | --- |
| 空 | 空树上查找 | 返回「未找到」，不崩溃 |
| 最小 | 只插入一个节点 | 根就是它，左右皆空 |
| 最大 | 插入大量有序数据（如 1..1000） | 树退化成链，但不崩溃、不泄漏 |
| 相等 | 插入重复值 | 按「小于等于走左边」处理，或按自己的约定记数 |
| 非法 | 销毁后再查找 | 未定义；调用方应保证不再使用（销毁时把指针置 NULL） |

- 不变量：任一节点的左子树所有值 ≤ 该节点值，右子树所有值 > 该节点值；销毁后不泄漏任何节点（用 ASAN 验证）

### 复盘三问

1. **为什么对**
2. **暴力做法为什么不行**：用有序数组也能查找（二分），但插入要搬移；BST 的意义就在插入。比较两种结构各自适合什么场景
3. **哪里最容易错**：只 `free` 根节点导致子树泄漏；插入空树时没有正确设置根；重复值放错边
