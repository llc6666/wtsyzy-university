# 上下文、记忆与资料边界

## 何时用

任务跨多轮对话、跨多个项目或涉及大量本地资料时使用。目标是给 Agent 足够事实完成当前工作，同时避免把过期、无关或敏感信息混进结论。

## 输入

- 当前任务契约。
- 候选来源列表。
- 已知的时效信息和敏感信息类别。

## 步骤

### 1. 把信息分成四层

| 层 | 内容 | 处理规则 |
| --- | --- | --- |
| 本轮上下文 | 当前问题、文件、约束 | 任务结束可丢弃 |
| 项目状态 | 目标、版本、决策、未完成项 | 写入项目卡或交接卡 |
| 稳定方法 | 可跨任务复用的流程与模板 | 有来源和边界后写入知识库 |
| 私密信息 | 身份、账号、密钥、内部资料、原始数据 | 最小化访问，默认不写入公开产物 |

记忆属于“线索层”，不自动等于当前事实。遇到版本、价格、规则、人员、线上内容等时效信息，必须重新读取当前来源。

### 2. 建立最小来源包

不要让 Agent 从整块硬盘开始搜索。先提供一个来源表：

| 来源 | 回答什么问题 | 证据等级 | 时效 | 是否可公开 |
| --- | --- | --- | --- | --- |
| 官方文档 | 当前规则 | 高 | 有版本 | 链接可公开 |
| 本地报告 | 历史结果 | 中 | 固定快照 | 需脱敏 |
| 对话记忆 | 已做决策线索 | 低到中 | 可能过期 | 不直接引用 |

需要扩展范围时，先让 Agent 报告“为什么需要、预计读取什么、会产生什么风险”，再授权。

### 3. 分开保存原文、解释和行动

- 原文或数据放来源区，保留链接、日期和文件定位。
- Agent 的解释标记为“推论”，并写清前提。
- 下一步动作进入任务卡或决策卡，带负责人和触发条件。

这能防止“Agent 总结过一次”被误当成原始事实。

### 4. 做公开前脱敏

先做发布范围表，再扫描文本，最后人工检查图片、附件、文档属性和 Git 历史。删除正文不足以抹除已提交的敏感内容。

## 交付物

- 一张最小来源表。
- 一份资料分层规则。
- 一张公开发布范围表，或“不公开”的明确结论。

## 验收

- 每个事实性结论能回到来源、日期和适用范围。
- Agent 使用的记忆与当前来源发生冲突时，以当前来源为准并记录差异。
- 公开产物不含个人身份、联系方式、令牌、内部链接、未公开截图或第三方原文。
- 任何扩大读取范围的动作都有理由和授权记录。

## 常见失败与修正

- 把旧对话记忆当作当前配置：先重新读取配置或官方页面。
- 将聊天摘要写成来源：补原链接、原文件或明确降级为待验证。
- 为“全面”一次性导入所有资料：按任务问题建立最小来源包。
- 只扫描 Markdown：同时检查图片、PDF、表格、文件名与提交历史。
