# 论文与技术报告写作：从证据表到交稿

适合已经收集了资料，却把文章写成逐篇摘抄、背景口号或结果清单的读者。按下面的顺序，完成一张任务卡、一张证据表、一个段落提纲和一份有出处的稿件。

本文由本地写作学习笔记抽象改写，只保留可复用的编辑方法。来源笔记记录了对两篇综述、三篇工程论文及一份模板的分析；本轮完整阅读该笔记，未重新通读六份原件，也不据此复述论文的技术结论。来源未提供这套写作流程的效果评估记录；本轮仅整理，未执行代码、实验或效果测试。

## 1. 先填任务卡，确定文章要交付什么

准备任务要求、目标模板、能访问全文的主要文献，以及已有的推导、设计或实验记录。只有题名和搜索摘要的材料先放在待读清单，不填成已经读过的证据。

```text
文章类型：综述 / 原创研究 / 工程设计报告 / 读书报告
读者和用途：
本文只回答的问题：
纳入对象、场景和时间范围：
本次不讨论的内容：
篇幅、语言、提交格式与截止时间：
要求或模板的发布方、版本、原始链接：
必须保留的栏目：
冲突项、待确认项：
```

把问题缩到能用现有材料回答。例如，将“介绍仿生材料”改为“比较所选文献中两类材料设计策略的作用路径与适用条件”。后者可以逐项填入证据表；前者容易扩展为百科式背景。

| 类型 | 正文需要完成的动作 | 可以据此写出的结果 | 需要避免的越界 |
| --- | --- | --- | --- |
| 综述 | 围绕同一问题比较不同研究 | 分类、共性、分歧和局限 | 把他人的实验写成自己的工作 |
| 原创研究 | 说明问题、方法、结果及解释 | 自己的研究记录支持的发现 | 让文献中的结果替代自己的结果 |
| 工程设计报告 | 对齐需求、约束、方案和已有产物 | 已完成的设计、实现及相应证据 | 把设计目标写成已达到的指标 |
| 读书报告 | 解释一组文本的主张和论据 | 对原文的分析、比较和疑问 | 宣称完成了系统综述或实证研究 |

这些是选结构时的工作区分，具体栏目服从任务要求。ICMJE 将 IMRAD 列为原创研究的常见组织方式，也说明其他文体可采用不同结构；该指南面向医学期刊，不能充当所有课程和工程报告的统一格式。[官方说明](https://icmje.org/recommendations/browse/manuscript-preparation/preparing-for-submission.html#one)

## 2. 建证据表，再写正文

每行只记录一个要引用的判断。文献编号使用自己的真实文献管理编号，后续排版时再统一为目标引用格式。

| 字段 | 填什么 | 填完后怎样检查 |
| --- | --- | --- |
| 编号与出处 | 完整题名、年份、DOI 或官方链接、版本 | 能打开对应材料；区分正式出版、预印本和其他材料 |
| 定位 | 印刷页码及 PDF 页序、章节、图号或表号 | 不用全文重搜就能找到相应内容 |
| 原文事实 | 用自己的话记录原文报告了什么 | 不混入自己的解释，不抄成整段摘录 |
| 条件 | 对象、输入、环境、方法、对照和指标 | 数字与比较对象的口径完整 |
| 你的解释 | 这条事实与本文问题有什么关系 | 明确标为自己的归纳或推论 |
| 可支持的结论 | 能放进正文的最小判断 | 结论没有超出原文对象和条件 |
| 不能支持的结论 | 缺少什么，哪些范围无法外推 | 不能只填“有局限”，要指明缺失项 |
| 使用位置与状态 | 拟放章节；全文已读 / 待读 / 待补来源 | 待确认的内容不会混入定稿 |

完成一行后，把“可支持的结论”和原文放在一起读。原文只报告某个条件下的变化，正文就保留该条件；只有相关关系的材料，不直接改成因果结论。

涉及性能数字时，加填：绝对值、单位、基线值、变化方向和取值条件。只看到“提高了某个百分比”却找不到比较对象时，先不用这个数字。

对于综述，再留一条简短检索记录：

```text
检索日期与入口：
关键词及组合：
时间、语言、对象范围：
纳入与排除的理由：
本次实际读到哪些全文：
已知遗漏及其可能影响：
```

普通学习综述可以先做到范围透明；不要仅凭这一张表给文章冠以“系统综述”。系统综述还需遵守相应领域的方法和报告规范。ICMJE 鼓励综述描述资料定位、筛选、提取和综合方法，并对系统综述提出更明确的要求。[报告指南说明](https://icmje.org/recommendations/browse/manuscript-preparation/preparing-for-submission.html#two)

**本步产物：**能支撑核心问题的证据行，以及一份仍待补齐的材料清单。证据不足时缩小文章范围，保留缺口；不要用顺口的句子补齐事实。

## 3. 按问题分章节，先写段落主题句

综述可以用“问题与范围 → 必要概念 → 分类比较 → 综合讨论 → 结论与局限”组织。工程报告可以用“需求与约束 → 方案 → 已完成工作 → 已有结果 → 讨论与后续”组织。已有指定结构时，把这些信息放入对应栏目。

每节先填四项：

```text
本节问题：
本节准备支持的判断：
证据表中的行号：
完成后读者应理解的差异或边界：
```

随后只列段落主题句。某个主题句找不到证据行时，将它标为待补、改成问题，或删除。不要先写几百字背景，再寻找能勉强贴上的引用。

综述尽量按共同问题、机制、方法或约束分类。若两篇论文的对象、环境和指标不同，就把差异写进表中，保留“当前不宜直接比较”的判断。单凭各自摘要里的最佳数值排高低，会丢掉比较条件。

| 比较对象 | 对象与条件 | 采用的策略 | 指标与口径 | 原文结果位置 | 适用限制 |
| --- | --- | --- | --- | --- | --- |
| 文献或方案名称 | 按证据表填写 | 只写已报告动作 | 单位、基线和统计口径 | 页码、图表号 | 缺失条件或已报告限制 |

**本步产物：**每节有问题、每段有判断、每个主要判断有证据入口的提纲。

## 4. 把段落写成“判断、证据、解释、边界”

不要求每段固定四句话，但这四项信息应能找到。下面只演示表达方法，方括号内容必须由真实材料填写，不能当成已有研究结果引用。

**待改句：**“该技术性能优秀，发展迅速，具有广泛应用前景。”

**可填写的改写：**

> 在[对象与条件]下，[文献作者或真实来源编号]采用[具体策略]，报告[指标、单位和变化]。这一结果支持[限定范围内的判断]。该研究未覆盖[缺少的场景或条件]，因此本文只将其作为[具体用途]的依据。

有证据支持机制时，补出“什么通过什么过程影响了什么”。来源只报告现象时，用“观察到”“报告了”，机制解释标为推测并交代依据。

修改段落时按下面的顺序处理：

1. 圈出“优秀、先进、显著、首次、广泛、完全”等词。
2. 找到词所指向的对象、指标、对照和证据位置。
3. 有证据就写具体变化；没有证据就删去评价或改为待研究问题。
4. 检查“因此、导致、表明”前后的逻辑。并列材料不强接因果，不同条件的结果不直接合并。
5. 将段落结尾接回本节问题；只有泛泛价值判断的句子删掉。

“统计显著”与“实际影响较大”要分开写。来源没有统计分析时，不替它补上统计意义；需要描述幅度时直接报告原始数值与条件。

## 5. 工程报告按证据选择动词

先列已有产物，再决定能够使用哪些表述。本步骤整理已有记录，不要求为了成文临时补做实验。

| 已有材料 | 建议写法 | 还不足以支持的写法 |
| --- | --- | --- |
| 想法、目标或计划 | 拟采用、计划完成、目标为 | 已实现、达到指标 |
| 结构图、接口表、算法流程 | 已完成某项设计，说明产物位置 | 系统稳定运行 |
| 已写出的代码或制作记录 | 已编写某模块、已完成某制作步骤 | 编译通过、功能通过或性能达标，除非另有对应记录 |
| 指定环境的运行记录 | 在所记录环境下完成某项运行 | 对其他环境、输入或设备同样成立 |
| 仿真记录 | 在所列模型和参数下得到某结果 | 实物已达到同一指标 |
| 实测记录 | 在所列设备、工况与测量方法下测得某结果 | 无条件推广到所有场景 |

把已有结果按下面的格式整理。缺失字段填“来源未记录”，随后收紧正文结论。

```text
要支持的判断：
记录类型与日期：推导 / 设计 / 实现 / 运行 / 仿真 / 实测
对象、设备或软件版本：
输入与环境条件：
对照与指标定义：
结果、单位与不确定性：
原始记录位置：
尚不能支持的结论：
```

如果只有文献和方案，就按综述或设计报告如实写作。要求必须包含实测而现有记录不足时，把缺口交还作者处理，停止补写结果。

## 6. 正文完成后再压缩摘要和结论

先从正文提取信息，再形成摘要；已有初稿也按此顺序回查。

| 部分 | 写什么 | 回查动作 |
| --- | --- | --- |
| 综述摘要 | 问题、纳入范围、比较角度、主要归纳和边界 | 每项归纳能指到正文段落 |
| 工程摘要 | 问题与约束、完成的动作、已有结果、适用范围 | 动词与记录类型一致，数字与正文一致 |
| 引言末段 | 本文回答什么、处理哪些范围、如何组织 | 与任务卡和实际章节一致 |
| 结论 | 本文确实支持了哪些判断 | 逐项回扣正文，不加入新结果 |
| 展望 | 当前缺口、缺口的影响、下一步可补的材料或动作 | 删除“继续深入研究”等无法安排的表述 |

例如，把“未来将进一步优化系统”改成“现有记录仅覆盖[场景]；后续可补充[另一场景]下的[指标]记录，以判断[待回答的问题]”。这只描述后续安排，不表示已经完成。

需要英文摘要时，先锁定中文的对象、动作、数字、单位和结论范围，再翻译。逐项核对中英文信息，术语首次出现的全称和缩写保持一致；英文流畅不能补偿中文缺失的事实。ICMJE 强调摘要应准确反映正文，并服从目标期刊格式。[摘要要求](https://icmje.org/recommendations/browse/manuscript-preparation/preparing-for-submission.html#b)

## 7. 最后处理引用、图表和模板

先制作一张要求对照表：

| 项目 | 当前要求及来源 | 稿件位置 | 状态或冲突 |
| --- | --- | --- | --- |
| 篇幅、摘要和关键词 | 当次任务或目标期刊的要求 | 对应栏目 | 已满足 / 待改 / 待确认 |
| 标题、字体和行距 | 当前版本模板 | 全文样式 | 不照搬别的期刊参数 |
| 图表和公式 | 编号、题注、单位、正文引用要求 | 图表号及位置 | 检查缩写与符号说明 |
| 引用格式 | 目标要求 | 正文与文后表 | 双向核对 |

任务要求与模板冲突时，把冲突位置和版本列出来，请发布方确认。DOI、录用日期、基金等字段按真实情况及任务要求处理，不从模板示例中填造信息。

逐一对照正文引用和文后列表：文后每项在文中有实际用途，文中每个标记都能找到对应条目。引用支撑具体句子；需要原始研究细节时，回读原始研究，不把综述转述当作已经读过全文。引用前查看正式页面上的更正或撤稿信息。ICMJE 对引用准确性及原始来源使用提出了相应要求。[参考文献说明](https://icmje.org/recommendations/browse/manuscript-preparation/preparing-for-submission.html#g)

图表先问“它回答了哪一个问题”。没有正文用途的图表删除。保留时写清对象、条件、指标、单位、符号和来源；外部图表另行确认许可与署名要求，不因能下载就默认可再分发。公式解释变量及用途，同一变量的符号在全文保持一致。

## 8. 交稿前留下这五项产物

1. **任务卡与要求对照表：**版本、范围和冲突可查。
2. **证据表与检索记录：**事实、解释、支持范围和未读材料分开。
3. **段落提纲：**每节的问题和主要判断能对应证据。
4. **稿件：**正文、摘要、结论、图表和引用相互对应。
5. **待处理清单：**缺来源、不可比条件、缺失记录和待确认格式逐项列出。

读者可用下面的清单自行复查文本：

- [ ] 核心判断都有出处与定位，未读材料未标成已读。
- [ ] 他人报告、本人完成的工作、综合推论和未来安排表达清楚。
- [ ] 数字带单位、条件和比较口径，摘要与正文一致。
- [ ] 各节围绕问题组织，段落没有逐篇摘抄或无依据的因果连接。
- [ ] 展望指向具体缺口；评价词有证据，或已经删改。
- [ ] 图表被正文使用，引用可追溯，外部素材许可已处理。
- [ ] 最终格式回到当次要求，不把旧模板当作统一标准。

无法定位的核心证据、未确认的事实或任务必需但缺失的结果，应先处理再交稿。本清单只检查写作材料是否闭合，不替代同行评审、研究真实性审查或正式学术评价。

## 来源、适用边界与相关页面

整理日期：2026-11-19。本文适用于学习性综述、课程文章和技术报告的起草及修改；系统综述、临床研究及其他有专门报告规范的工作，还应使用相应规范。本文不承诺评分、录用或写作效果。

- 本地写作学习笔记提供了文体区分、证据与表达的对应关系。任务卡、表格和检查顺序为本次整理后的建议流程，不宣称是期刊强制规范；第三方原文、论文图表、学位论文、私人任务要求及原始模板均未随库发布。
- [ICMJE：Preparing a Manuscript for Submission to a Medical Journal](https://icmje.org/recommendations/browse/manuscript-preparation/preparing-for-submission.html)：本轮读取官方正文，作为文章结构、摘要一致性与引用责任的参考。它面向医学期刊，本文的通用工作表属于编辑性归纳。
- [《大学化学》征稿简则入口](https://www.dxhx.pku.edu.cn/CN/column/column27.shtml)：来源笔记用其讨论具体期刊格式。本轮访问遇到人机验证，未取得规则正文，因此本文不沿用旧笔记的字数、关键词、字体和分辨率数字。实际投稿时由读者打开官网核对。
- [资料入库与来源卡片](../方法论/知识库构建/资料入库与来源卡片.md)：用于保存文献出处。
