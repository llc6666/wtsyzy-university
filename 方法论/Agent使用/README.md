# Agent 使用方法论

## 何时用

当同类工作会重复出现，且需要读取资料、调用工具、生成可审查产物时使用 Agent。一次性的开放式讨论、没有明确产物的脑暴、涉及高风险且无法设定边界的行动，更适合普通对话或由人完成。

## 输入

- 一个能验收的目标，而非抽象愿望。
- 已授权的资料范围与工具范围。
- 允许 Agent 做到哪一步，以及哪些动作必须由人确认。
- 一个验收方法：测试、来源核验、链接检查、人工抽查或外部反馈。

## 核心模型

一个可靠的 Agent 工作流可以拆为五层：

```text
人：目标、边界、批准权
Agent：分解、判断、执行、报告
资料：可追溯的上下文和证据
工具：读取、计算、编辑、发布的执行通道
验证：独立检查、停止条件、交接记录
```

Agent 的价值来自“在边界内完成多步任务”，不来自把任何问题都自动化。官方实践指南同样把模型、工具、指令视为 Agent 的基础，并强调从单 Agent、小范围、真实任务验证开始。[OpenAI 实践指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/)

## 步骤

### 1. 先决定是否需要 Agent

满足以下至少两项，才值得使用：工作重复、输出格式固定、需要跨文件或工具、能明确验收。否则先用普通对话澄清问题。

### 2. 写任务契约

使用 [把需求写成可执行任务](把需求写成可执行任务.md) 把目标、来源、动作权限、交付物和验收写清楚。缺少其中一项时，先让 Agent 提问，不允许它自行扩大范围。

### 3. 设上下文边界

按 [上下文、记忆与资料边界](上下文、记忆与资料边界.md) 提供当前任务真正需要的文件和事实。记忆可以减少重复说明，不能替代重新核验当前状态。

### 4. 分级授予工具权限

先只读，再允许本地可回退写入，最后才是外部发布或不可逆动作。细则见 [工具权限、风险与人工审批](工具权限、风险与人工审批.md)。

### 5. 用最小版本执行并验证

先完成一个可检查的最小产物，运行 [验证、验收与错误处理](验证、验收与错误处理.md) 的验收项。失败时报告证据和下一步，不把“看起来合理”当作完成。

### 6. 留下可交接状态

结束时写变更、验证、风险、回滚与下一步，按 [交接、复盘与持续迭代](交接、复盘与持续迭代.md) 回流到项目或知识库。

## 交付物

- 一张任务契约。
- 一份来源清单与权限表。
- 一个可复查产物。
- 一份验收记录和交接卡。

## 验收

- 读者能说清 Agent 被允许做什么、不能做什么。
- 每个事实性结论能回到来源，或被明确标为推测。
- 每项写入或外部动作都能找到变更范围与验证结果。
- 失败、未验证和待人工决定的内容没有被包装为完成。

## 必须停止并交给人的场景

- 需要花钱、下单、签约、发送对外消息、处理敏感身份或医疗法律金融决策。
- 关键来源缺失、相互矛盾，或 Agent 只能猜测。
- 目标、文件路径、删除范围、权限范围不明确。
- 验收失败且无法定位原因，或风险超过预先约定的上限。
